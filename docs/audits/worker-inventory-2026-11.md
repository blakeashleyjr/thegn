# Host and daemon worker inventory — November 2026

This is a source-only inventory of long-lived host/daemon workers. The rows were
read from production `spawn_named`/`try_spawn_named` call sites in
`crates/thegn-host/src` (including `daemon/`). One-shot probes, child-pipe
readers, and operation-scoped helpers are omitted; the older
[`runtime-workers.md`](../runtime-workers.md) inventory covers those families.
“No explicit budget” means this audit did not find a per-source drain bound; it
does not mean the source is known to be harmful. A channel send is not a stop
acknowledgement.

## Host event ingress and drain budgets

These are the principal sources that feed the host loop. “Yes” means the source
has an explicit per-iteration budget or end-to-end backpressure at its host
boundary. A plain `try_recv` loop without a count/time limit is recorded as
“No” even when the payload itself has a cap.

| Ingress source                                                                                                                             | Owner / loop-side drain                                                                    | Drain budget or backpressure                                                                                                                                                                      |
| ------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| PTY output and exits                                                                                                                       | [`pty_drain.rs`](../../crates/thegn-host/src/pty_drain.rs), called by `run.rs`             | **Yes:** 16 KiB/2 ms with input pending, otherwise 128 KiB/5 ms; 16 KiB pane slices, 1 MiB stash high-water, bounded channel backpressure                                                         |
| LSP diagnostics                                                                                                                            | [`lsp.rs`](../../crates/thegn-host/src/lsp.rs) `drain_diagnostics`                         | **Yes:** 8 publications, 256 KiB, or 2 ms; input preemption and single-wake re-arm                                                                                                                |
| Log records                                                                                                                                | [`loop_policy.rs`](../../crates/thegn-host/src/loop_policy.rs) `drain_logs`                | **Yes:** 32 records/1 ms with input pending, otherwise 256/2 ms; 32-record chunks                                                                                                                 |
| Resident plugin messages                                                                                                                   | [`handlers/plugins.rs`](../../crates/thegn-host/src/handlers/plugins.rs) `drain`           | **Yes:** 256 message units per drain; bounded dispatch queue and per-plugin in-flight cap                                                                                                         |

| Refresh/model, stats, containers, daemon status, metrics, docs, PR/diff view, launch/create, sandbox, share, forward, and preview channels | [`run.rs`](../../crates/thegn-host/src/run.rs) drain block                                 | **No single per-source count/time budget found:** most are `try_recv` drains; generation fences, last-wins state, demand gates, or payload caps provide correctness bounds for individual sources |
| Event bus notifications                                                                                                                    | [`event_bus` setup in `run.rs`](../../crates/thegn-host/src/run.rs) and desktop dispatcher | **No host-loop drain budget found in this audit:** desktop delivery has its own channel/stop lifecycle; inbox/sidebar projection is loop-owned                                                    |

## Findings and ownership

The source review found no new unnamed-thread or missing-QoS violation in the
named call sites covered by the table; the [host thread-name ratchet](../../test/thread-name-host-ratchet.txt)
and [QoS ratchet](../../test/thread-qos-ratchet.txt) remain the owners of that
invariant. The audit did find two documentation gaps that are intentionally not
code changes in this slice:

| Finding                                                                                                                                                | Owner                                                                                                                                                                |
| ------------------------------------------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Several continuous host ingress channels rely on coalescing, generation fences, or an unbounded `try_recv` drain without one common per-source budget. | [THE-657](https://linear.app/blakeashley/issue/THE-657) — per-source budgets design                                                                                  |
| Release-profile idle/resource and worker-wakeup measurements are not established by source inspection.                                                 | [THE-665](https://linear.app/blakeashley/issue/THE-665) — competing-load measurement; [`just bench-soak`](../performance-benchmark-protocol.md) is the gate when run |
| Daemon heartbeat and idle-exit task stop acknowledgement is not visible at the named-thread call sites.                                                | [THE-657](https://linear.app/blakeashley/issue/THE-657) — worker lifecycle follow-up                                                                                 |

No other violation was found in this source-only pass. This document claims no
speedup, no measured idle state, and no universal latency threshold.

## Keeping the inventory current

When adding a long-lived worker or event channel, update this file in the same
change with its spawn site, wake source/cadence, visibility gate, cancellation
and acknowledgement path, and drain budget. If the path is intentionally
unbudgeted, say so and link its owner issue. Re-run the docs link/anchor checks,
the applicable thread ratchets, and the release-profile soak gate when evidence
rather than source inspection is required.
