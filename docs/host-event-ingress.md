# Host event ingress

This page is the source-by-source contract for every off-loop producer whose
results the host event loop (`event_loop` in `crates/thegn-host/src/run.rs`)
consumes. It answers THE-657's first acceptance item (a contract table that covers
every continuous producer and documents justified low-rate exceptions) and is the
inventory THE-661 closes entries against. It does not change any channel; the
companion [runtime worker inventory](runtime-workers.md) covers the threads and
tasks on the producing side.

## Method and base

Every row was re-verified by grep at base `2a05114b2` (`grep -n try_recv`,
`grep -nE 'unbounded_channel|mpsc::channel|sync_channel|watch::channel'`, plus the
`SnapshotSlot`, `Latest` and global-mutex `take`/`drain_results` drains called from
the loop) over `crates/thegn-host/src`. Line numbers are at that base: the
re-audit (THE-661, batch 138) re-grepped every drain, budget and declaration cite
and rebased the rest by diff from the row's previous base; a cell that this pass
could not tie to a source line says "unverified". Unless a cell
names another crate, paths are relative to `crates/thegn-host/src/`, and a bare
`run.rs:N` is a line in `run.rs`. A cell that the source does not settle says
"unverified"; nothing here is a guess.

Column meanings:

- **Rate**: `stream` (continuous while a source is live), `periodic` (ticker or
  sampler cadence), `fan-out` (a user action can start several producers),
  `one-shot` (one result per request), `event` (low-rate external events).
- **Payload**: the per-message size bound the source enforces.
- **Channel**: `bounded(N)`, `unbounded`, `slot` (one replaceable value), or
  `queue` (a custom bounded structure).
- **Semantics**: `lossless-ordered`, `must-deliver completion`,
  `replaceable snapshot`, or `coalescible invalidation`.
- **Generation**: how the loop rejects a stale result.
- **Wake**: the grep evidence that a send is followed by a `TerminalWaker` pulse
  (normally the waker is handed to the producer beside the sender).
- **Budget**: the per-iteration bound on loop work; `drain-until-empty` means none.
- **Verdict**: `bounded: sufficient (evidence)`, `needs slice: <name>`, or
  `unverified`.

## Drain-until-empty receivers

Four rows here are now budgeted (THE-657): refresh requests, workspace clone,
merge-queue drive messages and PR-queue messages drain through
`ingress_budget::take_batch`, which takes a bounded, lossless batch and re-arms
one wake when work is left. Each drain gets its own fresh budget, created
immediately before it (`run.rs::drain_budget`): a budget measures only its own
drain. One budget shared across the refresh and clone drains was spent by the
~3,000 lines of loop body between them, starving refresh to one message per
iteration. The budgeted drains still share the fair-turn rotation and the single
re-arm wake (no timer). The merge-queue fold result stays drain-until-empty: one
fold is in flight at a time.

## Rules

- **No indiscriminate drop-oldest or latest-only on streams, completions or
  exits.** Pane bytes, exits and completions are never dropped; backpressure is
  the throttle (`pty_drain.rs:8-14`). The two eviction cases above are justified
  exceptions because each records its loss: the log queue emits a gap marker,
  and the diagnostics queue sets an incomplete mark. A replaceable-snapshot slice
  may replace only values the table classes as `replaceable snapshot`, and must
  merge partial fields (see the container row) rather than overwrite them.
- **Pending work always schedules a future wake.** A drain that stops on a budget
  with work left must arm the poll (`budget_exhausted`, `log_backlog`,
  `plugin_backlog` into `idle_poll::poll_timeout`, run.rs:17210-17215) or re-arm a
  producer wake obligation (LSP). A producer that sends must pulse the waker. The
  container-event producer was found without a pulse during this inventory and was
  fixed in the same change: it now pulses at most once per 250 ms window plus one trailing flush.
- **Input preemption is preserved.** Bounded drains shrink their budget while input
  is pending (`drain_budget`, `log_budget`, the LSP `input_pending` hook) and check
  input between slices. A new slice must keep that check and must not add a
  blocking wait to the loop.

## Next slices

The unbounded channels that carry a replaceable snapshot, in suggested order. Each
is a THE-661 candidate; pick one with a measured case (a backlog observed under
`THEGN_PERF=1` while the loop is busy) before changing it.

1. **Container-event pulses** (`sandbox_event_counter`, run.rs:1208): done and
   bounded. Batches are coalesced per 250 ms window (`PulseCoalescer`); a

2. **Metrics state** (`metrics_inbox`, run.rs:1127): done. Whole-state replace via

3. **Container list** (`container_slot`, run.rs:1112): done. Replaced via the
   `SnapshotSlot` classification, with the optional footprint merged forward.
4. **Provisioning progress** (`provision_inbox`, run.rs:7162): done and bounded.
   Senders store into a keyed latest slot (`handlers/provision.rs`

## Budget exceptions (THE-657 disposition)

THE-657's remaining bullets are decided, not pending. Each drain below stays
drain-until-empty on purpose. Evidence is from the tree at the base above; this
page changes no code.

- **Model hydration** (`model_rx`, decl run.rs:938, drain run.rs:12468). Not a
  budget candidate. Each message is a whole `FrameModel` that also carries
  must-deliver intents: `drain_hydration_intents` (run.rs:28761) moves the
  adopt and `editor.open` rows into loop-local queues (run.rs:12463-12467),
  and its comment says that once `build_model` claimed a row, "even a stale
  snapshot must hand it to the loop" because the row is already deleted with no
  other consumer (run.rs:28758-28760). Deferring a message to a later turn
  would reorder or strand those intents. Generations (`hydration_gen`,
  run.rs:12489) reject stale models, and hydrations are single-flight
  (`inflight_hydration_gen`, run.rs:12472, 15120), so the queue is short.
- **App tile change hooks** (`app_rx`, decl run.rs:7323, drain run.rs:13463).
  Deliberately drain-all. Each message is a `usize` slot index; the loop does
  one `loop_perf.tick` and sets one `app_signalled` bool per message
  (run.rs:13462-13465), then runs a single `pump_observe` after the drain
  (run.rs:13467-13468). A budget would only delay that one coalesced call. A
  producer flood therefore costs a counter tick per message and no per-message
  work, and the ordering rule is that every tile hook seen before the pump is
  folded into it. The producer (`apps/mod.rs:787`) is best-effort and wakes the
  loop.
- **Worker lifecycle** (plugin lifecycle messages and the runtime workers).
  Not a loop-ingress candidate of its own. Plugin lifecycle messages already
  share the per-drain cap of 256 units (`MAX_PLUGIN_MESSAGES_PER_DRAIN`,
  `handlers/plugins.rs:43,1079`; `plugin_backlog` re-arms the poll,
  run.rs:14569, 17214). The thread and task side is inventoried in
  [runtime workers](runtime-workers.md) with its own bound classes. This page
  found no other worker-lifecycle receiver in the loop.

drains under load. This page records the contract; those gates are not part of
it.
