# Sandbox + remote programme (2026-11-17)

This is the in-repo record of the sandbox + remote programme: its waves, the freeze window, the
resources each wave needs, the owner decisions, and how it delivers THE-791. The binding rules for
lanes are in `CONTRIBUTING.md` ("Programme conventions (sandbox + remote, 2026-11)"). The roadmap
index is `tasks.md` group BA.

The twelve workstream plans (WS00 `shared-contracts` through WS11 `agent-presets-and-ux`) and the
reconciled rulebook (`resolutions.md`, rules `B1`-`B51`) are planning artefacts held outside this
repository; the item ids below (`WS<nn>-P<phase>-<nn>`) are the stable handles. Citations in those
plans were checked at main `cbf36fe3a`; cite symbols, and re-check any `file:line` before relying on it.

## 1. Parent acceptance record: THE-791

THE-791 (owner decision 2026-10-13) is the programme's parent acceptance record. Its five gates are
THE-792 (gate 1) to THE-796 (gate 5). The programme delivers them; THE-791 closes only when gate 5's
acceptance is met. The binding alignment decisions are T1-T17.

Two rules from the alignment govern every lane:

- Every spawn of repo-influenced code has one launch class (T1). Headless and untrusted launchers
  are admitted through one handle, `sandbox_admission`, and untrusted classes default to the boundary
  tier (T2, T3). The flip is WS11-P6-05 (W5).
- The user's own interactive panes keep the `standard` default (owner decision 2026-11-05).
  `standard` is an accident guard, not a boundary (B1).

### Freeze window

From the merge of WS02-P1-02b to the merge of WS02-P2-08, no lane outside WS02 edits
`crates/thegn-core/src/sandbox*.rs`, `capabilities.rs`, `sandbox_matrix.rs`, `sandbox_backend.rs`,
`sandbox_truth.rs` or `sandbox_support.rs`, and no lane outside WS02 creates a new file matching
`crates/thegn-core/src/sandbox*.rs` (lead ruling L3). Check:
`git diff --name-only <base>.. -- 'crates/thegn-core/src/sandbox*.rs'` is empty for every non-WS02
lane merged inside the window. The window sits inside W2. Every item that changes golden-recorded
output lands in W1 (before) or W3 and later (after). See `CONTRIBUTING.md` for the full rule.
