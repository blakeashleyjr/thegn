# WS06-P0-05 - Windows baseline gate before any Windows runtime code merges

**Question.** Does thegn on native Windows (msvc, ConPTY, named-pipe daemon, Job Objects) build, render, take input, handle Ctrl+C and run the daemon race on a real Windows kernel? Result: "gate passed" or "gate open" with a named list of what is broken.

**Needs (windows-device + kvm).** Windows 11 24H2 (26100.9278 or later) KVM VM (`just windows-vm-up`, from WS06-P6-03) and/or the owner's Windows machine; **Windows Terminal** (not conhost: check 2.7 expects conhost to be refused); Rust toolchain + git in a checkout of the commit under test; `gh` (optional) for CI status. Spends GitHub Actions minutes for the opt-in `windows` job (90-minute timeout): dispatch it once. No other cost.

**Script.** `pwsh -File scripts\spikes\ws06-p0-05.ps1 -OutDir C:\spike-out [-CiRunUrl <url>] [-Manual '2.2=pass,2.5=pass,...']` (PowerShell; parse-checked only). Builds (`cargo build -p thegn-host --example waker_spike --bin thegn`, heavy, once) then automates the environment record, CI run status (`gh run view`), check 2.1 (ticks + idle CPU), 2.7 (conhost refusal) and 2.8 (daemon two-instance race with an isolated `XDG_STATE_HOME`). Checks 2.2, 2.3, 2.4, 2.5, 2.6, 2.9 are manual; pass their results back with `-Manual` so the gate verdict is computed. It never edits the repo and never dispatches CI. It refuses to run outside Windows Terminal (`WT_SESSION` unset).

## Steps

1. Dispatch (a person, spends minutes): `gh workflow run ci.yml --ref main -f extras=true`; record the run URL and wait for `windows` and `windows-artifact-smoke`. On failure read the log, fix small port bugs (cap about 400 changed lines, likely `crates/thegn-host/src/platform/windows.rs` and the `windows` job), re-dispatch from the branch with `--ref <branch>`, record every attempt's URL. Classify failures: (a) small port bug (fix, count lines), (b) test assuming Unix (fix or skip with a reason), (c) larger work (file an issue with the log excerpt; the gate stays open).
2. On the device/VM in a Windows Terminal tab, same commit: `pwsh -File scripts\spikes\ws06-p0-05.ps1 -OutDir C:\spike-out -CiRunUrl <url>`.
3. Do the manual checks from `add-windows-compositor-validation` section 2 and save a transcript (text, screenshot for rendering) each: 2.2 bare `thegn`: first frame (chrome and a pane), pwsh prompt, typing echoes; 2.3 idle CPU about 0% in Task Manager; 2.4 hard resize drag storm: no tearing, no panic; 2.5 Ctrl+C in a pane interrupts the pane child not thegn, `exit` closes or replaces the pane (EOF reaches `pty_drain`); 2.6 `THEGN_LOG=info` with a forced background warning: frame stays clean and the line lands in `thegn-stderr.log`; 2.9 sidebar tree, pin strip and logotype glyphs render with no ASCII fallback; 2.1 key echo is instant; 2.8 a daemon-backed pane opens over the pipe.
4. Re-run with `-Manual '2.2=pass,2.5=pass,...'` so the verdict is computed.
5. Write `openspec/changes/add-windows-compositor-validation/evidence/<date>-<host>.md`: device/VM, Windows build and UBR, thegn commit, CI run URL(s), one section per check with its transcript. Check the boxes 2.1-2.9 that pass and 3.1; `add-windows-ci-distribution` task 4.3 (green-run half only; the opt-in gate stays); add the baseline status line to CONTRIBUTING "Windows (native)"; archive `add-windows-compositor-validation` only if every task is complete.

## Decision rule (from the issue)

Gate **passed** when the opt-in `windows` run is green AND checks 2.1, 2.2, 2.5 and 2.8 pass (2.3, 2.4, 2.6, 2.7, 2.9 may be known issues, each with a filed issue). Gate **open** otherwise: say which condition failed and which issues were filed.

## Downstream

Passed: WS06-P1-03, P1-04, P2-02, P4-04 may merge; also unblocks P1-06, P6-02, WS04-P4-02, WS09-P0-03 and WS10-P3-04s. Open: those stay blocked; pure items continue. A Ctrl+C or daemon-race finding that leaves a pane running after close is a high-priority containment-adjacent bug even if the gate passes.

**Time.** 2-4 h on the device plus CI waiting (and triage time if red).
