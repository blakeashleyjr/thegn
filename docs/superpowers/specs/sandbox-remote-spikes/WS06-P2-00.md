# WS06-P2-00 - capture real WSL behaviour before writing parsers and PTY assumptions

**Question.** How does WSL2 on Windows 11 actually behave for what thegn relies on: `wsl -l -v` encoding and layout, registry layout, `--cd`/`-e`/`-u` PTY semantics (resize, Ctrl+C), idle shutdown vs a held process, fd passing, env passing, export/import streaming, command-line limits (checks C1-C11)?

**Needs (windows-device + kvm).** Windows 11 with WSL2 and an Ubuntu distro, in Windows Terminal (a real ConPTY host). Where: the Win11 KVM VM from WS06-P6-03 if its nested-virtualisation spike shows WSL2 boots in the guest, otherwise the owner's device (do not assume). Record Windows build and UBR, `wsl --version`, the distro's `uname -r`. Optional second language pack for C1 and a WSL1 distro; a policy-managed VM for C9. Disk about twice the distro size for `-RunExport`. No accounts, no cost. Run in the same device session as WS09-P0-03 (check C6 is a shared row).

**Script.** `pwsh -File scripts\spikes\ws06-p2-00.ps1 -OutDir C:\spike-out [-Distro Ubuntu] [-ModifyWslConf] [-RunExport]` (parse-checked only). Raw bytes through `Start-Process` redirection, never a PowerShell decode. Scripted: C1, C2, C3 (non-interactive part), C5, C6, C8 (opt-in), C9 (registry presence), C10 (opt-in), C11. **MUTATING opt-ins:** `-ModifyWslConf` edits the distro's `/etc/wsl.conf` (backup restored in `finally`, distro terminated); `-RunExport` exports and imports a copy `tgspike-<pid>` (unregistered in `finally`). Not scriptable, do by hand: C3 resize + Ctrl+C relay (see below), C4 vim and the `claude`/`codex` TUIs, C7 fd 3 survival (needs a `CreateProcess` with an inherited handle: check `ls -l /proc/self/fd` inside `wsl.exe -e`; expected no), C9 on a policy-managed VM, C1 localized headers/WSL1/WSL-absent states.

## Steps

1. `pwsh -File scripts\spikes\ws06-p2-00.ps1 -OutDir C:\spike-out -Distro Ubuntu -ModifyWslConf -RunExport` (the C6 polls take about 4 minutes).
2. C3 by hand: `wsl.exe -d D -u U --cd /tmp -e sh -c 'trap "echo WINCH" WINCH; trap "echo INT" INT; stty size; while :; do sleep 1; done'`; resize the Terminal window (SIGWINCH printed, `stty size` matches); press Ctrl+C (INT printed exactly once, `wsl.exe` survives). C4: vim and the `claude`/`codex` TUIs render and accept input.
3. C7 by hand; C9 only on a policy-managed VM (look at `HKLM\SOFTWARE\Policies\WSL` and `wsl --status`) else record "deferred to device check W11".
4. Review `lxss-dump.redacted.reg` for GUIDs and `BasePath` before committing (note any redaction in the record); commit fixtures under `crates/thegn-core/tests/fixtures/wsl/`: `*.bin` raw `wsl -l -v` bytes (default and `WSL_UTF8=1`, with and without a WSL1 distro) and `lxss-dump.reg`. Keep binaries small.
5. Write `openspec/changes/add-wsl-connector/spikes/wsl-capture.md`: every check C1-C11 with result or "blocked: <reason>" with an owner, the decisions below, Windows build/UBR, `wsl --version`, distro and kernel.

## Decision rules (from the issue)

C1/C2 define the fixtures and drive P2-01's `parse_wsl_list` and P2-02's registry-first discovery. C3/C4: if ConPTY -> `wsl.exe` -> Linux pty fails on resize or Ctrl+C, WS06-P2-01, P2-02 and P2-05a are blocked and the record names the failure. C6: a held `sleep infinity` keeps the distro Running => the generated connector emits `keepalive.hold`; if not, omit it and the doctor note recommends `.wslconfig instanceIdleTimeout=-1`. C7: fd 3 does not survive (expected) => the in-distro composer takes the intent as `--intent-b64` (stays the plan either way). C8: `WSLENV` works with interop disabled => allowlisted env via `WSLENV` names; else secret passthrough refused for WSL panes ("use distro-local credentials (see `thegn help sandbox-windows`)"). C10: streaming works => provisioning streams export to import, else temp tarball. C11 sets the intent size bound (default 16 KiB, lower to what the capture supports). C5 records the WSL kernel's Landlock ABI (expected at most 3), userns availability, AppArmor absence (feeds P2-05b docs and netns-based egress over a Landlock port pin). If WSL2 cannot run in the KVM guest rerun on the owner's device; never mark a check done from a Linux-only substitute.
