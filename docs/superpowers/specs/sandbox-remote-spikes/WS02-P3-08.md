# WS02-P3-08 - capture real container runtime facts (Linux, macOS, Windows hosts)

**Question.** What do the real container runtimes print (`docker version/info/context`, `podman machine`, `nerdctl`, `finch vm status`, `docker events`) so WS02-P3-03/05/06 write parsers and presets against real output instead of unverified strings?

**Needs.** Linux host with whichever of docker (rootful, rootless), podman, nerdctl is installable without root; for the full matrix an Apple-silicon Mac (macOS 26) with Docker Desktop, Colima, OrbStack, Rancher Desktop (moby and containerd), Finch, podman machine (libkrun, applehv). Windows rows (podman machine wsl/hyperv, Docker Desktop) are run by WS06 on the Win11 VM with this same script; WS06-P3-01 owns those fixtures. Tools: bash 3.2+, shellcheck. No accounts, no cost. The one mutating step (`--events`) pulls an image and creates then removes one labelled container.

**Script.** `scripts/spikes/ws02-p3-08.sh OUTDIR [--events]` (read-only except `--events`). Writes `OUTDIR/runtimes/<product>/<version>/*.txt` and `OUTDIR/WS02-P3-08.evidence.txt`. Writes nothing outside OUTDIR. Redacts user names and home paths. The shipping script of the item is `test/support/capture-runtime-facts.sh`; this one is its spike draft (same contract, `--events` instead of an interactive prompt) and may be moved there unchanged.

## Steps

1. Linux: `OUT=$HOME/spike-evidence/WS02-P3-08-$(date +%F); scripts/spikes/ws02-p3-08.sh "$OUT"`.
2. For each engine with a reachable daemon, add the events capture (MUTATING: creates and removes a scratch container labelled `thegn.spike=...`, removed by trap even on failure): `scripts/spikes/ws02-p3-08.sh "$OUT" --events`. Set `SPIKE_IMAGE` to an image you already have to avoid a pull.
3. nerdctl, if installable without root: `nerdctl create`, `nerdctl exec`, `nerdctl rm` by hand against a real install; record date, version and result in the decision record. Otherwise record "nerdctl stays Unverified".
4. Mac session (hardware item, same session as WS05-P0-01/P0-06): repeat step 1 once per product (switch the docker context or start the product first): Docker Desktop, Colima, OrbStack, Rancher Desktop moby, Rancher Desktop containerd, Finch, podman machine libkrun, podman machine applehv.
5. Review EVERY file for tokens, registry auth, auth config and private hostnames (`docker info` and `docker context inspect` can include them) before copying anything into `crates/thegn-core/tests/fixtures/runtimes/<product>/<version>/`.
6. Create the stub `openspec/changes/add-sandbox-runtime-endpoints/design.md` decision table: one row per WS02 section 12 product (Podman rootless, Podman rootful, podman machine x5, Docker Engine, rootless Docker, Docker Desktop macOS/Linux/Windows, Colima, OrbStack, Rancher Desktop moby/containerd, Lima docker template, Finch, nerdctl) with capture path, product version, `verified_preset` yes/no, or the sentence "candidate only (no capture)".

## Capture and where it goes

- Raw captures: `crates/thegn-core/tests/fixtures/runtimes/<product>/<version>/` (after review).
- Decision record: `openspec/changes/add-sandbox-runtime-endpoints/design.md` (add a minimal `proposal.md` only if `just openspec-validate` rejects a change with no proposal).
- Hand to WS06 for the Windows rows; hand the macOS V-OCI captures from WS05-P0-01 over as extra fixtures.

## Decision rule (from the issue)

- A product preset becomes `verified_preset = true` only with a capture from that product version or newer.
- `nerdctl` becomes `Verification::Verified` only after a manual create, exec and rm on a real install, recorded in the decision record.

## Downstream

- Capture present: WS02-P3-03 marks that row `verified: true` and its parser tests use the fixture (also P3-04, P3-06 docker events fixtures, P4-11 named presets).
- No capture: the row stays a candidate, shown in doctor and never auto-selected (safe).
- nerdctl without the manual run: keeps the `Unverified` caveat on the P3-05 row and in `thegn doctor`.

**Time.** Linux 20 min; Mac 2-3 h across products (installs dominate).
