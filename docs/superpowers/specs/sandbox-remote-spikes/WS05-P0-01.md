# WS05-P0-01 - macOS on-device evidence: Apple `container` (V-AC-01..05) and podman/docker (V-OCI-01..03)

**Question.** What does Apple `container` actually do for `network none`, internal networks, `--ulimit nproc`, labels and `--version` (V-AC-01..05), and what do the podman/docker engines print on the Mac (V-OCI-01..03)?

**Needs (macos-device).** The owner's Apple-silicon Mac on macOS 26.x with Apple `container` installed (optional per case: missing tool is recorded `skipped-not-installed`), podman, docker CLIs as available, `python3`, bash 3.2 (stock). Registry access for a small image (`SPIKE_IMAGE`, default `docker.io/library/alpine:3`). No accounts, no cost. The cases create a random per-run Apple internal network and label-test container. The V-AC-02 listener binds an ephemeral port to one chosen interface address and serves one random canary response; it never exposes a working directory. Cleanup targets only successfully created resources with this run's random names.

**Script.** `just macos-ondevice OUTDIR` calls `test/macos/on-device.sh`, which runs `scripts/spikes/ws05-p0-01.sh OUTDIR` (on non-Darwin prints "macOS only", exits 2). Use a new private output path; evidence is never overwritten. Evidence is `OUTDIR/WS05-P0-01.evidence.jsonl`, one JSON line per case `{id, macos, arch, thegn_commit, cmd, rc, expect, stdout_sha, stdout_head, stderr_head, verdict}`. For this suite the JSONL omits raw stdout/stderr; raw output stays in the private `OUTDIR/WS05-P0-01/<id>.out|err` directory with basic username/path/host/address/image redaction. Treat raw captures as local-only; copy only reviewed, whitelisted fields into repository fixtures. `test/macos/lib.sh` shares the existing case-runner contract with WS05-P0-06. `just macos-ondevice-selftest` exercises classification, redaction and collision safety without invoking a runtime. The Apple CLI flag forms remain probes: each row records the argv actually run.

## Steps

1. `OUT=$HOME/spike-evidence/WS05-P0-01-$(date +%F-%H%M%S); just macos-ondevice "$OUT"` (about 10-15 min; first run pulls the image). Run from an interactive shell whose `PATH` contains the Apple `container` executable and with its API service started.
2. Read the computed verdict and all per-case rows. V-AC-02 is positive only after an ordinary network proves the container can start, reach the internet by direct IP, and reach the canary listener, followed by explicit network-denied errors for both targets on the internal network. A nonzero exit alone, startup failure, listener failure, missing marker or timeout is inconclusive.
3. If `container` was missing, re-run after install; V-OCI cases need only the engines you have. Also start each engine's VM (Docker Desktop, Colima, OrbStack, Rancher Desktop, Finch) once and re-run to capture `V-OCI-03` per engine (or run WS02-P3-08's script per product).
4. Keep raw captures private. After review, commit only the whitelisted, redacted rows/fields required by WS02-P3-08 under `docs/audits/macos-evidence/<date>/`; never commit the raw V-OCI output. Note macOS version, arch, date, engine and source commit in the PR.

## Decision rule (from the issue)

- V-AC-01/02: `network = none` succeeds and the internal-network test proves internet and host blocked after both positive controls => positive branch for WS05-P0-02 (Apple `network = "none"` may be honoured); a reachable target is negative; failed controls or timeouts are inconclusive. V-AC-01 rc/stderr informs the wording of the Apple refusal.
- V-AC-03: record the accepted flag and observed process count under the image's default user. This probe alone does not establish enforcement because it has no user/control comparison; do not infer disabled policy or approval from its count.
- V-AC-04: `--label` accepted and visible in `container ls -a --format json` => WS05-P0-04 enables labels and the GC filter.
- V-AC-05: the `container --version` format fixes the parser table in WS05-P0-05.
- V-OCI-01..03: raw captures (podman machine JSON, no-machine state text, docker contexts and engine sockets) for WS02-P3-08 and WS05-P6-02.

## Downstream

Decides WS05-P0-02, P0-04, P0-05 and feeds WS02-P3-08, WS05-P6-02, P6-04; blocks WS05-P0-06 (runner) and, without a Mac in W0, moves P0-02/P0-04 to W3.

**Time.** 15 min run, 30 min review.
