# WS03-P0-03 - user-namespace and AppArmor matrix across Linux distributions

**Question.** What exactly do bwrap and the user-namespace probes print on each distro, and which single `UsernsStatus` does each capture map to, so WS03-P3-01's classifier is written against real stderr?

**Needs (ubuntu-apparmor).** Ubuntu 24.04 VM with `apparmor_restrict_unprivileged_userns=1` and NO bwrap profile; Ubuntu 24.04 with `bwrap-userns-restrict` loaded; Ubuntu 25.10; Ubuntu 26.04 (default config); Debian 12; Fedora 43; RHEL 10 with `max_user_namespaces=0`; WSL2 (kernel 6.6, 9p `/mnt`); a Docker container on the default seccomp profile; the GitHub `ubuntu-24.04` hosted runner. Ubuntu VMs and the runner are the W0 hardware; the rest may be containers or VMs. Each host needs bash, coreutils, `bwrap` (and `systemd-run --user` where systemd user units exist). No accounts beyond GitHub for the runner, no cost. A host you cannot get is listed "unreproducible: classifier gives `Unknown`, treated unavailable".

**Script.** `scripts/spikes/ws03-p0-03.sh OUTDIR CASE_NAME`: copy it plus `lib.sh` to the host (or clone the repo there) and run once per host. Read-only except bounded bwrap and `systemd-run` probes. Writes `OUTDIR/WS03-P0-03/userns-<case>.json` (user names, home paths redacted) and prints a SUGGESTED status; a human assigns the final status.

## Steps

1. Per host run `scripts/spikes/ws03-p0-03.sh "$HOME/spike-evidence/WS03-P0-03" <case>` using the fixture names `ubuntu2404_restricted`, `ubuntu2404_profile_loaded`, `ubuntu2510`, `ubuntu2604`, `debian_sysctl0`, `fedora43`, `rhel10_max0`, `wsl2`, `docker_default_seccomp`, `gha_ubuntu2404` (WS03-P3-01's tests expect at least `ubuntu2404_restricted`, `ubuntu2604`, `debian_sysctl0`, `docker_default_seccomp`). Each file records the file reads (`max_user_namespaces`, `unprivileged_userns_clone`, `apparmor_restrict_unprivileged_userns`, AppArmor module and current profile, the two `bwrap-userns-restrict` paths, the bwrap setuid bit), the argv, exit code and full stderr of every probe run (`bwrap --version`, `--help`, the real flag shape, `--unshare-net` on success, the nested bwrap-in-bwrap run), the `systemd-run --user ... ProtectSystem=strict PrivateTmp=yes true` result, `ping_group_range`, and the `PrivateDevices=yes` `/dev/pts` observation.
2. Ubuntu 24.04 rows: capture the exact failing stderr (expected: a "uid map" permission error under restrict=1) for both the no-profile and the profile-loaded host, and state whether loading the profile changes the outcome. Confirm the profile covers only `/usr/bin/bwrap` (a nix or user-local bwrap stays restricted) and that nested namespaces fail inside bwrap. thegn never installs or edits AppArmor profiles: loading the profile for the second row is a manual host step you do and undo.
3. GitHub hosted runner: the existing `security-e2e` job sets `kernel.apparmor_restrict_unprivileged_userns=0`; do NOT edit the shared workflow. Use a separate throwaway workflow run (or a VM) with that step skipped or reversed, running this script and uploading the JSON as an artifact.
4. `PrivateDevices=yes`: compare the host `/dev/pts` count with the unit's (`private_devices_pts_note`); equal and above 1 means the unit still sees host ptys.
5. Edit `status` in each JSON to exactly one `UsernsStatus` (`Available`, `DisabledSysctl(..)`, `AppArmorRestricted{..}`, `SetuidBwrap`, `Denied(..)`, or `Unknown` for unreproduced/ambiguous). Copy to `test/fixtures/confine/userns/<case>.json` plus a one-line-per-file summary next to them. Review for secrets: user names, home paths, hostnames.

## Decision rule and downstream

- Fail-closed: an unreproduced or ambiguous case maps to `Unknown`, which is treated as unavailable (the chain skips bwrap and doctor says why).
- A fixture mapped to a status sets the exact assertion in WS03-P3-01's classifier tests (`ubuntu2404_restricted` -> `AppArmorRestricted{ExtraAvailableNotLoaded}`, `ubuntu2604` -> `Available`, `debian_sysctl0` -> `DisabledSysctl`, `docker_default_seccomp` -> `Denied(NoPermissionNs)`).
- `/dev/pts` observation: if `PrivateDevices=yes` still exposes host ptys, WS03-P4-02 relies on the helper's exact-tty rule for systemd units, not on `PrivateDevices=yes`.
- Unblocks WS03-P1-01, P3-01, P1-03, P3-04, P4-01, P4-02, P7-03; feeds the WS11 Ubuntu row and (later) owner decision O20.

**Time.** 15 min per host once reachable; half a day total including VM setup.
