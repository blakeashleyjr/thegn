# WS03-P0-04 - copy-on-write options for ignored build dirs and shared caches

**Question.** Are bubblewrap overlay mounts (`--overlay-src`, `--overlay`) or reflink clones (`FICLONE`) safe and fast enough for (a) ignored build directories and (b) extracted-source/executable cache stores; and for each of the 16 `auto_cache_mounts()` entries does the host tool verify the store on use?

**Needs.** Linux with bwrap 0.11+ (dev host has 0.12.0) and unprivileged overlayfs in a user namespace; btrfs, XFS and ext4 volumes (loop-mounted images are acceptable: say so in the record); a scratch Rust workspace as corpus (NOT the thegn checkout; a few crates, with unit tests) and optionally a Node project; `inotifywait` (inotify-tools) for the watcher check. Heavy: cargo builds and a few GB per filesystem. No accounts, no cost. Do not point anything at production state directories. fuse-overlayfs is excluded.

**Script.** `CORPUS_RUST=/path/to/scratch/workspace scripts/spikes/ws03-p0-04.sh OUTDIR WORKDIR [RUNS=3]`, once per filesystem (WORKDIR on that filesystem). It runs native / reflink / bwrap-overlay incremental rebuilds (the same one-file edit each time, restored from a cold-state snapshot), measures upper growth against bytes changed, counts hard-linked files native vs overlay, checks inotify on the overlay, compares `cargo test` native vs overlay, verifies cleanup, and emits the 16-row cache skeleton. Everything it creates is under `WORKDIR/tgspike-cow-<pid>` and removed by trap. Node corpus (`npm ci && npm test`) is a manual add-on.

## Steps

1. Create the volumes (needs root; sudo = DESTRUCTIVE to nothing but the image files you create), e.g. for each of btrfs/xfs/ext4: `truncate -s 20G /var/tmp/tg-$fs.img; mkfs.$fs /var/tmp/tg-$fs.img; sudo mkdir -p /mnt/tg-$fs; sudo mount -o loop /var/tmp/tg-$fs.img /mnt/tg-$fs; sudo chown $USER /mnt/tg-$fs` (XFS needs reflink: `mkfs.xfs -m reflink=1`). Unmount and delete when done.
2. Prepare the corpus once; record sizes (`du -sb`).
3. Per filesystem: `CORPUS_RUST=... scripts/spikes/ws03-p0-04.sh "$HOME/spike-evidence/WS03-P0-04-$fs" /mnt/tg-$fs 5`. Each run prints a per-filesystem verdict.
4. Cache table (manual, per `auto_cache_mounts()` entry, re-read the function at run time since WS01-P6-01 changes sealed): for each of `.cargo/registry`, `.cargo/git`, `.rustup`, `.npm`, `.cache/pnpm`, `.cache/yarn`, `go/pkg/mod`, `.cache/go-build`, `.cache/pip`, `.cache/uv`, `.m2/repository`, `.gradle/caches`, `.cache/sccache`, `.cache/prek`, `.cache/pre-commit`, `.cache/nix` decide store kind (content-addressed, extracted, executable), whether the tool verifies on use (cargo `.crate` vs `Cargo.lock` checksum; Go zips vs `go.sum`; npm `_cacache` integrity; pnpm `verify-store-integrity`; nix store hashes; pip, uv, maven, gradle, yarn: find out), with a corrupt-one-file experiment on a COPY where cheap. Uncertain means "not verified on use" (so WS03-P2-05 isolates it). Note the B26 subdirectory split (`go/pkg/mod/cache/download`, `.cargo/registry/cache`, `.npm/_cacache`).
5. Write `docs/audits/linux-confine-2026-11/cow-evaluation.md`: decision, numbers, table, commands. Cleanup: unmount, delete images.

## Decision rule (verbatim from the plan)

Adopt overlay for build dirs (WS03-P8-01) and caches (WS03-P2-05) only if ALL hold: incremental rebuild at most 1.3 times native, zero corpus correctness failures, upper layer at most 2 times the changed bytes. Otherwise WS03-P2-05 uses private per-worktree directories and the reflink numbers go into the record (no `wt new` fast path, B49). If a filesystem fails, treat the whole decision as "otherwise" unless you argue a per-filesystem split (flag the runtime-check cost to P2-05).

## Downstream

Overlay adopted: P2-05 binds extracted/executable stores with `--overlay` uppers; P8-01 proceeds in W5 behind `build_dir_overlay = false`. Not adopted: P2-05 uses `$XDG_CACHE_HOME/thegn/sbcache/<worktree-key>/<cache-name>`-style private dirs and P8-01 is not built.

**Time.** 3-4 h plus volume setup; the cargo builds dominate.
