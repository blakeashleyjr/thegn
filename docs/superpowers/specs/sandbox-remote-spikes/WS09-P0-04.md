# WS09-P0-04 - benchmark the mux transport: credit window and optimistic OPEN

**Question.** Which initial flow-control window (64, 256 or 1024 KiB) for the thegn mux wire v2 keeps echo-latency head-of-line blocking within budget (echo p99 under a flooding channel at most 2x the idle p99), how does one mux compare with eight ssh channels on a ControlMaster, and what does sending DATA before OPEN_OK (optimistic OPEN) save?

**Needs (none).** Linux dev host with a local `sshd` and key login to `localhost` (`ssh -o BatchMode=yes localhost true` must work), Rust toolchain. Quiet machine (numbers are advisory per B9). No accounts, no cost. Dependency: WS09-P0-01 (records results in `add-connectors/design.md`; if absent, put results in the PR description and move them once the change exists).

**Script and probe.** `scripts/spikes/ws09-p0-04.sh OUTDIR [RUNS=3] [TARGET=localhost]`, building `scripts/spikes/probes/mux-bench/` (standalone std-only crate, built from a COPY under OUTDIR; the binary is both the remote agent and the client). Framing is the throwaway equivalent of plan 3.8: `[tag u8][chan u32 BE][len u32 BE][payload]`, preamble `\x00tgMUX\x02\n`, tags HELLO/OPEN/OPEN_OK/DATA/CLOSE/WINDOW. Seven echo channels plus one flood channel (the agent sends flood DATA only while it holds credit; the client returns credit as it consumes), 3 s idle then 6 s flood, per window; the same workload over a ControlMaster with eight `ssh` children (`cat` x7, `yes`); then 500 unary requests with and without DATA-before-OPEN_OK. Every child ssh/agent is killed and waited on. Prints per-window verdicts and the chosen window.

## Steps

1. `scripts/spikes/ws09-p0-04.sh $HOME/spike-evidence/WS09-P0-04-$(date +%F) 5` (about a minute per run for the workload, plus the build).
2. Read the machine description the script records (CPU, kernel, ssh version, loopback) and the per-window lines (`flood_p99` vs 2x `idle_p99`, flood MB/s for all three so the trade-off is visible), the ControlMaster baseline and the optimistic-OPEN delta.
3. Write the results table and the chosen window into `add-connectors/design.md` (a "Spike results" section) with the machine description.
4. Delete the scratch bench (it never merges; leave no `[[bench]]` entries or example files behind).

## Decision rule (from the issue)

Acceptance bar: echo p99 under flood at most 2x the idle p99 with the chosen window. Choose among 64, 256 and 1024 KiB the SMALLEST window that meets the bar (least buffered memory per channel and head-of-line delay); the plan default is 256 KiB. If none passes, keep the 256 KiB default, record the failed criterion, and the lead decides before WS09-P4-04a starts whether the mux ships only when chosen explicitly (`multiplex = "thegn"`, never by `auto`). Record the optimistic-OPEN delta: B40(f) keeps the feature either way; the number only sets the size of the claim in docs.
