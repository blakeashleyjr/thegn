# WS07-P2-01 - verify smolvm on real installs before the shipped definition is written

**Question.** Does smolvm behave on a real install as the 1.35.0 source says for the facts a shipped `lifecycle = "instance"` backend relies on (volumes, ownership, network flags, secrets, fork, resident processes, read-only rootfs)? 16 checks; answers the owner's 2026-10-20 decision on THE-141.

**Needs (macos-device + kvm).** Linux host with `/dev/kvm` (rw) first, then the owner's Mac (HVF; macOS rows are separate runs, never substituted by Linux results). A hand-installed smolvm 1.35.0 or current (record how it was installed and its checksum; releases are unsigned; thegn never downloads wrapper binaries; do not leave it on `PATH` afterwards). `python3`. No real credentials in the environment. If smolvm cannot be installed on the Linux host record "unverified: not installable on this host" with the failure output (that satisfies THE-141 but leaves P2-03 blocked). No accounts, no cost.

**Script.** `SMOLVM_BIN=smolvm scripts/spikes/ws07-p2-01.sh OUTDIR`. Runs in an EMPTY scratch directory (no repo `Smolfile` discovered), machines named `tgspike-<pid>-*` (all deleted by trap), mounts only the scratch dir (never `$HOME`, `~/.ssh` or a worktree), never starts `smolvm serve`. Each check appends `CHECK n: PASS|FAIL|REVIEW - detail` to `OUTDIR/WS07-P2-01.evidence.txt`; raw captures per check in `OUTDIR/WS07-P2-01/`. Auto-computed: 2, 4, 7, 9, 10, 11 (and 13 as an observation). `REVIEW` rows need a human read of the capture: 1, 3, 5, 6, 8, 12, 14, 15, 16. Manual: the `-i -t` PTY exec of check 1. The flag spellings are the source-read forms; a flag that differs on the real install is itself the finding ("differs"). Takes about 15 minutes (check 16 idles 60 s).

## Steps

1. Install smolvm by hand for the spike; `SMOLVM_BIN=$(command -v smolvm) scripts/spikes/ws07-p2-01.sh $HOME/spike-evidence/WS07-P2-01-linux`.
2. Read the REVIEW rows against the checks: 1 lifecycle/exit codes/missing-machine text, 3 `status --json` absent/stopped/running text, 5 host ownership of files written as `-u uid:gid` vs guest root, 6 `-w`, 8 `--net --block-private` (public egress, LAN address, gateway reachability; host-loopback by hand), 12 branch identity (hostname, machine-id, ssh host keys re-minted?), repeating `-v` in one `mount add`, `pause`/`resume`, 14 default image and size, 15 any read-only or discard rootfs option (does a write outside mounts persist across stop/start?), 16 resident process count and RSS (running, after stop, after delete=0).
3. Mac: repeat on the owner's Mac in the same session as WS05-P0-01/P0-06; label the evidence with the macOS version. If the Mac is unavailable record the macOS rows "not run: <reason>" (and leave macOS out of `live_tested_on`).
4. Author `openspec/changes/add-smolvm-backend/` with `proposal.md`, `design.md`, `tasks.md`, `verification.md` (the result table: PASS, FAIL or "differs" per check with smolvm version and host, or "not run"). The change ADDs requirements only ("Shipped microVM backends declare and prove their manifest", "Backends without single-file mounts report unpinnable git metadata"; it does not MODIFY "Backends are described by one profile table"). Replace task 5 in `openspec/changes/audit-sandbox-cross-platform/` (`tasks.md` section 5 and the status block of `smolvm-verification.md`) with a pointer, keeping its candidate-runtime evaluation text intact for WS07-P3-03. Run `openspec validate --all --strict` (the ratchet).
5. Confirm every machine is deleted and no stray VMM process remains (the script's final section lists leftovers; it must be empty).

## Decision rules (from the issue)

- Check 4 fails (volume not path-preserving) => smolvm is NOT shipped; WS07-P2-03..P2-10 stop; the definition stays `documented-only` (non-negotiable: git worktree metadata carries host paths).
- Any verb/flag differs from the source read => correct section 3.4 of the plan's smolvm definition (record the corrected argv in `verification.md`) before P2-03 starts.
- Check 16: the measured count replaces `resident = { per_instance = 2 }` and feeds the ARCHITECTURE process inventory and soak ceilings (WS07-P5-05).
- Check 15 finds a read-only/discard rootfs option => add it to the `create` template and set `read_only_root = "slot"` (`sealed` may admit smolvm); else `read_only_root = "unsupported"` and B23 makes `sealed` refuse smolvm (O23 default refuse).
- Check 5 shows root-owned/unwritable files => the template must always pass `-u uid:gid` and WS07-P2-10's git-metadata plan accounts for it.
- Checks 7-9 fail => downgrade `native:hostname-at-start` in the manifest; WS04-P4-05's lowering is not wired to it; record the leak.
- Check 10 shows a secret persisted or in argv => `secrets = "unsupported"`; fork bases may not carry secrets.
- Check 11 shows `--name` does not win => the wrapper must `env_clear`; blocker for P2-03's `env_allow`.
- Check 12: `mount add` cannot repeat `-v` => WS07-P5-03 issues one `mount add` per mount.
- Check 13: a surviving guest process => `kill_tree` stays `best-effort-pgid`, teardown relies on `stop`/`delete`.
- Check 14: the default image becomes the documented default when `[sandbox] image` is empty.
- The measured version is the lower bound of `version_req` (default range `>=1.35.0, <1.37.0`, upper per WS02-P4-15).
