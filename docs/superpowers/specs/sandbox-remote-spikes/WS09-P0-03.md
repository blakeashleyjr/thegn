# WS09-P0-03 - Windows-host transport facts and account-only connector recipe flags

**Question.** On real Windows 11: is `ssh.exe` stdio binary-safe (needed for the thegn mux over `ssh.exe`)? Is `wsl.exe -e` stdio binary-safe? How does Win32-OpenSSH run a `ProxyCommand` (interpreter, `%` escaping)? Does ControlMaster exist, and does `ssh_program = ["wsl.exe","-e","ssh"]` give one (including the agent-socket gap)? And for the account-only recipes (AWS, GCP, Azure, Teleport, Twingate) which flags are real?

**Needs (windows-device + paid-account).** Windows half: Windows 11 24H2 (26100.9278+) KVM VM and/or the owner's box, after the WS06-P0-05 baseline gate, plus a Linux host reachable over ssh with key login (`SPIKE_SSH_TARGET`), WSL2 with a distro. Account half (W5, about $0-20/month, owner decision E6): AWS (SSM, EC2 Instance Connect Endpoint), GCP (IAP), Azure (Bastion bills hourly: tear down the same day), Teleport, Twingate. Rows without an account are written "blocked: no account" with an owner and the W5 date. Dependencies: WS09-P0-02 (creates `config/recipes/connector/VERIFICATION.md`), WS00-P1-08, WS06-P0-05.

**Script (Windows half only).** `$env:SPIKE_SSH_TARGET='user@host'; pwsh -File scripts\spikes\ws09-p0-03.ps1 -OutDir C:\spike-out [-Distro Ubuntu]` (parse-checked only). 50 MB random file with sha256 on both sides through `ssh.exe ... cat` and through `wsl.exe -e cat` (redirections via `cmd.exe`, so bytes are never decoded); `ProxyCommand` probes with a `cmd` and a `powershell` command that print `%h/%p/%r` and a `%%` literal to stderr; ControlMaster on Win32-OpenSSH (expected unsupported); ControlMaster via WSL OpenSSH (`-O check`) and `SSH_AUTH_SOCK` inside WSL. Records the quoting goldens of WS09-P1-02 as "blocked: goldens not yet written" and the WSL idle-vs-hold row as shared with C6 of `ws06-p2-00.ps1` (same device session; copy that result). The account rows are NOT scripted: cloud CLIs, credentials and billed resources are a human step.

## Steps

1. Windows half: after the baseline gate, `pwsh -File scripts\spikes\ws09-p0-03.ps1 -OutDir C:\spike-out`. Note OS build, WSL version, OpenSSH version and PowerShell version (the script records them) as the "Environment" line per run.
2. Read `proxycommand-*.err`: which interpreter ran, whether `%h %p %r` expanded, whether `%%` gives a literal `%`.
3. Account rows when the accounts exist (credentials from the vendor CLIs' own login, never pasted into files): AWS SSM ProxyCommand (Linux and Windows targets), EC2 Instance Connect Endpoint `open-tunnel`, `send-ssh-public-key`, the SSM 20-minute idle timeout; GCP `start-iap-tunnel --listen-on-stdin` and `compute ssh --tunnel-through-iap`; Azure Bastion tunnel; Teleport `tsh config`, `tsh ssh -t`, `tsh status` exit codes; Twingate headless. Tear down billed resources the same day. Bastion and IAP tunnels listen on loopback only: record the bind address. Redact credentials, SSM session tokens and Teleport certificates.
4. Append dated rows to `config/recipes/connector/VERIFICATION.md` (same columns as WS09-P0-02; keep both sets of rows on merge conflicts) and a "Decisions" block.

## Decision rule (from the issue)

- `ssh.exe` stdio not binary-safe => `multiplex = "thegn"` on Windows needs `ssh_program` via WSL, or a base64 framing mux feature named `b64` (WS09-P4-04a adds it; `b64` joins the plan's mux feature vocabulary: `optimistic_open`, `share_state`, `pair_code_only`).
- No `--listen-on-stdin` on GCP => the GCP recipe uses the supervised forward form (`start-iap-tunnel INST 22 --local-host-port=localhost:{free_port}`).
- `wsl.exe -e` stdio not binary-safe => WS06's generated connector sets `exec_binary_safe = false`: no sync path and no mux over it; WS06 uses a `\\wsl.localhost` copy for install.
