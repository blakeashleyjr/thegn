# WS09-P0-05 - size remote delivery: full static musl `thegn` vs a feature-trimmed `thegn-remote`

**Question.** Which binary does the remote daemon install ship: the full static musl `thegn` (82,779,192 bytes on the dev host; re-measure) or a smaller feature-trimmed `thegn-remote` (daemon, mux, bridge; no TUI, media, voice, plugin UI, gtui)?

**Needs (none).** Linux dev host, `gzip`, `zstd` 1.5+, the musl rustup target and cross compiler (`just build-musl`, or `nix build .#thegn-musl`), a 2-vCPU VM for the decompression timings (the script records `nproc`; a run elsewhere is visibly not comparable), two consecutive alpha builds of each binary for `--patch-from`. No accounts, no cost. Release builds are heavy: build ONLY `-p thegn-host` in release (one build per artifact), use `THEGN_ALLOW_HEAVY=1` deliberately, never a whole-workspace release. Dependency: WS09-P0-01 (results go to `add-remote-daemon/design.md`).

**Script.** `FULL_BIN=... TRIMMED_BIN=... [PREV_FULL_BIN=... PREV_TRIMMED_BIN=...] [SMOKE_PASS=1] scripts/spikes/ws09-p0-05.sh OUTDIR`. Measures binaries you already built (the builds and the feature split are throwaway source edits and not scriptable): raw bytes, `gzip -9`, `zstd -19 --long=27`, best-of-5 decompression time, `zstd --patch-from` delta, SHA-256s; computes the decision.

## Steps

1. Scratch branch only. Baseline: `just build-musl` (or `nix build .#thegn-musl`); record the byte size.
2. Add a throwaway cargo feature split in `thegn-host`; build `thegn-remote` with `--no-default-features` plus the keep list (daemon, mux-agent, bridge, `remote-info`, `attach`, `session list`, `pair new --code-only`, `sandbox enter --intent-*`; off: TUI, media, voice, plugin UI, gtui). Check which of those commands exist yet (`mux-agent`, `remote-info`, `pair new --code-only`, `sandbox enter --intent-*` come from later items). If the split cannot compile with a reasonable edit, the rule falls back to the full musl `thegn`; record the blocking dependency.
3. Build the two most recent consecutive alpha builds of both binaries (the repo bumps `0.1.0-alpha.N` per batch) for the delta.
4. Smoke subset on the trimmed binary: mux-agent over the fake connector, attach, session list. Where a command is not in the tree use the existing `daemon`, `attach`, `session list` and record what could not run and why. Then `SMOKE_PASS=1` if it passed.
5. `FULL_BIN=target/x86_64-unknown-linux-musl/release/thegn TRIMMED_BIN=... PREV_FULL_BIN=... scripts/spikes/ws09-p0-05.sh $HOME/spike-evidence/WS09-P0-05-$(date +%F)`; run the decompression part on the 2-vCPU VM.
6. Record the table (columns: artifact, raw bytes, gzip -9, zstd -19 --long=27, decompression time on 2 vCPU, patch-from delta for both artifacts) and the decision in `add-remote-daemon/design.md`; discard the scratch branch.

## Decision rule (from the issue)

Ship `thegn-remote` iff its raw size is at most 40% of the musl `thegn` size AND it passes the smoke subset; otherwise WS09-P5-01 ships the musl `thegn`. Delivery always uses compression. If the median `--patch-from` delta is at most 20% of the `.zst` full size, record a follow-up for delta delivery (out of scope here).

## Downstream

WS09-P5-01's `Files:` line names the chosen artifact (its owner edits it); the release workflow's build target; install size/time budgets in WS09-P5-02a; whether `thegn-remote` becomes a real feature split. Expected install size about 20-30 MB `.zst` for the musl binary, less for `thegn-remote`.

**Time.** 2-3 h (builds dominate).
