# WS09-P0-02 - connector tool flags and transport facts reachable without paid accounts

**Question.** Which connector-recipe facts can be checked on a Linux host: tailscale, cloudflared, kubectl exec binary safety, limactl, incus, multipass, dumbpipe (does it take the ticket via env or stdin?), wstunnel, netbird, zerotier, nebula, zrok, step, opkssh, et, shpool, tmux flags, systemd-ssh-proxy over vsock, `git bundle` to stdout across git 2.30-2.54, and `zstd`/`gzip` presence in base images?

**Needs (none).** A Linux host (the sandbox of a live thegn may block network or installs: install tools into a scratch directory, never touch the repo or `$HOME` config). Tools are whatever is present; absent tools become "still unverified" rows with the exact command. Optional: `kind` + `kubectl` + a container engine (kind cluster; pulls images), `docker`/`podman` for the base-image table, several git binaries (via nix shells or builds) for the bundle matrix, a local VM for vsock. No accounts. Dependency: WS00-P1-08 (creates `config/recipes/connector/`; if absent create only `VERIFICATION.md` there).

**Script.** `scripts/spikes/ws09-p0-02.sh OUTDIR`. Captures `--help`/version/status output for every tool on the list (timeout each), records absent tools as unverified rows, and writes draft table rows (`recipe or topic | command | tool version | date | result | evidence level | decision`) into the evidence file. Opt-in extras: `RUN_KIND=1` creates a kind cluster `tgspike-<pid>` and does the 50 MB `kubectl exec -i` sha256 round trip (cluster deleted by trap); `RUN_IMAGES=1` pulls debian:12, ubuntu:24.04, alpine:3.20, fedora:41 and tests `zstd`/`gzip`; `GIT_BINS=/path/git-a:/path/git-b` runs the bundle matrix (`git bundle create - refs/heads/main` and `... ^<tip>` to stdout, then fetch from the file) once per git binary.

## Steps

1. `scripts/spikes/ws09-p0-02.sh $HOME/spike-evidence/WS09-P0-02-$(date +%F)`; then with extras as available: `RUN_KIND=1 RUN_IMAGES=1 GIT_BINS=... scripts/spikes/ws09-p0-02.sh ...`.
2. dumbpipe: the script only greps `--help`; read `src/main.rs` of the installed version (a fresh scratch clone, nothing executed) to decide whether the ticket can arrive via an environment variable or stdin. Record the evidence.
3. tailscale: use `tailscaled` in userspace mode for the exit-code rows (stopped, logged out, up). `shpool attach -f` and `tmux new-session -A -s`: record flag presence (inputs to the no-daemon wrapper item). systemd-ssh-proxy over `vsock/` through a local VM is manual (shared with WS07). macOS 15 `zstd`/`gzip` presence is by hand.
4. Decide a template for each locally reachable row or mark it explicit `documented-only`; mark every row not run "still unverified: <exact command>". Re-read plan WS09 section 12 (Eternal Terminal, Tailscale, Netbird, ZeroTier, Nebula, zrok, wstunnel, step-ca, opkssh, limactl, incus, systemd-ssh-proxy, dumbpipe, kubectl) so no row is missed.
5. Commit `config/recipes/connector/VERIFICATION.md` (Decisions section on top; dated rows; evidence levels `verified on this host`, `source read`, `vendor docs`, `still unverified`; redact tickets and tokens). Not embedded in the binary; link it from WS08-P6-00's `INDEX.md` only if that exists.

## Decision rules (from the issue)

- dumbpipe accepts the ticket through an environment variable or stdin => WS09-P7-03 moves the ticket there; otherwise it documents the residual in `known-limitations.md` and leaves argv as is.
- A missing wrapper flag (`shpool`, `tmux`) => WS09-P5-09 drops that `session_wrapper` value and gives a validation error for it.
- Each locally reachable recipe row ends with a decided template or an explicit "documented-only" tier.
