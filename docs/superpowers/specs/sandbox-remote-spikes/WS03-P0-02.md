# WS03-P0-02 - exec cost of a self-exec helper against a small static binary

**Question.** Is the confinement helper the hidden `thegn __sandbox-exec` entrypoint of the main binary (self-exec) or a separate small static `thegn-confine-exec`? Decided by p50/p95 wall time against `/bin/true` on x86_64 and aarch64.

**Needs.** Linux x86_64 dev host AND an aarch64 machine (the `ubuntu-24.04-arm` hosted runner or a device; without one record "aarch64 unverified (x86_64 only)" and the helper stays dev-channel on aarch64). Rust toolchain; ideally the musl target (`rustup target add <arch>-unknown-linux-musl`) else a `crt-static` glibc build is used and recorded. A release `thegn` binary built from a THROWAWAY branch (step 1). No accounts, no cost. Set the CPU governor to `performance` if you can, or record it.

**Script and probe.** `THEGN_SELF_EXEC_BIN=<release thegn> scripts/spikes/ws03-p0-02.sh OUTDIR [RUNS>=200]`, building `scripts/spikes/probes/exec-cost/` (standalone crate: `confine-exec-static` = the ~1 MB size-optimised static subject; `exec-bench` = interleaved spawn+wait timer, std only). Run once per machine.

## Steps

1. On a throwaway branch (never merged), in `crates/thegn-host/src/main.rs` `run_main`, before `mem::tune_allocator` and clap (next to the `--voice-worker` early dispatch), add: when `argv[1] == "__sandbox-exec"`, find `--` and `execve` the rest (use `std::os::unix::process::CommandExt::exec`). Build ONLY `cargo build --release -p thegn-host --bin thegn` (one release compile; not the workspace). The dev-host binary is ~127 MB.
2. x86_64 dev host: `THEGN_SELF_EXEC_BIN=$PWD/target/release/thegn scripts/spikes/ws03-p0-02.sh $HOME/spike-evidence/WS03-P0-02-x86 300`.
3. aarch64 machine: build the same throwaway `thegn` there, copy this repo checkout (scripts and probes only), run the same command into `...-aarch64`.
4. The script records p50/p95 per subject, overhead over baseline, SHA-256 timing of both images, governor, machine model, image sizes.
5. Write `docs/audits/linux-confine-2026-11/exec-cost.md`: raw numbers and commands for both machines, the decision, and (if the small binary wins) what changes: nix `postInstall`, installer list, `smoke-pkg`, check-cross stub `main`, materialised exactly as the self-exec copy (B19: content-addressed under `$XDG_STATE_HOME/thegn/bin/<sha256>/`, 0500 file in a 0700 directory, read-only bind). Record both comparisons: 8 ms trigger (bare exec) and the 4 ms p50 / 10 ms p95 whole-helper budget (2 ms of the budget stays reserved for Landlock and seccomp setup). Commit the numbers, not the binaries.

## Decision rule (from the issue)

- Self-exec p95 overhead over `/bin/true` above 8 ms on EITHER machine: ship `[[bin]] thegn-confine-exec` (nix `postInstall`, installer list, `smoke-pkg`, check-cross stub `main`), materialised as B19 says.
- Otherwise: self-exec; no new binary; WS03-P1-06b hashes the 127 MB image once per process (about 0.1 s) off the loop.
- No aarch64 machine: record "aarch64 unverified (x86_64 only)"; helper dev-channel on aarch64 until measured.

## Downstream

Unblocks WS03-P1-01 (openspec change), WS03-P1-06 (helper entrypoint) and WS03-P1-06b (materialisation), which pick their target from this record. The script prints each machine's verdict only; the decision needs both.

**Time.** 1.5 h per machine (the release build dominates), 30 min for the record.
