# Shared lock inventory

## Scope and method

This is a source audit of base `00c121687bf038525edc2783406537305e523b20`. It covers
production process-wide `static`/`OnceLock`/`LazyLock` mutexes and rwlocks in the Rust
crates, plus the named shared-state locks in metrics, glyph/log hydration, the frame
writer, daemon service, database wrappers, and scan pool. Per-request locals and
test-only statics are excluded. The first-pass count of 145 was not reproducible from a
recorded command, so it is withdrawn. `rg -n 'static.*(Mutex|RwLock)' crates --glob '*.rs'`
returns 217 matching source lines at this base; it is a broad declaration-line scan, not
a count of production locks. The audit excluded 15 test-only locks after checking `cfg(test)`
scopes (including fixtures embedded in production source files).

No lock was timed. THE-1645 calls for opt-in measurement of suspect paths, not blanket
lock timing. “Safe” below means the lock scope was verified in source to avoid slow or
size-dependent work; “worker-only slow” identifies deliberate serialization away from
the UI/runtime; “unmeasured” means reading source alone does not settle contention or
cost. Line references are to the stated base.

## Verified positive patterns

- Frame writer: queue operations are guarded, but the worker invokes the sink only
  after leaving the queue scope; its source comment states this explicitly
  (`crates/thegn-host/src/frame_writer.rs:698-699`; sink write/flush at `:900-903`).
- Metrics: the supervisor owns its state on a named background OS thread and sends
  snapshots through a channel (`crates/thegn-host/src/metrics.rs:72-78,119-181`). It
  has no shared metrics mutex to flush under. The perf CPU ledger drains atomic
  counters (`crates/thegn-host/src/perf.rs:326-350`); the diagnostics WARN+ ring uses
  `try_lock` for both push and snapshot (`crates/thegn-core/src/diagnostics.rs:151-166`).
- Glyph persistence: rows are cloned/snapshotted before persistence; SQLite writes
  occur after the glyph-cache guard is released
  (`crates/thegn-host/src/hydrate.rs:2025-2061`). The cache retain itself remains a
  size-dependent critical section, listed as a violation above.
- Log scanning: `update_log_error_total_in` snapshots state, reads and parses the
  file unlocked, then validates and commits the snapshot (`crates/thegn-host/src/hydrate.rs:4060-4112`).

The async-path std mutexes named above are `ci_refresh` (coordinator/memos/health),

Their critical sections contain no await; media handles are moved out before await.
`db_task` queue/notice state is owned by the writer or cloned before notification. The
remaining declaration inventory has source-local call sites, but this pass did not map
every call to an async caller.

## How to keep this current

Update this document in the same change that adds a process-wide lock or holds shared
state across I/O. Keep the companion [runtime worker inventory](runtime-workers.md)
aligned when a lock owner or caller thread changes.
