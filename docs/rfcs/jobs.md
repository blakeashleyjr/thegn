# Thegn Jobs and the hosted execution service

Architecture proposal for review, 18 November 2026. The handoff settles the product split and decisions D1–D13. The implementation choices and release gates below are recommendations. The companion [Job contract v0](job-spec-v0.md) specifies what a client, executor and queue must agree on.

## Release sequence

The [agent tier and local-mode amendment](agent-tier-local-mode.md) defines workspace ownership, routed commands and expiring VM leases. The [delivery RFC](agent-execution.md) sets the first release gate. A local stock agent sends a build or test to the runner selected by its project, either Fly Sprites or Vercel Sandbox. Both vendors must pass the same terminal and laptop CPU checks.

The local daemon owns admission, snapshotting, the recoverable queue and results. A local fixture proves the contract during development. The first release executes real commands on both remote providers. Enrolled SSH nodes and volume-backed Fly Machines follow. Publish the tested contract before the hosted control plane consumes it. The first hosted release has one qualified Kubernetes pool. The next release earns the multi-cloud claim by losing an entire pool during a run and recovering both execution and outputs.

## OSS execution

1. **Submit and snapshot.** An authenticated submit request reserves its idempotency key. The daemon snapshots the requested worktree once, resolves the environment, checks policy and records the immutable inputs and shard rows. A retry resumes or returns that submission. The same references feed every attempt.
2. **Place and lease.** The daemon compares required controls with configured offerings, then ranks eligible capacity by cache locality, wake latency and estimated cost. Atomically reserve the slot, budget allowance and shard lease. If provisioning precedes a claim, persist an idempotent provision operation with an expiry. Reconcile it after restart. A capable but busy pool queues work. A job no configured offering can satisfy gets an actionable rejection.
3. **Execute.** Local execution exercises the guest protocol over a local socket. On SSH and Fly, an enrolled node dials out over authenticated iroh, reports capabilities and launches the guest. Use vsock across a VM boundary. The guest receives a read-only snapshot, private writable workspace, and run-scoped grants. It streams bounded logs and stages outputs. The daemon owns final publication. Execute-only providers adapt their APIs to the same results and fences and advertise the capabilities they can actually enforce.
4. **Recover and meter.** On startup the daemon reads queued shards, reservations, attempts and pending publications from durable SQLite, compares heartbeats and resumes deadlines. Treat queue state as authoritative data with a backup/migration policy distinct from rebuildable views. A capacity reservation survives until release or expiry. Account for failed and preempted attempts, deduplicate usage by attempt and meter interval, and release outstanding budget reservations. Providers supply price and usage evidence. The guest cannot set its own charge.

The Fly reference runs one job at a time per Machine. Retain private `/nix` and compatible `target/` state by repo, trust domain, toolchain, profile and target. Use a per-run writable layer for read-only consumers, including for local-disk cache hits. Seed new volumes from a trusted golden image. Stop through the node after leases, transfers and authorized debug holds are clear. A volume-locality stockout goes back through placement. Keep the proxy-managed ssh-ng pool separate from these job builders. The Nix proxy resolves a builder and tunnels the protocol. Trusted infrastructure verifies provenance and signs eligible staged outputs. [Fly Proxy autostop](https://fly.io/docs/reference/fly-proxy-autostop-autostart/)

Assign a persistent builder to a single trusted write domain. For external or agent-authored source, use a fresh admitted VM with trusted cache data mounted read-only and discard its writable layer afterward. A warm builder's signed Nix closure and mutable compiler state must never acquire trusted provenance from an untrusted run.

On user-owned Kubernetes, Indexed Jobs supply shard slots. Each pod must claim its logical shard before executing. The queue owns retry limits, even if Kubernetes creates replacement pods. Disruption observations are hints attributed to a pod UID and attempt. A delayed observation cannot revoke the replacement. No operator is required for the OSS provider. A failed-run PTY is an explicit, time-limited OSS hold under the same admission and access policy. A managed host reaps only after that hold is released. [Kubernetes Jobs](https://kubernetes.io/docs/concepts/workloads/controllers/job/)

## Hosted execution

**Demand and dispatch.** Start with a single logical queue in highly available managed Postgres and one authoritative writer per shard. Workers long-poll with free capacity. The matcher first applies tenant quota, trust, architecture, location and budget, then allocates CPU/memory shares across eligible tenants in short rounds using dominant-resource fairness. A cache hit can skip the wait for the next round only within the same fairness and quota decision. Apply cache affinity after those checks. Track queue age by eligible tenant and resource shape so a stream of small cache hits cannot starve a large job.

**Supply.** The planner sets targets per provider, region, shape, isolation and price class. The operator requests pods and warm templates. The cluster autoscaler supplies nodes. Feed time to ready, stockouts, reclaim rate, backlog and cache-transfer cost back into the planner. Cool a failing pool down and probe before reopening it. Try authorized BYOC, owned, spot and on-demand capacity in policy order. Size standby per eligible shape and residency group from measured lost capacity, startup delay and tolerated queue time. An aggregate spare-vCPU target can hide an entire region or architecture with no failover capacity.

**Isolation.** Admit tenant runs only on a verified hardware-virtualized runtime, including BYOC and dedicated nodes. Exclusive tenancy is a separate placement attribute. Require the approved RuntimeClass, node configuration and actual guest isolation on both warm and cold paths. Match warm claims by immutable image, template, architecture, controls and resource limits. Inject credentials only after claim, run sidecars inside the same guest, then destroy the pod after one run. A template miss uses the exact requested image on the cold path. Enforce resource overhead, default-deny ingress and egress, block metadata and cluster-control endpoints, and disable ambient service-account tokens. Workload output is untrusted even when it came through the open-source guest.

The guest boundary protects a host from tenant code. Whoever administers the host still controls the guest's execution environment. Bind BYOC enrollment and claims to the owning tenant by default. Cross-tenant overflow uses service-operated, qualified pools. Scope the operator's credentials to its pool and keep each guest grant scoped to one run and epoch.

**Storage.** Keep an L0 node cache, an L1 per-pool cache and a durable L2 origin in the allowed residency domain. R2 is the proposed origin where policy permits. Pull upstream dependencies and images through pool-local mirrors. Immutable blobs can be replicated asynchronously. For a visible result, require receipts for every referenced blob from storage that meets the promised failure domain. Phase 3 should wait for a durable origin receipt for required outputs. Optional cache warming can lag. Test fetching the successful result after its entire execution pool disappears.

**Delegation.** When Thegn targets the service, persist the remote operation ID under a stable submission key before treating a timeout as a failure. Send the immutable spec, source digest, original shard identity and remaining retry/deadline policy. The service owns attempts for each delegated shard. The daemon reconciles the same operation until terminal and propagates cancel idempotently. An ambiguous remote acknowledgement is resolved by lookup under the original key. Any transfer back to local scheduling needs confirmed revocation or terminal ownership at the service. This prevents an outer retry loop from multiplying the inner retries.
