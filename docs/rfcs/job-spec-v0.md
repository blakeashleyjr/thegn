# Thegn Job contract v0

Draft for public review, 18 November 2026. A Job consumes one immutable snapshot and produces one structured result with artifact references. A shard is a logical partition of that job. A run is one execution attempt of one shard. All providers use those meanings, including when a job has one shard. The wire choices, defaults and failure rules here are proposed for the [Jobs architecture and release plan](jobs.md).

The first implementation provides the [spec and result types](../../crates/thegn-job-spec/src/lib.rs), [canonical directory encoder](../../crates/thegn-cas/src/lib.rs), [attempt lease transitions](../../crates/thegn-lease/src/lib.rs) and [guest handshake](../../crates/thegn-guest-proto/proto/guest.proto). Replay the four crates' contract tests together with `cargo nextest run -p thegn-job-spec -p thegn-cas -p thegn-lease -p thegn-guest-proto`. The [change ledger](../../openspec/changes/add-job-contract-v0/tasks.md) tracks the storage and executor checks.

Non-Rust clients can consume the generated [JobSpec schema](../../crates/thegn-job-spec/schemas/job-v0.json) and [JobResult schema](../../crates/thegn-job-spec/schemas/result-v0.json). A schema describes wire structure. The schema cannot express the cross-field rule that a typed `recipe` replaces `steps`, so a consumer that is not the typed selected-runner route must reject a spec carrying `recipe` even when `steps` is empty or present. The submission parser also checks cross-field and path constraints. Byte quantities accept unsigned integer bytes or the binary suffixes Ki, Mi, Gi and Ti. Durations accept a positive integer with ms, s, m or h. Result timings use milliseconds, and cost amounts use millionths of the stated currency.

## A portable job

```yaml
apiVersion: thegn.dev/jobs/v0
kind: Job
metadata:
  name: web-e2e
source:
  snapshot: auto
  exclude: [node_modules/, test-results/]
environment:
  image: ghcr.io/acme/ci:2026-11
resources: { cpu: 8, memory: 16Gi, shm: 2Gi, disk: 40Gi, arch: x86_64 }
isolation: microvm
placement:
  { providers: [any], regions: ["us-*"], spot: allowed, affinity: [cache] }
services:
  - name: db
    image: postgres:17
    env: { POSTGRES_PASSWORD: test }
caches:
  - key: "playwright-${hash(package-lock.json)}"
    paths: ["~/.cache/ms-playwright"]
    restoreKeys: ["playwright-"]
env: { CI: "true", PLAYWRIGHT_JUNIT_OUTPUT_FILE: test-results/junit.xml }
steps:
  - name: install
    run: npm ci
  - name: test
    run: npx playwright test --reporter=junit --shard=${THEGN_SHARD}/${THEGN_SHARDS}
shards: 8
results: { junit: "test-results/*.xml" }
artifacts: [test-results/]
retry: { onPreempt: { max: 2 }, onFailure: { max: 0 }, escalate: on-demand }
timeout: 30m
```

### Parse, resolve and admit

| Input                         | Proposed v0 behavior                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| ----------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Envelope and source           | Require a supported `apiVersion`, `kind: Job`, and a name. Labels are informational. `snapshot` defaults to `auto` at the submitting daemon. A remote consumer gets a CAS digest and a scoped read grant.                                                                                                                                                                                                                                                                                                                                                                                  |
| Environment                   | Exactly one of OCI `image` or `nix: {flake: …}`. Resolve image tags, including sidecars, to digests before dispatch and record the platform selected. For a relative flake, resolve from the submitted snapshot and record locked input identity. Reuse these values on retry.                                                                                                                                                                                                                                                                                                             |
| Resources and policy          | Validate positive resource quantities, memory/disk/shm units and architecture (`any`, `x86_64`, `aarch64`). Omitted shape uses provider defaults and the result records the allocation. `isolation` defaults to policy. Provider/region allow-lists intersect trusted policy. Spot defaults to `allowed`. Affinity is a hint. Dedicated-host requests require exclusive hardware in addition to all required guest controls.                                                                                                                                                               |
| Services, steps and env       | Services share the job's network namespace and are terminated with the attempt. Require at least one ordered step unless a typed `recipe` is present, in which case `steps` MUST be empty and the spec is only for the typed selected-runner route. Specify either a script run by the guest shell or an explicit argv vector. Run from the private working directory. Record step start, exit code/signal and duration. Scripts that depend on service readiness should check it within the deadline. Validate env strings and reserve the `THEGN_` runtime names.                        |
| Caches                        | Exactly one keyed path set or named tool recipe per entry. Evaluate `${hash(file)}` against the immutable input. Use literal exact keys first, then declared prefixes in order with the latest committed compatible version and a stable tie-breaker. `~` means the guest's private home. Tools such as sccache and Nix imply explicit capabilities.                                                                                                                                                                                                                                       |
| Secrets                       | Names only. Resolve via policy and broker using run- and epoch-scoped grants. Authorize secret access independently of cache writes. Withhold a grant if an executor cannot enforce its injection or proxy mode.                                                                                                                                                                                                                                                                                                                                                                           |
| Shards, results and artifacts | `shards` defaults to 1 and must be positive and within policy limits. Public `THEGN_SHARD` and `ShardResult.index` range from 1 to N. `THEGN_SHARDS` is N. All shards see the same snapshot. JUnit globs, cargo JSON parsing and artifact paths are opt-in. A Kubernetes completion index of 0 becomes shard 1. [Playwright CLI](https://playwright.dev/docs/test-cli) · [Kubernetes Jobs](https://kubernetes.io/docs/concepts/workloads/controllers/job/)                                                                                                                                 |
| Retry and timeout             | `onPreempt.max` defaults to 2, `onFailure.max` to 0. Counts are additional attempts per shard. Preemption/lost leases and command failures have separate counters. After the preemption allowance, optional escalation permits one additional attempt on on-demand capacity if policy and budget allow it. `never` disables replay for that cause. Default timeout is 60 minutes per run, including preparation and commit. A step deadline can shorten it. A caller's RPC timeout ends the wait. Persist any overall submission deadline separately and cap new leases by time remaining. |

Parse known fields strictly and report field paths for errors. Additive fields that change execution imply a negotiated capability. An older submitter rejects an unknown execution field before it can disappear in a round-trip. Providers advertise supported spec versions and capabilities per offering, including transport limits, enforced isolation, architecture, services, shm, parser and cache support. Admission requires **one offering** satisfying the full intersection. A union of mutually incompatible offerings is insufficient. Report the failed constraints per candidate. Policy denial and unavailable capacity are distinguishable from an unknown capability. Resolve trusted policy again when granting a lease and when launching the actual runtime.

The daemon derives the author class from trusted identity and source information. A repository can raise its isolation floor, narrow allowed providers, reduce spend or forgo cache writes. The effective policy intersects all grants and takes the strongest required boundary. Owner work can use an admitted container. Agent and external work require a VM boundary. The service requires that boundary for every tenant. Check actual capacity, budget, location and enforceable controls even when a job supplies an explicit provider.

### Client operations

Expose submit, status, watch/logs, artifacts and cancel through the public API. Submit returns a stable job ID once the request is durable. A retry or a lookup by scoped idempotency key recovers that ID. Status returns current phases or a terminal result. Logs take an attempt ID and cursor for streaming, tail or bounded search. Artifact reads select a job, shard, attempt and manifest path. Cancel can be replayed and reports which terminal state won a race. All reads require authorization for that job. Give agent credentials scoped verbs, concurrency and byte limits. CLI, MCP helpers such as build/test/nix_build, and the optional hosted provider use these same operations.

## Input, output and storage authority

The [agent-tier proposal](agent-tier-local-mode.md#3-workspace-snapshots-and-source-changes-a4) layers routed command output on this boundary. A worker can publish a candidate patch under its attempt fence. Only the workspace authority can apply it. The proposal also gives live VM leases their own API resource so existing v0 documents retain `kind: Job`.

Build the snapshot from the selected worktree's current bytes, including tracked edits, additions, deletions and non-ignored untracked files, subject to explicit excludes. Exclude Git administrative data. Apply trusted secret/path exclusions before upload. Treat gitlinks, non-portable path names and unsupported file kinds as validation errors until specified. Read symlinks as links, constrain their targets to the tree, preserve the executable bit and sort entries as REAPI requires. Detect changing inputs during capture and retry or return a snapshot error. A submitted job is pinned once its input root is durable.

Use SHA-256 and byte count for every blob. The snapshot reference is the digest of the canonical serialized REAPI root `Directory`. Child directory and file digests recursively identify its contents. Git OIDs are useful capture metadata. A cache-volume manifest is a separately versioned list of paths and chunks. Freeze exact directory bytes and expected digests in a golden fixture independently decoded by a REAPI implementation. [REAPI protobuf definition](https://github.com/bazelbuild/remote-apis/blob/main/build/bazel/remote/execution/v2/remote_execution.proto)

Materialize that root read-only, then give each attempt a private writable copy or copy-on-write mount. This allows `npm ci`, Cargo and test runners to write beside their sources while the user's worktree stays untouched. Collect declared outputs beneath the attempt root. Resolve every file operation relative to a granted root, reject escaping paths, and enforce file, byte and manifest limits. Export per-shard manifests so identically named reports from different shards remain addressable.

Use scoped authorization on blob upload, existence checks, downloads and log lookup. Knowing a digest grants no access. Partition cache indexes by tenant or local trust domain, repo, trust and compatibility inputs. Read-only consumers get disposable writable scratch. Trusted writers upload immutable blobs to staging. For cache-key contention across **different** valid jobs, publish immutable versions and conditionally update the key head against its expected generation. A valid lease for one job cannot override a concurrent writer's key generation. Keep optional cache misses and save failures distinguishable from loss of a required artifact.

## Attempts, authority and publication

The stable scheduling key is `(job_id, shard_index)`. Each claim creates a fresh `run_id` and increments the shard's persisted epoch exactly once. Store lease owner, expiry, attempt history and retry counters durably. Authority comes from the queue database's clock and transaction. Provisioning hosts, a guest heartbeat or an object-store grant alone conveys no right to publish.

| Event                              | Required atomic effect                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| ---------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Submit                             | Uniquely reserve `(principal, idempotency_key)` with a canonical request fingerprint. A replay of the same request returns the original job, including while snapshotting. A different request using that key conflicts. Persist the final snapshot digest before making shards eligible.                                                                                                                                                                           |
| Claim                              | From `Queued`, acquire an eligible slot and budget allowance, increment epoch, insert its attempt and set the active lease in one transaction or an equivalent fenced reservation protocol. A second claimant loses. Active phases are `Leased → Preparing → Running → Committing`.                                                                                                                                                                                 |
| Renew                              | Match principal, shard, run ID and **exact** current epoch in an active state before expiry. Propose a 5 s heartbeat and 30 s TTL remotely. For local trials use a 2 s heartbeat with a 10 s TTL. Clamp renewal to the run deadline. Expiry remains effective even before the sweeper observes it.                                                                                                                                                                  |
| Cancel, timeout, preempt or expire | Serialize against commit and renewal. Close authority, record the reason once and release the reservation. Signal the worker best-effort. A cancelled job forbids new claims. For a retryable outcome, requeue only within the applicable budget. A late preemption for the old run cannot close the replacement's lease.                                                                                                                                           |
| Stage                              | Upload immutable blobs under limited grants. Check lengths, digests, references, limits and required durability. Staged data has no public manifest pointer. Expire unreachable staging after a grace period that covers active uploads.                                                                                                                                                                                                                            |
| Commit                             | In one authoritative transaction check worker, shard, run, exact epoch, unexpired lease, active commit state, deadline and durable blob receipts. Publish the attempt result and manifest references, release its slot, and advance the shard or schedule a permitted retry. Enqueue idempotent usage and authorized cache promotions transactionally. Resolve the last shard into the aggregate result in the same transaction or through an idempotent finalizer. |
| Replay a commit                    | Return the stored receipt for the identical previously accepted request, including after loss of its acknowledgement. A different manifest for the same commit, a future epoch, an expired lease and an unseen stale commit all fail. Replaying a receipt cannot republish data or charge twice.                                                                                                                                                                    |

For cache promotion through an outbox, the successful commit binds a specific cache manifest, permission and expected key generation. The promoter consumes only that immutable authorization. Workers never receive credentials for writing public index pointers. Failed attempts may retain logs and declared diagnostic artifacts under their own attempt references. Promote shared caches only on an eligible committed outcome.

During a partition a worker can continue computing for a bounded offline grace period, buffer logs and stage blobs while its grants last. Only the authority can renew its lease. After reconnect, query the authoritative record. Publish buffered output only if the original lease is still valid, or retrieve a receipt for an already-accepted commit. Discard or garbage-collect fenced staging. Define and test this sequence in SQLite and Postgres.

At-least-once execution also applies on on-demand capacity. An external publish or deployment can succeed just before its worker disappears. Thegn cannot fence that remote system. For side-effecting work require `spot: forbidden`, disable automatic replay on failure **and** lost worker/preemption, and return an indeterminate outcome on ambiguous loss. For a repeatable final action, require an idempotency key honored at the destination, or a transactional external integration. Putting the action last in a shell script supplies neither guarantee.

For example, shard 3 of 8 starts as run A at epoch 7. Its worker uploads a report and disconnects before committing. After expiry, worker B claims shard 3 as run B at epoch 8 and commits a different report. A's late commit receives a fenced outcome. B can replay its accepted commit to recover the same receipt. The result lists two attempts, one selected report for shard 3, and the resource usage attributable to each attempt.

## Guest protocol and provider boundary

Frame protobuf messages with a fixed four-byte unsigned big-endian length and a negotiated maximum. Reject oversized or malformed frames before allocating the payload. Protocol and spec versions negotiate independently. Start with control and bounded, sequenced output streams. Transfer large files by scoped CAS reference. A slow log consumer must leave a path for heartbeats, cancellation and preemption.

| Exchange                               | Contract                                                                                                                                                                                                                                                                                     |
| -------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `Hello → Assign`                       | Negotiate overlapping protocol/spec versions, capabilities and limits. Authenticate the endpoints. Bind assignment to job, shard, run, exact epoch, snapshot and resolved environment. Supply only its file, cache and artifact grants. A reconnect is identified by its attempt and cursor. |
| `Exec → Output → Exit`                 | Run scripts or argv under the admitted workspace/env/PTY settings. Identify step, stream and offset so reconnects can deduplicate. Separate stdout and stderr for pipe mode. Bound buffers, report truncation or gaps, and preserve full log references where available.                     |
| `CacheRestore / CacheSave / Put / Get` | Validate granted roots, scope and digests, stream progress, verify received bytes. Retain verified immutable blobs after an interrupted transfer. Publish through the fenced commit.                                                                                                         |
| `Heartbeat / Preempt / Cancel`         | Carry attempt identity and epoch. A preemption deadline stops new steps. Finish any best-effort staging within the remaining grant. The node/operator reports reclaim directly so the queue can revoke immediately.                                                                          |
| `Result / Commit → Receipt`            | The guest supplies step outcomes, parser data, log and manifest references. The executor offers that evidence to the queue for one fenced commit. The queue computes final status, policy, placement and cost from trusted records. Stale guest output cannot become a job result.           |

Native provider traits expose describe/offerings, optional managed-host provision and lifecycle, and execution with a durable handle for watch, lookup, cancel and result. Use object-safe traits and the repository's boxed-future convention. Runtime isolation, service support and cache behavior are declared per offering. Use distinct managed and independent handles. A community provider receives only scoped HTTP/signing, KV, clock and log functions. A vendor command adapter must be able to identify a run after reconnect and enforce the same commit rules for capabilities it advertises.

## Result and compatibility fixtures

Every terminal `JobResult` carries a job ID, status/reason, shards and attempt histories, merged test summary, failures, compiler diagnostics, log tail and full log references, artifact manifests, phase timings, cache statistics, placement and cost. A rejected job can have zero attempts and includes its constraint report. An unavailable estimate is explicitly unknown. The compact MCP projection can omit large arrays while retaining counts, truncation flags and references.

| Result dimension      | Aggregation rule                                                                                                                                                                                                                                                                                                                                                                                                                   |
| --------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Status                | An accepted job cancel takes precedence while the job is open. Otherwise, on completion select indeterminate side effect, timeout, failure, then success in that order across terminal shards. Report exhausted infrastructure retries as `Failed` with an infrastructure reason. Retain each shard outcome, including preemptions. A later cancel cannot rewrite a finalized result.                                              |
| Tests and diagnostics | Aggregate the selected terminal attempt of each shard once. Keep earlier attempts inspectable. Dedupe reported failures by stable test identity, suite and location where available. Count flaky tests only with test-level evidence. Record incomplete or unreadable reports. Cap displayed failures and diagnostics (proposal: 50 each), bound excerpts by bytes, and redact brokered values from persisted logs where possible. |
| Outputs and timings   | Link artifacts by shard, relative path, digest, size and content type. Expose full logs and parser data by authorized reference. Bound the failing-step tail by lines and bytes. Report queue, placement, wake, sync, restore, steps, save and upload separately. Distinguish wall-clock completion from summed worker time.                                                                                                       |
| Accounting            | Keep per-attempt provider, pool, region, shape, isolation, spot class, exit and epoch. Sum actual usage across attempts and record attributed storage/egress and estimate provenance. Meter IDs are idempotent. Mark unavailable measurements explicitly.                                                                                                                                                                          |

Release one black-box runner with capability-specific fixtures. Run it against local, node, vendor and service adapters, as well as every eligible pool. The following cases gate a release.

1. A dirty tree with an executable file, deletion, ignored file and symlink gives the same root on two implementations. Changing a cached input changes the root. Writing output in the job leaves the original worktree byte-identical.
2. An unsupported feature fails before execution with a field or capability reason. If two eligible-capability subsets exist on different hosts, neither can satisfy their union. A weaker warm template, dedicated host or provider pin cannot bypass admission.
3. A duplicated submit creates one job. Two workers racing for a shard get one live lease between them. Pause worker A, expire it, run worker B at the next epoch and deliver A's result, cache save and heartbeat late. Only B's new publication is visible. Repeat with cancel racing commit, an unissued future epoch, and a lost commit acknowledgement.
4. Restore and save a trusted cache. Interrupt before manifest publication, then test read-only credentials, cross-tenant lookup, a prefix restore and two valid writers to the same key. Every visible manifest resolves to verified blobs.
5. Run the same sharded failing test through CLI and MCP, including a retried shard. Assert shard numbers, summary counts, capped output, step timing, separate infrastructure outcomes and cost deduplication. Test execution timeout, user cancellation and indeterminate external effects independently.
6. Exercise mixed guest versions, slow logs, reconnect from a cursor, a vanished node and a daemon restart during commit. On service pools, evict a pod and its replacement, remove the pool cache, then fetch the acknowledged result from outside that pool.

The v0 release gate is agreement on those observable outcomes across capable OSS providers and a published suite the service can run without checking out Thegn. The full REAPI execution frontend, workflow language and build-once/test-many DAG remain later extensions.
