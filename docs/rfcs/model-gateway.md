# Thegn model gateway

Architecture and delivery RFC · 18 November 2026 · Proposed for review

An individual running Claude Code and Codex in two Thegn worktrees should be able to answer “what did this branch cost?”, set one ceiling across both sessions, and see exactly where a request went. An automation author should eventually be able to run the same task across harnesses and compare the resulting changes. An enabled gateway uses the user's provider credentials. A stock, AI-disabled Thegn installation must continue to run independently of model traffic, accounts, pricing feeds and recording.

Git is the design and review record. Linear holds executable scope, dependencies and acceptance. The implementation baseline below is commit `6f37810b2`. Everything described as a target, gate, or phase is proposed. An accepted change to runtime behavior needs the appropriate OpenSpec delta and evidence under the delivery policy. [Linear initiative](https://linear.app/example/initiative/thegn-model-gateway-9da776fbc1bf) · [Delivery policy](../delivery-governance.md) · [Accepted model-proxy spec](../../openspec/specs/model-proxy/spec.md)

## 3. Boundaries and request lifecycle

The host owns worktree and session identity, harness launch, credential references and the gateway supervisor. The gateway owns ingress, policy decisions, provider I/O, admission and receipts. Pure types, route eligibility and pricing calculations fit in the existing core proxy module. Runtime adapters, sockets, secrets and SQLite transactions belong behind their existing substrate boundaries. UI and MCP clients consume authorized projections. Keep network I/O, catalogue refresh and exports off the shell event loop. The local admin channel uses an owner-only endpoint or equivalent authenticated control channel. A run-scoped bearer cannot mint keys or inspect another worktree.

| Step               | Input → output                                                     | Rule at the boundary                                                                                                                                                                                |
| ------------------ | ------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Accept             | connection → request ID, protocol, bounded raw entity              | Authenticate before expensive processing; bound headers, body, decompression, frames, time and concurrency. A request ID is generated locally. Never trust client-supplied identity headers.        |
| Identify           | virtual bearer → verified principal and scope                      | Validate signature, issuer, audience, expiry, key generation, session liveness and allowed route. Log a non-secret key ID. Add separately marked inferred annotations.                              |
| Evaluate policy    | principal + config generation → eligible providers and obligations | Clamp budgets, retention, allowed regions, models, disclosure and tool permissions. Refuse unknown mandatory terms. Capture the policy version at admission.                                        |
| Resolve and shape  | requested model + features → bounded candidate request             | Resolve alias/pin and select a compatible protocol. Decide raw forwarding, guarded mutation or translation. Count and price the **final** request. Recheck constraints after mutation or rerouting. |
| Schedule           | candidates → eligible lane and attempt                             | Queue by key/priority with a deadline. At dispatch recheck current revocations, circuit, rate permits and budget. Persist the attempt and its hold before sending.                                  |
| Dispatch and relay | attempt → provider events, downstream events                       | Exchange auth inside the provider adapter. Stream with bounded backpressure. Mark provider-dispatch uncertainty separately from downstream visibility.                                              |
| Close              | terminal event, loss or cancellation → receipt                     | Persist settlement or remaining exposure and release permits. Publish metadata with stable event IDs. Optional sinks consume independently under the recording policy.                              |

These are type and test boundaries within one process. Start with existing Rust seams and small functions. Add a trait when it has a second implementation or enables a wire/store test. The proposal for arbitrary WASM hooks at every stage would give plugins access to identity, secrets and partially settled state. A later extension contract supplies constrained views at selected stages. Authorization, budget commit, credential resolution and mandatory policy always have a trusted final check.

## 4. Principal, policy and credentials

A principal carries `tenant_id` (local default), profile, zone, repo ID, worktree ID, launch/session ID, harness and optional automation/run ID. Persist a branch-at-admission label alongside the stable worktree ID. Branches can move. Turn index and child span ID are optional. Sign only host-verified facts. Use a versioned claims envelope with issuer, audience, key ID, token ID, issued/expiry time and revocation generation. Expire on session end, impose an absolute maximum lifetime, renew only from an authenticated live launch, and allow bounded overlap when signing keys rotate. Store signing material under host control. Validate version and scope before dispatch. Recheck revocation before queued work starts. Separately authorize export, content inspection, key management and budget overrides.

Unmanaged harnesses may supply a user agent, provider headers or prompt features. A local, scoped keyed prefix fingerprint can suggest continuity when recording policy permits deriving it. Record provenance as verified, reported, inferred or unknown and allow correction. Hash keys and matching windows are tenant/profile scoped. Reject ambiguous parentage rather than assigning a charge to another session. Sub-agent spawns and auxiliary calls use explicit parent IDs from lifecycle hooks where possible. Link inferred activity in the viewer. Only verified bindings authorize access and budget ownership.

Aliases such as `smart`, `local` and `review` use preference precedence. Trust constraints intersect provider/model/region allowlists and take the tightest budget and least permissive content disclosure. Define explicit allowed recording capabilities (capture, redact, retain, export) so “full with redaction” cannot widen a no-content rule. A restrictive edit freezes new admissions immediately and can revoke active capability where specified. Ordinary reload lets streams finish on their admitted generation. Report applied and desired generations, drain deadline and failure reason without revealing tokens.

Provider keys begin as the supported `env:` and `file:` SecretRefs. Resolve inside the adapter process and replace downstream authorization headers on the upstream leg. Strip internal attribution and hop-by-hop headers. Extend broker resolution for OS keychain, 1Password/Bitwarden or cloud workload identity behind explicit capabilities. Credential checks use the least-cost supported metadata operation and report “unverified” where unavailable. Rotation uses two non-secret lane IDs, bounded overlap and revocation. Scope provider base URLs, redirects, DNS resolution and local discovery to approved endpoints. Secret references can select an account only within enclosing policy.

Sandbox egress must implement gateway-only model traffic for each qualified backend. Injecting a base URL is insufficient. Define whether the policy permits other internet access through separately governed destinations, and account for alternate model endpoints or tunneling before calling an allowlist enforced. Use a controlled local origin to demonstrate direct denial, authorized transit, a revoked key refusal and loss of gateway availability. Fail closed for a profile that requires enforcement. Label weaker backends accurately. The credential broker and network layer retain their existing authority.

## 5. Protocol design and wire compatibility

Treat ingress protocol, upstream protocol, operation and model features as independent dimensions. OpenAI-compatible Chat is one capability. Native Responses, conversational continuation, server tools and streamed usage each require their own qualification. Current Codex config documents `responses` for a custom provider's `wire_api`. Native Responses is therefore a v0 prerequisite for advertising Codex. [Codex config reference](https://developers.openai.com/codex/config-reference/)

| Operation                        | First supported path | Proof and failure semantics                                                                                                                                                                                                                  |
| -------------------------------- | -------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Anthropic Messages + stream      | v0 native            | Opaque signed thinking, redacted blocks, citations, cache markers, tool IDs, beta/version headers, errors and event order survive when supported. Delegate exact count_tokens to a compatible provider; label any local estimate explicitly. |
| OpenAI Chat Completions + stream | v0 native            | Preserve structured/tool fragments, multi-choice indices, usage-only final chunks and terminator. Qualify each compatible provider separately.                                                                                               |
| OpenAI Responses + stream        | v0 native            | Relay lifecycle events, item/content indices, streamed arguments, response IDs, terminal incomplete/failed states and compatible continuation. Pin a provider-native continuation to its authorized lane.                                    |
| Model discovery                  | v0                   | List only routes the caller may use. Distinguish virtual aliases, exact pins and provider model IDs. Return reasons for disabled or reserved adapters to authorized diagnostics.                                                             |
| Embeddings                       | extension gate       | Preserve dimensions, encoding, input ordering, token usage and batch-size limits. No chat transformation or text logging.                                                                                                                    |
| Provider batches                 | v2 async operation   | Durable submit, status, cancel and per-item fetch. A multi-turn agent waiting on a tool call cannot transparently become an overnight batch.                                                                                                 |
| Realtime, STT, image generation  | Later                | Require separate transport, lifetime, content/privacy and metering design. Binary streaming and interactive sessions have different failure boundaries.                                                                                      |

**Three execution modes.** Native raw mode keeps the original entity bytes and forwards upstream event data incrementally, with authorized transport/auth headers and a bounded passive usage observer. The provider must accept the exact requested model and fields. Native modified mode rewrites an alias, inserts a cache marker or applies redaction, preserves unknown siblings where safe, records changed fields and repeats validation and quoting. Cross-protocol mode decodes a typed envelope with ordered content blocks, tools, results, IDs, citations, multimodal references, thinking/signatures, cache annotations, native opaque fields and explicitly declared representability. Preserve original bytes where a fallback to native is allowed. A content transformation may be incompatible with a signed or opaque block. Refuse such a route before any upstream request. Do not equate entity fidelity with identical HTTP packet or SSE chunk boundaries.

**Feature-survival contract.** Publish a versioned table keyed by source operation, destination operation, provider/model capability revision, direction and streaming mode. Outcomes are preserved, emulated under listed preconditions, lossy with explicit consent, or unsupported. Unknown inputs on native raw paths are forwarded subject to policy; unknowns requiring cross-protocol interpretation are refused. A diagnostics command exposes the same table used by route admission. The route preview predicts the changed features, state locality and cache rebuild as an estimate. Review diagnostics and compatibility against pinned releases.

| Feature                                       | Native candidate                                                           | Cross-protocol decision                                                                                                                                                        |
| --------------------------------------------- | -------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Signed thinking or redacted thinking          | Preserve exact opaque payload and originating model constraints            | No synthesized signature. Block when a required signed turn cannot continue on the destination.                                                                                |
| Tool use/results                              | Preserve IDs, ordering, choice and argument bytes as the protocol requires | Map IDs and completion boundaries deterministically. Check parallel versus forced tool choice. Refuse ambiguous pairing.                                                       |
| Cache controls, citations, images, documents  | Preserve provider-native options                                           | Require a documented mapping for each content type, provenance and citation range. A cache hint may be dropped only under declared loss policy.                                |
| previous_response_id and provider-owned items | Bind to tenant, issuer, lane and expiry                                    | Emulate only where all required items and tool results are available with authorized retention. Missing, expired or inaccessible state returns an explicit continuation error. |

**Stream transducer.** Keep a small protocol crate or module with pure decoders, typed events and encoders; extract a crate when the test corpus and clients justify it. Track response creation, output/item/block opens, delta assembly, tool arguments, stops, terminal usage and terminal status. Partition by response/choice/item/block IDs. Parse SSE with incremental UTF-8 handling, comments, arbitrary TCP splits and bounded per-item buffers. Forward native data before upstream completion. Never execute tool arguments while incomplete. Downstream terminal signaling follows the selected protocol. On terminal absence mark the attempt incomplete and preserve uncertainty about charges. Closing the downstream stops local delivery and attempts upstream cancellation. Downstream backpressure and observer overflow cannot cause unbounded memory growth. [Responses stream events](https://developers.openai.com/api/reference/resources/responses/streaming-events) · [Anthropic streaming](https://platform.claude.com/docs/en/build-with-claude/streaming)

**Response state.** Namespace gateway-issued IDs by tenant/principal and store the minimum normalized input, output and tool history needed for a supported continuation, with parent pointer, policy generation, model and expiry. Authorize every lookup, enforce depth/size/TTL and handle deletion of ancestors. Native continuation uses an opaque upstream mapping or same-lane native ID with ownership validation. Provider storage and local retention have separate policy checks. In a no-content profile permit only compliant native continuity or require callers to supply history. A cache miss must never quietly begin a fresh conversation. [OpenAI conversation state](https://developers.openai.com/api/docs/guides/conversation-state/)

**Qualification corpus.** Build sanitized or synthetic fixtures for native HTTP bodies, SSE data and terminal outcomes. Pin harness and API versions, record fixture provenance and check unknown fields. Exercise every byte boundary, malformed/truncated frames, slow client, cancellation, multi-tool interleaving and terminal usage. A loopback upstream emits its first event, waits for the client to observe it, then releases the next. This proves real streaming without fragile millisecond assertions. An unsupported mapping must make zero network calls. Real-provider smoke is explicit, credentialed, spend-bounded and separate from hermetic CI.

## 6. Pricing, hard budgets and recovery

Define a **request** as one client operation, an **attempt** as one potentially billable upstream dispatch, and a **usage event** as one versioned observation or correction. Clients see one request outcome; the ledger can show several charged or unresolved attempts. A session is attribution, never an idempotency key. The guarantee is bounded authorized exposure across participating gateway writers under a known conservative tariff. Direct charges on unrelated clients sharing the provider credential are outside the observable balance. Show that limitation wherever a user sets a hard limit.

**Price book.** Version by effective time, provider, model revision, account-specific tariff, region and operation. Preserve currency, unit, source, retrieval time and completeness. Store integer minor accounting units with an explicit scale (proposed micro-USD for USD accounts) and checked rational multiplication. Round exposure up after combining exact components. Specify receipt rounding separately and retain raw counts. Keep signed adjustments as separate immutable events. Never silently mix currencies or reinterpret old rows under current prices. An upstream model list is discovery, not an authoritative tariff or retention guarantee. Keep a last-known version, show age and require a defensible upper bound for hard admission.

| Dimension                 | Normalization and evidence                                                                                                                                                                                                                                                                             |
| ------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Input/output              | Record total input/output and the provider's included subsets. Separate plain input, cache reads, cache creation by TTL, reasoning within billed output, and long-context tier. Validate counters prior to subtracting overlapping subsets.                                                            |
| Non-text and server tools | Per-operation price unit for images/embeddings, bounded server tool calls, search fees or other provider charges. For an unbounded operation, require provider-enforced limits and a defensible quote or disallow hard-budget dispatch.                                                                |
| Batch and BYOK            | Apply the contracted batch or account schedule once. Record list amount, actual provider amount when known, estimated amount with provenance, and billed amount (zero locally). Unknown actual is nullable. A measured subscription window is a separate observation.                                  |
| Example fixture           | With an invented tariff of 2 micro-USD/plain input token, 1/read token and 5/output token, 100 input tokens including 40 reads and 10 output tokens cost 210 micro-USD. A disjoint-input provider supplying 60 plain and 40 reads yields the same total. Add different 5-minute/1-hour write fixtures. |

**Ledger and identity.** Logical records are request, attempt, verified principal reference, tariff snapshot, budget scope/window, reservation allocation, provider receipt and usage adjustment. Give each attempt a unique local ID and optional scoped provider request ID. Keep an idempotency namespace per principal + operation and bind the key to a request digest. Duplicate keys with a different body conflict. Equivalent requests without an explicit supported idempotency contract can be distinct. Use tenant ID and schema version from the initial migration. Index time/scope for worktree queries and attempt/status for recovery. A single receipt may affect multiple scope counters, but there is one canonical charge. Exports join by event ID. Budget aggregates are projections with a rebuild check.

**Admission algorithm.**

1. Resolve mandatory policy, eligible route, tariff, actual transformed input bound, output ceiling, provider-enforced tool limits and applicable window keys. Token estimates used for UI are insufficient to prove a ceiling. If precision is unavailable, use an independently justified upper bound, require narrower limits, or return “unpriceable under this budget.”
2. Wait for scheduling capacity without a write lock. Open a short SQLite write transaction using the existing store boundary. Acquire the writer before reading limits. Preserve current global, zone, workspace, agent and worktree scopes and include profile, repo and automation constraints when configured. Deduplicate identical scope keys and evaluate all windows from one clock read. Propagate lookup or lock failure explicitly. Soft alerts and cheaper preferences cannot override an enclosing denial. [SQLite transactions](https://www.sqlite.org/lang_transaction.html)
3. For each currency/token dimension require settled usage plus outstanding exposure plus the new maximum to fit. Insert the attempt, hold and all scope allocations atomically. Commit before any provider I/O. A full queue, busy database or failed commit yields a bounded retry/refusal. Hard enforcement never treats storage failure as permission.
4. Durably mark dispatch intent before crossing the provider boundary. After intent, loss of the process or socket can leave delivery ambiguous. Another attempt, failover lane, hedge, server tool or batch item needs independent cover for its own maximum while previous exposure is outstanding. Acquire a new quote if lane, model, transformed input or tariff changed.
5. In a second transaction settle trustworthy terminal usage exactly once, book actual or evidenced estimate and release excess hold. Release an undispatched or demonstrably unbilled reservation once. For unknown usage retain exposure or conservatively account the upper bound with reconciliation status. Resume idempotently after restart and apply correcting receipts without negative double-release. Alert on a provider charge above its declared bound; record the true liability and suspend the unreliable hard-budget tariff.
6. Window policy must specify charge attribution. Proposed v0 charges an attempt to its admission window and retains the allocation against that window through settlement. Carry overlapping unresolved exposure forward when required by a rolling ceiling. Persist the policy version, clock timestamps and carry relationship. Rebuild after downtime or clock rollback without resetting a live hold. User-defined budgets/kill switches take effect before each new dispatch. An emergency active-stream cancellation may still incur cost.

**Crash and contention proof.** With 100,000 micro-USD left and 20 simultaneous 60,000 micro-USD quotes, at most one request may dispatch before settlement frees enough headroom. Test separate processes and connections. Kill the test worker at each boundary (before hold, after hold, after intent, after upstream accept, after usage, after settlement); replay the same receipt, move the clock across the window and race a kill switch. Verify the database, calls observed by the fake upstream, exposure reported to the user and permits released. Test route escalation to a more expensive model, partial streams, parent hard plus child soft, a failed store write, absent usage and cleanup after restart. Never infer a zero charge from client cancellation. Run the previous schema through the migration with real legacy-shaped rows and an AI-disabled launch.

**Budget UX.** Distinguish refusal, temporary unavailability, soft alert and an explicitly permitted downgrade. Include scope, window, permitted route and remaining headroom where authorized. Use protocol-compatible errors and stable Thegn reason codes. A downgrade is a new routing decision with a new quote and feature check. Notify once per threshold crossing and expose pending exposure alongside settled spend. Rate-of-spend forecasts show observation interval and assumptions. Cost per merged branch, test or automation uses verified run/outcome IDs, includes failed attempts and represents missing outcomes explicitly.

### Financial state visible to operators

| Attempt state           | Durable evidence                                                                | Permitted next action                                                                                         |
| ----------------------- | ------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------- |
| Reserved                | Local attempt ID, immutable quote, scope/window allocations, no dispatch intent | Start the authorized attempt or atomically release a proved-unsent reservation.                               |
| Dispatch intended       | Timestamp and provider/lane identity written before network I/O                 | Relay the request. After a crash, reconcile using a supported scoped provider lookup or retain exposure.      |
| Streaming               | Attempt ID, first upstream and downstream timestamps if observed                | Relay within limits. Stop local delivery on disconnect; retain liability until a trustworthy outcome.         |
| Terminal, usage known   | Scoped provider receipt, counters and tariff revision                           | Settle once. Record per-category rounding and release excess allocations in the same transaction.             |
| Terminal, usage unknown | Completion or transport reason and conservative outstanding amount              | Reconcile later or explicitly account the bound. An authorized correction has its own event and reason.       |
| Settled or released     | Unique finalization reference and balance projection version                    | Replay finalization idempotently. Add subsequent provider corrections without rewriting the original receipt. |

An operator query by attempt ID must explain the currently held amount, scopes/windows affected, last known provider state and evidence needed to release it. Expose that view without the request body. A quota or balance response from another client on the same upstream account is evidence about shared capacity, not proof that a particular local attempt was unbilled.

## 7. Catalog, routing and reliability

The registry stores a provider account/lane, concrete model/version, operation and capability set, context and output limits, data residency and retention evidence, price revision, allowed credentials and endpoint. Sync only configured providers through explicit policy; cache a local revision, surface source and staleness, permit validated local overrides and granular last-known values. Unknown retention fails a zone requiring a verified term. For a meta-provider, qualify and constrain the **ultimate** provider and region. If enforcement or reporting cannot be demonstrated, exclude it from that restricted route. [OpenRouter provider routing](https://openrouter.ai/docs/guides/routing/provider-selection)

Resolve explicit model pin or named alias, then existing model classes and deterministic auto-routing, respecting current precedence. Record requested alias, resolved revision and actual provider model separately. Exact pins reject replacements. A mid-session preview checks model-bound state, feature loss, context, new maximum cost and cache affinity. A switch affects subsequent admissions. Local models can have zero provider invoice cost while still having a separately attributed compute estimate. Default v0 BYOK qualification covers Anthropic, OpenAI, OpenRouter and configured Ollama, with an operation matrix per lane. An OpenAI-compatible local server can serve Chat without claiming Responses. Later, qualify AI Studio, Vertex, Bedrock, Azure OpenAI, DeepSeek, Mistral, xAI, Groq, Cerebras, Together and Fireworks by operation. Verify local vLLM, llama.cpp, LM Studio and MLX or explicitly authorized iroh hosts through opt-in discovery. Avoid scanning networks or starting paid probes by default.

| Signal                         | Routing decision                                                                                                                                                                                                | What the caller sees                                                                                 |
| ------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| Quota or 429                   | Honor documented retry/reset headers, deadline and per-key request/token buckets. Wait or choose an eligible alternative. Bound missing/malformed time hints.                                                   | A cancellable queue position or typed exhaustion result.                                             |
| Overload, 529 or transient 5xx | Update circuit/EWMA. Retry after bounded backoff with jitter only when replay and budget allow. Half-open with one controlled probe, then return to preferred eligible lane.                                    | One logical request; all attempts retain provider, outcome, latency and cost.                        |
| Authentication/billing/config  | Disable the affected lane where appropriate and notify its owner. Do not replay the same credentials. Keep content blocks/policy denials terminal.                                                              | Provider-safe reason with no credential or prompt disclosure.                                        |
| Context exceeded               | Check final transformed input and output headroom. Use an allowed larger-context alias only if privacy, state, pin and budget permit.                                                                           | Explicit rejection with measured/estimated size and limit if no route fits.                          |
| Disconnect or timeout          | Distinguish pre-dispatch, possibly delivered and first downstream body/event sent. No automatic retry after visible output. Before output, retry only if operation remains replay-safe and exposure is covered. | In-stream or transport terminal error as protocol permits, never a fabricated successful completion. |
| Hedge                          | Disabled by default. Consider only replay-safe work before downstream visibility, with a separate hold, no side-effecting tools or state creation and cancellation/accounting for the losing attempt.           | One winner and an auditable attempt tree.                                                            |

Use bounded per-key queues with separate interactive/automation classes, aging and per-principal fairness. Reserve rate permits just before dispatch; return unused predicted tokens from reliable usage. Shared provider limits can span model families or accounts, so record the provider's actual limit dimension. Handle missing headers conservatively. Sticky sessions prefer the last compatible endpoint under the same account and region; policy, hard constraints and health override stickiness. Record cache miss as observed, and any counterfactual cost estimate separately. Synthetic health checks are explicit and budgeted. Freeze candidate policy at admission and revalidate any fallback target. Track queue wait, first downstream event, completion, retry reason and timeouts by phase.

## 8. Recording, privacy, diagnostics and replay

Default accounting retains identifiers, verified scope, model/lane, result, token counts, charge provenance, timestamps and versions. A turn can link to a tool span without storing its arguments. Make the trace hierarchy workspace → worktree → session → turn → request → attempt/tool. Carry trace IDs across bounded asynchronous sinks. Keep cardinal identifiers out of default metric labels. Pin the version of OpenTelemetry GenAI attributes and allow content-bearing attributes only under the applicable export policy. [OpenTelemetry GenAI conventions](https://opentelemetry.io/docs/specs/semconv/gen-ai/)

| Recording choice           | Durable local data and available operations                                                                                                                                                                                         |
| -------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Off                        | Skip optional trace/transcript recording. When an enabled hard budget requires a minimal financial receipt, disclose that separately before enabling it. A policy forbidding even that receipt cannot offer durable hard budgeting. |
| Metadata (current default) | Spend, live request tail, session tree and operational metrics with opaque IDs. Replay of message content and prompt-prefix diagnostics requiring content are unavailable or explicitly partial.                                    |
| Redacted transcript        | Redact before persistence, hashing for deduplication, queuing export or writing temporary files. Store policy/redactor version. Replay the permitted representation and label redaction.                                            |
| Full transcript            | Explicit scoped opt-in with access checks, size cap and TTL. Encrypt sensitive blobs with scoped key custody, deduplicate only inside a permitted trust domain and prevent cross-domain equality disclosure.                        |

Use SQLite metadata plus scoped, compressed, content-addressed message blobs when recording is approved. Index references, lengths, schema and expiry separately. A garbage collector removes unreferenced blobs after transaction-safe reference updates, sweeps abandoned staging files and bounds local storage. Enforce deletion across transcript indexes, response-state ancestry, replay, response caches, fingerprints, export queues and backups per the documented retention window. Explicitly disclose already-delivered third-party exports. Gate read, export and delete independently. Apply the same content policy to errors, panic diagnostics, SSE debug, audit, metrics and notifications. Measure real deduplication and compression on an approved fixture corpus before making storage claims.

CLI projections extend the existing `thegn proxy` namespace. If `thegn llm` is added as an alias, both resolve the same commands and authorization. Launch includes `spend --by worktree --since 7d`, filterable `tail`, and diagnostics showing provider, credential resolution status, route, enforcement and gaps. Include stable JSON schemas and cursor-based time filtering. A slow tail reader drops or resumes events using cursor semantics without blocking dispatch. TUI per-tab cost, model, provider and queued state reuse the same query. Further panes show cache hits, token rate, session tree and switch preview. Admin HTTP/gRPC and MCP publish only registered authorized capabilities. Export OTLP, Prometheus and JSONL with explicit destinations, redaction, backpressure and retry limits; later add Parquet/DuckDB analysis and a qualified Langfuse integration when native mapping is needed.

Replay reconstructs a recorded turn, tools, costs and outcome. A fork copies the permitted context into a fresh isolated worktree and principal, resolves and quotes the proposed model, and treats future tool effects as new actions. Record inputs such as base commit and dirty snapshot, harness/model revision, generation parameters, tool policy and fixture outputs. Label nondeterministic model behavior and unavailable resources. Require explicit authorization to replay external side effects. A comparison uses the same task snapshot and rubric across N isolated trials, independent budgets, and a common deadline. Report tokens, cost, wait versus execution time, tests, diff size, mergeability, failure type and missing evidence. Save regression suites with input and grading versions and compare distributions where trials repeat.

### Control and error contracts

Group control operations by authority. A session may read its own status, usage, model and remaining budget. A worktree viewer can inspect its authorized session tree, tail and spend. A profile operator can change an alias, drain a lane or rotate a credential reference. Grant transcript reads, exports, issuer administration and money overrides separately. The CLI, HTTP/gRPC adapters and MCP front doors call the same authorized operations. Every list and cursor remains scoped after pagination.

Use stable machine reasons for invalid identity, denied scope, unsupported semantics, expired continuation, hard budget exceeded, unavailable accounting, deadline, provider rate limit and incomplete upstream stream. Encode them in the ingress protocol's error envelope. Preserve provider retry information when safe. An authentication error should never look like an exhausted budget. Before sending response headers, choose the appropriate HTTP status and retry hint. After headers, use a legal terminal event or terminate the transport and persist the incomplete outcome. The request ID in a client error must be enough for an authorized operator to find the attempt without exposing another principal's balance.

## 9. Content handling, tools and automation

Outbound scanning is an explicit policy stage. Reuse the credential scanner's rule IDs if available, bound text decoding and scan the final outbound representation, including tool results. An inspectable route may alert, redact or block. A strict scan requirement rejects opaque, binary or oversize content it cannot inspect. Redact before export and revalidate the transformed wire and quote. A redaction that invalidates signed data requires a different eligible route or refusal. Keep rule ID, count and position class as allowed; never echo the finding. Optional PII detectors live behind the same capability. Inspect completed inbound tool calls and prompt-injection indicators for user-facing signals. Tool execution and filesystem/network permissions remain with the harness and sandbox. A chained admin audit records policy changes, overrides, key issuance and alias edits with actor and generation. Define trusted checkpoints, verification, retention and recovery; possession of a local writable chain alone cannot prove resistance to rewriting its whole history.

Cache controls apply only on qualified providers. An opt-in modifier chooses stable tool/system-prefix breakpoints and the last eligible stable turn within provider limits. Compare authorized, scoped prefix fingerprints across turns; suggest the changed segment and show observed cache-read/write deltas. Distinguish an estimated avoidable cost from a measured charge. Automatic mutation records provenance and obeys signature constraints. An exact response cache is off by default. Require explicit allowance, a pinned model, compatible sampling, complete request/config/tool/schema digest, freshness and identical authorization/recording domains. Bypass mutable tools, stateful continuations and ambiguous nondeterminism. Cache hits get their own receipt; actual provider cost on a hit is zero. Context compression may strip ANSI, collapse repeated unchanged reads or summarize oversized tool results only under policy. Record transform version, before/after token estimates and fidelity limits. Reversal requires authorized originals; expose inability to reverse when retention forbids them. [Anthropic prompt caching](https://platform.claude.com/docs/en/build-with-claude/prompt-caching)

Automations have a principal per definition and a run/session per invocation, with inherited caps, policy, scheduling window, concurrency and priority. A deferrable item declares independent inputs and an async result contract. Persist submit intent, scoped idempotency IDs, provider batch ID, per-item status and receipts. Poll with bounded backoff, recover from restart, handle partial success, expiry, cancel and late results, and notify once per run. Retrying unresolved items requires separate exposure. Provider batch tariffs and eligibility are versioned. Interactive tool loops stay on synchronous transports. [OpenAI batch guide](https://developers.openai.com/api/docs/guides/batch/) · [Anthropic batch processing](https://platform.claude.com/docs/en/build-with-claude/batch-processing)

Use the existing MCP registry to expose tools to a harness. Authorize each list/call against principal, worktree and tool policy, with explicit disclosure of data sent to server-side search, fetch or code execution. Provider tools are separate capabilities with bounded charges and result provenance. A read-only agent self-check exposes its own model, context estimate, budget and outstanding holds. Provider-native and local tools share correlation IDs with the model attempt. Bill a provider fee once even if both the usage trailer and a tool event report it.
