# Design

The existing selected-config status classifier owns all eligibility decisions. A lazy probe callback is invoked only after source presence, trust approvals (including non-source pending requests), effective sandbox honorability, user-pinned source precedence, environment substitution restrictions, and refused/reserved/unknown fields settle. Hydration memoizes a demanded report within one build and uses a process-wide demand-only capability cache across builds. Doctor and launch queries remain uncached.

The cache retains one result, one generation token, and at most one synchronous producer. Waiters release the mutex into a bounded Condvar wait and recapture their own inputs after waking. Producer completion must match its admitted generation, the currently observed key, and freshly captured inputs. Invalidated owners retain custody until they finish; no replacement producer runs concurrently. An RAII reservation clears running ownership and wakes waiters on success, error or unwind. Poison invalidates cached authority while preserving active custody.

Keys include cwd, the full length-framed environment digest, lexical absolute executable path, pinned same-file identity, size and modification time. The actual probe receives exactly the captured cwd/environment via env_clear; cached state holds no environment values. Discovery runs again on every demanded access, so installing a previously absent helper, PATH/environment/cwd changes, and executable replacement invalidate immediately. Ready results expire after 30 seconds and degraded/unavailable results after 5 seconds, only on demand. No timer or refresh worker is introduced.

Owned key construction rejects more than 1024 environment entries, 64 KiB per entry, 256 KiB aggregate, 256 PATH directories or 16 KiB paths before sorting/hashing or choosing a truncated search. Standard-library environment snapshot allocation and OS filesystem scheduling are not hard realtime APIs. Identity opening is platform-owned: Unix nonblocking open follows executable symlinks and rejects nonregular descriptor metadata; Windows uses metadata-only access and the same regular-file requirement. This closes FIFO replacement blocking without claiming atomic executable attestation against hostile same-UID mutation. Restoring identical in-place metadata can remain undetected until demand TTL; this is diagnostic coherence, not launch authority.

The private bounded capture engine keeps the existing Git two-slot / 15-second / 2 MiB per stream and nonzero-refusal contract. A fixed capability lane has its own one-slot counter and retained reaper/queue, with a maximum of 2 seconds and 16 KiB per stream. Both use checked admission arithmetic and one deadline from before spawn through child and pipe completion. Capability returns full exit status/stdout/stderr, preserving provider nonzero-version behavior. Late pipe/child holders retain their lane capacity; a stuck capability reaper cannot block Git reaping. Existing devcontainer start/up run_bounded is outside this repair (THE-639).
