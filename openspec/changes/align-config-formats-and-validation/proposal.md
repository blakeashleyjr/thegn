# Settle the config format contract and close the validation blind spots

Linear: THE-38

## Contract established

THE-38 audited two questions: whether all configuration files accept JSON,
YAML, and TOML, and whether the examples are generated from code. The answer
is intentionally asymmetric.

The trusted layers — the main `config.toml` (including `--config`) and the
active profile's `profiles/<name>/config.toml` — are TOML-only. `--set` and
`THEGN_*` are value overlays, not document readers. The repo-root overlay is
the untrusted exception and accepts `.thegn.toml`, `.thegn.yaml`, `.thegn.yml`,
or `.thegn.json`, with TOML > YAML > YML > JSON precedence.

`config/config.toml.example` is hand-authored prose, not autogenerated. It is
protected by schema/example coverage, deserialization, and strict-validation
gates; the runtime `config-reference` page is generated from that example.
The reference therefore documents example values. It does not claim that
illustrative values equal `Config::default()`, and this change adds no noisy
defaults-accuracy gate.

## Gaps addressed

The branch already had repo tri-format parsing, profile loading, trust
clamping, home-manager drift checks, example coverage, and generated help-page
registration. The remaining audit gaps are the implemented code chunks:

1. `thegn-core` now exposes the format-neutral repo candidate/parser seam,
   path-only shadow discovery, and schema-driven repo-overlay diagnostics.
   The shared walker reports syntax, unknown-key/hint, type, and enum
   problems while preserving dynamic maps, legacy-key tolerance, and tolerant
   loading.
2. `thegn-host` now collects the selected main TOML, active profile TOML, and
   selected repo overlay. `config validate --repo <path>` prefixes findings
   with their owning file and fails for problems; `config get/set` carry the
   effective config path; doctor consumes the collector for text, JSON, and
   bundles without changing its diagnostic-only exit policy.
3. The architecture and help docs now state the trust-tier contract, actual
   repo tables, layer order, shadow warning, tolerant load, and explicit
   validation behavior. The in-flight OpenSpec delta below records those
   requirements without changing the canonical spec until archive time.

## Non-goals

- **JSON/YAML at trusted layers.** `config set` edits TOML with
  comment-preserving `toml_edit`; the example gate, runtime reference,
  home-manager module, and live reload are TOML-native. Adding trusted
  readers would multiply those paths for no demonstrated user need.
- **Autogenerating `config.toml.example`.** Curated prose plus schema/example
  coverage is the deliberate contract.
- **A defaults-accuracy gate for commented example values.** Example values
  are illustrative; a heuristic comparison would add noise and is deferred.
- **Trust-clamp semantics.** Existing repo trust resolution and clamping are
  untouched; this change documents the table set and validates the selected
  file without widening its authority.

  it is updated when this implemented change is ready to archive.
