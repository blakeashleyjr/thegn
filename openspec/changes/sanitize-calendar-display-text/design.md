# Display policy and sink inventory

`calendar::display::DisplayText` maps C0/C1 controls, whitespace, bidi override/isolation controls and invisible separators to a single separating ASCII space, then removes trailing/leading separators. ZWJ/ZWNJ and variation selectors remain supported for emoji/script shaping. Leading combining/zero-width characters are omitted so they cannot attach to an earlier terminal cell. Input work stops at 4096 scalars before unbounded allocation. Title/location/organizer have independent 256-scalar and 256-cell budgets; calendar/category/extension/clock labels 64; URL display 256; final composed reminder 512. Conservative scalar-width budgeting bounds retained output; the emitted string is measured with the same unicode-width version/model as host layout. Raw CalEvent fields are never modified.

Reachable sinks reviewed: agenda title/calendar cells, world-clock label/abbreviation cells, preferred popup width, and reminder title plus URL/location followed by a final message bound. Date/month/weekday headings are generated from typed date values, not provider strings. Weather headings remain under their separate ingress policy. Organizer/category/extension fields have no current calendar draw site; the public field policies provide independent budgets when projected. Raw URL remains semantic input and this patch adds no new URL exposure.

Config clock/account labels receive explicit advisory warning diagnostics, leaving legacy configuration admissible and sanitized at draw time. No blanket fatal rejection or raw label echo is introduced. The source ratchet covers existing agenda/clock/reminder seams; it is a narrowly enumerated guard, not a proof that arbitrary future string concatenation is safe.

Validation: actual pure display source harness 4 passed (controls, emoji/combining/wide characters, independent bounds, idempotence). Host fixtures cover all four provider model origins (ICS-backed inputs and command JSON) through clipped popup rendering, raw-value retention, reminder single-row limits and layout measurement. These are display-chain fixtures, not a claim that live HTTP/CalDAV/command transport has been exercised. Full host/core integration execution and independent review remain pending.
