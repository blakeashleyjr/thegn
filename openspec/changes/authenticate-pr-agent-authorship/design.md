# Design

`PrStatus.author` is optional descriptive cache data. The new optional `Forge::pr_authorship` operation returns non-serialized evidence containing stable author/viewer, repository and PR IDs, the head, state, provider and selected origin authority. One GraphQL request obtains author and viewer under the same CLI authentication; `--hostname`, owner, repository and PR number are explicit. The service ladder forwards the complete operation, never composing account and author from different layers. GraphQL partial errors, deleted/bot/malformed identities and unknown cache authors deny own-mode admission.

A shared host gate binds this proof to the selected execution location's origin, fetched PR URL/number/head, selected provider and current checkout HEAD. The selected PR number is an explicit input; a fetched status for another number is rejected before a proof request. The permit retains the selected checkout path, and final admission rereads persisted location metadata from the caller's DB. Authoritative no-record/local location is supported; DB errors, malformed metadata and nonlocal routes hold. Remote/provider proof cannot approve an agent runner that may still use a local shell; verified remote execution admission remains unavailable (THE-541/THE-550), without weakening own-only policy. The PR queue and CI autofix acquire proof before side effects and revalidate after floor/prompt preparation before spending a dispatch attempt or candidate claim. The durable review path uses the same gate and delays its revision CAS claim until preparation completes; all preclaim holds return diagnostics without changing a row that another owner may have revised or claimed. Existing post-agent verified-push/source/content revision checks remain, and a fresh matching author/account/repository/PR proof is required immediately before provider thread resolution. Only that verified-push path may advance the permitted head.

`own_prs_only = false` remains explicit authorization for the broader policy and performs no new identity queries. GitHub and configured GitHub Enterprise origins have a proof implementation. GitLab/Forgejo and ambiguous origin forms remain readable but own-only automation is held with a diagnostic; no URL-owner or login-only fallback is used. HTTPS, SCP-style git SSH and explicit ssh://git@host forms are supported without ports, URL credentials, query/fragment or extra path segments.

This closes an authorship check, not all automation authority races. External credential changes after the final check are not frozen (THE-541); broader durable queue ownership/checkout authority remains THE-550. The proof read uses the existing blocking GitHub CLI subprocess seam and inherits its lifecycle/timeout limitations. No live provider calls, agent dispatches, or review resolutions are used in validation.
