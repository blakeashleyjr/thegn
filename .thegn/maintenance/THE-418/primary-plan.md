## Chosen compatibility and execution policy

1. WarmDirenv default and shipped example become Off. Keep legacy auto/allowed-only parseable for compatibility but both resolve to disabled host warming with a bounded deprecation diagnostic. No mode may run host direnv or mutate/bless repository caches. Remove the actual subprocess/cache-blessing implementation rather than hide it behind a default. Remove unused warm bookkeeping and helpers; keep only a pure compatibility policy if needed.
2. Remove host warming from every listed startup/create/launch/materialize/prewarm/daemon path; simplify sync_warm plumbing. No .envrc evaluation, detached threads, subprocesses, or .direnv host writes from lifecycle. Public helper APIs that remain for compatibility must be inert and documented.
3. Remove all generated direnv allow commands, including target shell snippets and provisioning, because target HOME/allow DB may be shared and automatic approval is not necessary. Do not replace them with bypass env vars or silently approve on user's behalf. Retain ordinary target-side toolchain use only within a real resolved target; manual direnv approval in that target remains user's own operation. No new host approval mechanism is implemented, so closure-approval and evaluator timeout/cache-blessing requirements are satisfied by removing that evaluator, not claiming containment.
4. Remove auto Nix-daemon mounting keyed by warm_direnv. An explicit existing nix_daemon setting is separate trusted policy; don't broaden it. Avoid silently mounting socket after default-Off.
5. On degraded sandbox/provider resolution, refuse fallback to a host login shell when a sandbox was requested; surface an actionable existing launch error. Do not add a permission prompt or new config. A user deliberately selecting existing backend=None is explicit host execution with their own shell configuration; document that boundary accurately, and ensure Thegn never synthesizes direnv allow/exec for it. Automatic spare/layout prewarm must not launch bare-host rc hooks in a repository. Prefer no prewarm there. Test failure path really refuses instead of merely no direnv substring.
6. Adjacent Nix evaluation: stop implicit startup/launch prewarm of repository devShell on host and automatic DevShellClosurePush that invokes host nix develop --command true (can execute shellHook). Keep actual target-side build paths available. No wholesale THE-420 cache redesign; record remaining explicit Nix/cache concerns for that issue. Do not claim target confinement if fallback reroutes commands to host. Do not trust mtime cache as permission to resurrect host evaluation.
