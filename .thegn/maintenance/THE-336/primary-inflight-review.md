# Primary source observations while 507 is in progress

These observations are against the uncommitted working tree and require rechecking against your final commit. Do not assume this is approval. No extra build requested.

- DiagnosticsSender::publish currently pending.insert(key,pd) on the replacement check consumes pd for the new-key case, then attempts to insert pd again. Beyond compile ownership, inserting before budget eviction corrupts count/order/bytes and can leave orphan pending entries when refusing. Distinguish existing-entry replacement from new admission; reserve first, mutate exactly once, maintain count/bytes/order invariants.
- wait() only tests order nonempty. The run.rs bridge loops wait/wake; once ANY publication exists it busy-spins until host drain, and health-only changes never satisfy its condition. Use an atomic-under-lock wake obligation with explicit rearm/ack for partially drained work, health, and producer/consumer races. Idle means genuinely blocked, zero polling, QoS background/utility. Need deterministic wake-count/race tests.
- generation policy currently accepts unknown authorities (active.is_some() && mismatch); retired map sentinels never reclaim capacity. Revalidate registration on dequeue/apply because a queued old generation can survive close/reopen. Wire close/retire into actual worktree lifecycle, not dead-code test helpers. Retire matching generation only; old close must not retire newly opened client. Clear old generation store partition with health, preserve other servers. Bound/root-length-check active registry, pending keys, health metadata BEFORE clones. Numeric generation is not external authority.
- Queue fairness is global FIFO, not round-robin roots; reserve progress for quiet root under continuous hot-root updates. Evict flooding root deterministically. Dedup sequences must not allow stale replay after evicting history.
- Diagnostic projection collects up to512 owned strings FIRST, then applies256KiB byte cap. Preflight borrowed lengths and total before constructing each item; include root/server/key/bookkeeping and host panel duplicated file strings. Other projectors cloning before aggregate check need same correction.
- Truncated/invalid diagnostic publication currently looks like ordinary PublishedDiagnostics with no completeness marker. Store clears incomplete on any partial update. Add per-publication completeness and active-loss state cleared only by a complete current-generation resync/clear; sticky cumulative counters remain. Missing/wrong diagnostics type must never masquerade as complete empty clear.
- Host loop currently lacks2ms elapsed slice and counts only path/messagebytes. Use one common publication accounting and timer, one-publication overshoot, input preemption. Rebuild affected active partition once per slice.
- Add real fake-server flood/multiroot/retired-generation/clear and bounded memory accounting tests; current handful of constructor tests insufficient. No test pass claim without primary execution.

This corrupts accounting and can defeat queue byte limits. Only subtract bytes for entries actually removed. Ensure producer rejects stale and unknown before clones, receiver removes/decrements stale queued entries, and test conservation of bytes after repeated stale floods.
