## Production call path and prerequisites

1. `crates/thegn-host/src/cmd/merge.rs:547-588` implements `thegn merge
sweep [--force]`. It returns early unless `[merge_queue] on_landed =
"expire"`, then reports `SweepReport` decisions.
2. `crates/thegn-host/src/merge_sweep.rs:80-106` opens the DB, and
   `:126-239` selects landed rows for the repository/target, filters prior
   holds, applies TTL (or lets `force` ignore only the clock), and calls
   `merge_lifecycle::remove_landed_with_config`. A candidate must have a
   local/known location and a nonempty landed result OID.
3. `crates/thegn-host/src/merge_lifecycle.rs:316-518` validates queue
   identity, claims the physical path, calls `cleanup::Verified::probe`,
   validates resource ownership and queue/cache identity, then performs the
   final guarded removal and bookkeeping. A probe refusal becomes
   `CleanupOutcome::Refused`, which the sweep reports as `kept`.
4. `Verified::probe` at `merge_cleanup.rs:384-490` proves repository/worktree
   identity, branch/target refs and ancestry, linked-worktree metadata, and
   cleanliness before taking identity handles. `clean()` is called at line 465.
5. `clean()` at `merge_cleanup.rs:272-322` currently checks config before
   skip-worktree/assume-unchanged flags, submodules, and porcelain status.
   Its Git subprocess wrapper at `:184-218` bounds/captures output, disables
   hooks, fsmonitor, auto-maintenance and lazy fetch, and never logs config
   values.

`--force` therefore cannot clear this case: it changes due-row selection but
does not bypass `Verified::probe` or `clean()`. The minimum safe fixture also
needs a landed/eligible local worktree, matching branch and target identities,
no attached runtime/session ownership, and a clean index/worktree.

## Smallest complete fix

Change only the filter predicate in `clean()` and its focused tests, within the
coordination brief's scope (`merge_cleanup.rs` and its tests):

1. Remove the config-wide `git config --list` predicate.
2. Before the existing flags/submodule/status checks, run the data-only probe
   `git ls-files -z ':(attr:filter)'`. This asks Git for tracked paths in this
   worktree with a set `filter` attribute; it does not read file content or
   invoke clean/process/smudge drivers.
3. Preserve fail-closed behavior: a probe error remains an unsafe refusal; a
   nonempty NUL-delimited result refuses cleanup; an empty result proceeds to
   the unchanged existing checks.
4. Keep the existing safety intent and all other guards unchanged. On a
   nonempty result, report a bounded count or first few matched path names in
   the refusal, while never exposing filter command/config values. The reason
   should retain the explicit-cleanup/filter wording so callers still classify
   it as a filter safety refusal.

No sweep scheduling, TTL, `on_landed`, branch-retention, resource-admission, or
`landed commit identity is missing` behavior should change.

## Existing tests and required regressions

The fixture and isolation seam is in
`crates/thegn-host/src/merge_cleanup_tests.rs:126-200`:

- `TestIsolation` redirects global Git config to a temporary fixture file,
  disables system config and inherited config environment, and existing Git
  setup forces `commit.gpgsign=false` at lines 142-147.
- `Fixture::new()` creates a clean linked worktree with tracked `tracked` and
  `.gitignore` files.
- `hidden_index_modifications_and_filters_refuse_without_running_driver` at
  lines 247-273 already proves the existing skip-worktree/assume-unchanged
  refusal and that an assigned filter driver is not executed. It currently
  uses a local filter config and an uncommitted `.gitattributes`, and only
  checks the generic `filters` wording.
- Existing clean/probe/removal tests cover the ordinary attribute-free fixture,
  dirty/ignored/untracked content, submodules, special index flags, and
  physical removal. In particular, the successful removal test at lines
  370-384 is the no-filter/no-attribute baseline.

Add or revise focused tests in that module:

1. **Global/local config only, no attribute:** configure a harmless
   `filter.<name>.clean` and/or `.process` in the isolated fixture config,
   without any `.gitattributes`, and assert `clean()`/the fixture probe
   succeeds (ideally complete the existing removal path). Retain a canary to
   prove no driver was executed.
2. **Tracked path has `filter=lfs`:** use a fixture with a tracked path and a
   `.gitattributes` assignment, assert cleanup returns `Refusal::Unsafe`, and
   assert the reason names the matched path (or bounded path summary) while
   retaining filter/explicit-cleanup wording. Keep a driver canary absent.
3. **Empty/attribute-free repository:** retain an explicit successful clean or
   removal assertion with no filter config and no attributes, independent of
   the developer's Git configuration.
4. **Probe safety/error shape:** preserve the existing canary assertion and
   exercise that a failed `ls-files` probe is an unsafe refusal if the test
   seam can inject that failure without broadening scope. Do not replace the
   probe with `status`, `add`, or any content-touching operation.

All fixture commits/tags must continue to force `commit.gpgsign=false` and
`tag.gpgsign=false` as applicable; no test may inherit a developer's signing
configuration or real global filter commands.

## Failure cases to preserve

- A tracked path whose effective attributes set `filter` must still refuse;
  list only bounded path metadata, never driver command values.
- A configured driver with no applicable path must no longer refuse merely due
  to global/system configuration.
- An empty attribute result must still pass to the existing cleanliness checks.
- A failed or malformed filter probe must refuse conservatively.
- `skip-worktree` / `assume-unchanged`, submodules, dirty/ignored/untracked
  files, changed identities, locks, runtime ownership, and final revalidation
  remain refusals.
- `--force` still ignores only the grace-period clock.
- Missing landed commit identity remains the separate sweep reason and is out
  of scope.
