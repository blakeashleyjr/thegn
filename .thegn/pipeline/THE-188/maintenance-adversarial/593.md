`docs/ARCHITECTURE.md`, `.thegn/maintenance/issue.json`, and

## Findings

### 1. High — absolute windows are not reachable through the real Observe app

`crates/gtui-app/src/engine.rs:139-158` keeps the existing `TimeRange` spawn
boundary and unconditionally adapts it through
`relative_from_range` (`engine.rs:88-99`). The only `ObserveApp` constructor
uses that boundary (`crates/gtui-app/src/app.rs:47-67`), and its only window
setter sends `SetTimeRange` (`app.rs:103-106`), which again converts the range
to `QueryWindow::Relative` (`engine.rs:207-210`). The production tile creates
the initial range as “now minus 15 minutes” and adjusts it through that setter
(`crates/gtui-embed/src/embed.rs:67-90`).

Although `QueryWindow::Absolute` and `EngineCmd::SetWindow` exist, no actual
Observe app path calls them. A caller that supplies an absolute historical
`TimeRange` through the existing app API is silently changed into a duration
window and will drift on the next refresh, violating the historical
immutability criterion. Wire the typed `QueryWindow` through `ObserveApp` (or
provide a separate explicit historical constructor/setter) and add an
integration-boundary regression proving that path remains byte-identical.

### 2. Medium — config reload behavior is not implemented or explicitly

verified for Observe

`ObserveTile::new` snapshots dashboard, sources, initial window, and refresh
cadence once (`crates/gtui-embed/src/embed.rs:40-74`). The host config reload
branch updates general host state and assigns `current_config`
(`crates/thegn-host/src/run.rs:11502-11593`), but does not rebuild or send a
configuration command to the already-running Observe tile/engine. There is no
Observe-specific reload path in `ObserveApp` or `EngineCmd`. Consequently a
reload of Observe settings leaves the running dashboard and refresh cadence
unchanged, while the primary acceptance criteria require reload behavior to be
defined. Either implement a reload command that preserves the relative versus
absolute policy while replacing the configured duration, or document and test
that Observe configuration is intentionally snapshot-at-open and does not
apply until the tile is recreated.

### 3. Medium — regression tests bypass the spawned command/ticker path

The new tests call the private `query_all` directly (`crates/gtui-app/src/engine.rs:416-417,
448-449, 472, 494-496, 523-527`) and use test-only `pause`/`resume` helpers
(`engine.rs:300-308`). They do not exercise `run`'s `tokio::select!`, the
scheduled-tick suppression branch, `EngineCmd::SetWindow`, or the public
`EngineCmd::Pause`/`Resume` handling (`engine.rs:193-219`). A future wiring or
race regression in the real task can therefore pass all current tests. Add a
fake-clock, recording-source test around the spawned task/command channel (or
factor the command transition into a directly tested pure method) covering
pause, resume, absolute `SetWindow`, and at least one scheduled refresh.

## Positive checks

- The relative resolver samples the clock once before panel iteration
  (`engine.rs:230-244`) and clones the same range for every target.
- The absolute resolver does not call the clock (`engine.rs:263-266`), and
  repeated direct resolution is covered by the existing absolute test.
- Backward-clock resolution clamps the relative end and now also asserts that
  the configured duration remains one minute (`engine.rs:480-507`).
- No new production-side unbounded collection or blocking I/O was introduced
  by this change. Existing unbounded channels remain outside this review's
  change surface; no stress run was performed.
