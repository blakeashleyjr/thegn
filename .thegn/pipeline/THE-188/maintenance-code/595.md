# THE-188 implementation — native dispatch row 595

verdict: implementation-ready

## Scope

Implemented the primary revision in `crates/gtui-app/src/engine.rs` only. No
host-loop, datasource, configuration-reload owner, or unrelated changes were
made.

## Changes

- Removed the unreachable `QueryWindow::Absolute` / `AbsoluteWindow` surface
  and `EngineCmd::SetWindow`. No product caller can currently supply a
  historical Observe range; every Observe construction and adjustment path is
  live/relative. This uses the primary's approved remove option rather than
  retaining a variant that no real path can construct.
- Kept a dedicated `RelativeWindow` duration. Each refresh samples the
  injectable clock once, preserves the configured duration, and clamps a
  backwards wall-clock sample to the previous resolved end.
- Kept pause/resume semantics in the engine: pause freezes the last resolved
  range and suppresses scheduled refreshes; resume resolves from the clock and
  queries immediately.
- Documented at the window boundary that config reload does not retarget a live
  Observe tile; new config applies to the next tile. Live reconfiguration is a
  THE-407 follow-up requiring its own generation/cancellation contract.

## Regression coverage

The tests now spawn the real `QueryEngine::run` task and receive updates from
the actual ticker/command path. They cover:

- successive ticker refreshes advancing while preserving duration;
- a fake clock moving backwards without inverting or regressing the range;
- one resolved range shared by all panels in a refresh;
- pause, paused requery, and resume behavior through `EngineCmd`; and
- conversion of the app's configured `TimeRange` into a duration without
  retaining its construction-time end.

The approved absolute-historical acceptance is explicitly scoped out by the
remove option above: the current product has no historical-range caller, so
there is no absolute behavior to preserve or test until such a caller exists.
