# THE-188 implementation — native dispatch row 582

verdict: implementation-ready

## Scope

Implemented the primary-approved engine-only plan in
`crates/gtui-app/src/engine.rs`. No changes were made to `gtui-core`,
`gtui-query`, the host loop, app/embed callers, or unrelated features.

## Changes

- Added distinct `RelativeWindow`, `AbsoluteWindow`, and `QueryWindow` types.
- Added an injectable `Clock`; production uses `Utc::now`, while tests use a
  queued fake clock.
- Relative windows resolve one `now` at the start of each refresh, preserve the
  configured duration, and clamp backward wall-clock movement to the previous
  resolved end.
- Absolute windows are copied unchanged and never consult the clock.
- Kept the existing `TimeRange` constructor/setter boundary source-compatible;
  it is adapted as a live duration. Explicit historical callers can use
  `spawn_with_window` and `EngineCmd::SetWindow(QueryWindow::absolute(...))`.
- Added pause/resume engine commands. Paused relative queries reuse the last
  resolved range and scheduled ticks are suppressed; resume re-queries from the
  current clock. The existing app has no user-facing pause/reload action, so no
  new key or config surface was added.

## Regression coverage

The engine test module records datasource queries without network I/O and covers
successive relative advancement with equal duration, absolute immutability and
clock non-use, one range shared by all panels in a cycle, backward-clock
clamping, and pause/resume behavior.
