## Findings fixed during review

1. The pure locale resolver accepted only BCP-47 syntax for `LC_ALL` and
   `LANG`. Common POSIX values such as `ja_JP.UTF-8` therefore degraded to
   `en-US`, silently defeating automatic Japanese selection. The removed
   `sys-locale` dependency had performed this normalization. Commit
   `8fc3758d` restores POSIX-to-BCP-47 normalization at the pure environment
   boundary and covers both precedence inputs, encodings, and modifiers.
2. The strict parity registry could drift from the locale directories embedded
   by `static_loader!`: adding a catalog directory without adding it to
   `SHIPPED_LOCALES` would ship an un-gated locale. Commit `8fc3758d` adds a
   loader-versus-registry equality test so every embedded locale participates
   in strict parity checks.

## Adversarial audit

- Locale selection remains a startup-only, thread-safe `OnceCell` value with
  explicit config -> `LC_ALL` -> `LANG` -> `en-US` precedence. The e2e freeze
  beats both environment inputs and the developer pseudolocale.
- Locale inputs are parsed as data; catalogs remain compile-time embedded.
  This change introduces no runtime path traversal, file permission surface,
  command construction, network access, or mutable reload race.
- Fluent interpolation keeps user folder/workspace data as argument values;
  it is not reparsed as catalog syntax. Capability glyph selection remains at
  the existing `caps` seam.
- Shipped key parity, action-id/message-key uniqueness, unknown-action
  degradation, pseudolocale placeholder preservation, translated cell-width
  fitting, and generated English help boundaries are covered by tests.
- The i18n literal debt ledger remains shrink-only and clean with its five
  intentional file pins. No config/env-overlay, help, completion, control
  schema, or unrelated ratchet was widened.
