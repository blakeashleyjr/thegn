verdict: implementation-ready

## Implemented

- Made `sandbox.warm_direnv` default to `off`; retained `auto` and `allowed-only` parsing as inert compatibility values with bounded deprecation diagnostics.
- Removed host `direnv` subprocesses, approval, detached warming, mtime checks, cache blessing, and lifecycle warm calls across startup, create, materialize, launch, split, daemon, and respawn paths.
- Retained only inert compatibility wrappers and pure policy/cache-read seams; cold devShell cache reads no longer start host `nix print-dev-env` evaluation or write cache entries.
- Removed automatic Nix-daemon mounting keyed to repository warming; explicit `nix_daemon = true` remains the separate trusted policy.
- Removed generated `direnv allow` steps and shell snippets, the host `DevShellClosurePush` plan/executor, and its host Nix/cache helpers. Target-side `direnv exec`/Nix provisioning remains available.
- Changed sandbox/provider fallback so an unavailable requested sandbox returns the existing actionable `SandboxHalt`; host execution is allowed only for local disabled/`backend = "none"` policy or the existing explicit run-on-host choice.
- Updated config examples, comments, OpenSpec wording, and workspace documentation to describe disabled host warming and explicit target-side setup.

## Regression coverage added or updated

- Core warm policy: all legacy modes are inert; default is `off`.
- Config validation: legacy warm modes are warnings, not validation errors.
- Environment plans: no host devShell push, no generated `direnv_allow`, and no generated `direnv allow` command even when legacy push/skip settings are supplied.
- Host shell snippet: generated target shell never emits `direnv allow`.
- Host fallback policy: requested local sandbox resolution does not authorize an implicit host fallback; explicit host/disabled cases remain allowed.
