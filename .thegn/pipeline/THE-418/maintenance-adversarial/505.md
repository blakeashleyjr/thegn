## Findings

### F-01 — revisions-needed, high: skipped prewarm attach bypasses stale tab identity

Locations: `crates/thegn-host/src/handlers/provision.rs:496-515` and `:546-555`; attach helper `:385-420`.

`drain_specs` validates the captured tab's pane identity only when `specs` is `Ok(...)`. A `SpecError::PrewarmSkipped` has no resolved leaf vector, so the `Err` path proceeds directly to `attach_prewarm_sessions(ctx, gi, ti, batch_attach)`. That helper trusts the old `(group, tab index)` and calls `graft_surplus` without checking that the tab still contains the captured leaves or an equivalent generation/token.

Reproducer: capture a prewarm for tab index 1, close tab 0, then deliver `Err(PrewarmSkipped)` with a live daemon attach target. Index 1 now names a different live tab; the delayed result grafts the daemon session there, sets dirty/relayout, and changes the wrong tab. The new test at `provision.rs:1071-1183` records the expected invariant and should currently fail against this source.

Required correction: carry stable target identity (the captured leaf set or a tab generation) on every `SpecBatch`, including skipped results, and perform the same stale check before any attach or bookkeeping mutation. A stale skipped batch must settle its own inflight state but must not attach, mark dirty, or relayout the surviving tab. Keep a focused test for both skipped-with-attach and skipped-without-attach cases.

### F-02 — revisions-needed, medium: detached prewarm workers can outlive tab state and multiply under churn

Locations: `crates/thegn-host/src/run.rs:8577-8600`, `:8600-8695`; tab cleanup `crates/thegn-host/src/handlers/tab_keys.rs:123-130`.

Each eligible prewarm inserts `(group, tab)` into `prewarm_inflight` and then discards the `spawn_blocking` handle. Closing a tab removes or shifts that key, but does not cancel or join the worker. A long provider/direnv/daemon-probe operation therefore continues after its tab is gone. A replacement tab at the same index can schedule another worker while the old one is still running. Repeated close/reopen or worktree churn can accumulate blocking tasks and duplicate probes; a worker panic or send failure also has no completion message to clear its inflight state.

This is also the source of delayed stale results that make F-01 exploitable. The acceptance criteria require bounded behavior and cancellation/failure handling for automatic paths. Add a generation/cancellation token and bounded worker accounting (or retain and manage join handles); reject results whose generation is no longer current, and ensure spawn/panic/send failure releases the reservation. Add a churn test that closes/reopens the target while a worker is held at a deterministic test barrier and verifies no second worker is admitted and no late attach is applied.

### F-03 — revisions-needed, medium: the new executable prewarm test still bypasses the production worker route

Location: `crates/thegn-host/src/agent_tests.rs:196-368`.

`automatic_prewarm_drains_host_result_without_spawning_or_evaluating` resolves through `launch_spec_synced_with`, manually calls `apply_relaunch`, manually calls `reject_host_prewarm`, constructs a `SpecBatch`, and invokes `drain_specs`. It does not execute `prewarm_requests`, the `spawn_blocking` worker in `run.rs:8577-8695`, or a production `Panes::spawn_argv_env` boundary. Consequently, removing or misrouting either of the two `reject_host_prewarm` calls in the automatic worker would still leave this test green: the test itself manufactures `PrewarmSkipped` before draining. The fake shell/direnv/nix executables are also only sentinel inputs; this test has no positive-control launch proving that the production route would have executed them if an unsafe host launch slipped through.

The attach test added in `handlers/provision.rs:967-1064` does exercise the real drain/graft route and checks bookkeeping, dirty, and relayout, but it likewise starts from a handcrafted batch. Preserve the narrow test-only daemon effect seam, while adding a non-masking test seam at the actual automatic-worker boundary (or an equivalent callable worker function) so the test invokes the real `SpecOrigin::Prewarm` routing, both rejection points, and the no-host-spawn result. Keep explicit focused materialize/host behavior as a separate positive control.
