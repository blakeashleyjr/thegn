# THE-505 adversarial source review

verdict: revisions-needed
dispatch: 493
scope: complete current delta from 0be575ce, with chunks 1–2 reviewed against the full issue acceptance criteria and primary instructions

## Outcome

The pure core admission function is substantially bounded and fail-closed when a caller supplies already-captured inputs, but it is not an executable configuration boundary yet. Authority-bearing runtime paths still use the legacy tolerant loaders, and the generation/reload/profile/source/provider work required by the issue is absent. This review cannot be source-review-clear.

## Findings

### Blocker — authority-bearing consumers bypass admission and still fall back to defaults

Evidence:

- `crates/thegn-core/src/config_admission.rs:3-7` explicitly says capture and host wiring are deferred, while `admit` is only the standalone API at `:402-606`.
- `crates/thegn-core/src/config.rs:6066-6085` retains `Config::load_layered`, which maps every load error to `Config::default()` and reapplies env/CLI values.
- Startup and CLI command paths call that fallback at `crates/thegn-host/src/run.rs:617-621` and `crates/thegn-host/src/main.rs:984-988,1139-1143` before DB-host merging and authority setup.
- Hydration still calls `try_load_layered(...).unwrap_or_default()` at `crates/thegn-host/src/hydrate.rs:4041-4050`; daemon refresh uses `try_load_layered` at `crates/thegn-host/src/config_source.rs:37-49`; teardown/provider cleanup independently uses `load_layered` at `crates/thegn-host/src/agent_teardown.rs:11-18` and `crates/thegn-host/src/agent.rs:1020-1023,3021-3031`.

An existing malformed, unreadable, invalid-UTF-8, oversized, or semantically invalid file can therefore still launch or drive authority-bearing behavior with defaults, depending on the route. This directly fails the first, third, and fourth acceptance criteria. The new API cannot protect a caller that never invokes it.

Required follow-up: migrate all authority-bearing startup, CLI, daemon, hydration, standalone, and teardown consumers to one captured admitted snapshot; retain legacy loading only for explicitly non-authority projections and remove the fallback once migration is complete.

### Blocker — no live snapshot store, reload health, CAS, or generation fence exists

`AdmittedConfig` always constructs `ConfigRevision { generation: 0, ... }` at `crates/thegn-core/src/config_admission.rs:591-600`. There is no publication/store API in the current delta. The intended generation/reload tests are disabled with `#[cfg(any())]` at `crates/thegn-core/src/config_admission_tests.rs:786-910`.

The live reload path instead sends `Result<Config, String>` through an unbounded channel (`crates/thegn-host/src/run.rs:920-923`), loads through the legacy parser (`:961-970`), and immediately installs the resulting config at `:11456-11608`. It carries no source identity, admitted revision, failure epoch, or compare-and-swap check. A semantically invalid-but-deserializable reload can be accepted, and a stale reload or concurrent DB-host/config change has no authority-boundary recheck. A parse failure leaves the old UI config in place, but does not produce the required typed degraded health or invalidate new authority operations.

This fails the reload, concurrency, stale-generation, and authority-publication criteria. Full Rust validation remains pending, but source inspection is sufficient to establish that the required mechanism is not present.

### High — `config explain` is a divergent, fail-open loader

`crates/thegn-core/src/config_resolve.rs:1410-1475` reparses the raw base file with an unbounded `read_to_string`, converts parse/read failure to empty/default state (`:1425-1436`), silently skips profile read/apply errors (`:1438-1443`), reapplies env/CLI through tolerant helpers (`:1445-1454`), and computes a separate trace. It does not consume `AdmittedConfig`, its normalization version, source identities, diagnostics, generation, or final host snapshot.

Thus explanation can report Builtin/default after a hidden parse failure and can disagree with runtime layering. This fails the exact explain-trace and parity criteria and remains exploitable as misleading operator evidence.

### High — source/profile identity is caller-asserted, not captured or bound

`SourceInput` accepts an arbitrary `&str` identity and borrowed bytes at `crates/thegn-core/src/config_admission.rs:23-38`; `AdmissionInputs` accepts an optional profile independently of the selected profile/environment at `:96-107`. The pure function bounds the identity string but cannot prove it names the file whose bytes were read, cannot capture filesystem metadata/rename/symlink state, and cannot ensure that the supplied profile is the selected profile overlay.

The production capture seams that would establish those relationships do not exist in this delta. The legacy path still obtains the profile from ambient env and then reads/merges DB hosts in separate operations (`crates/thegn-core/src/config.rs:6035-6047`; `crates/thegn-host/src/main.rs:1139-1174`). A caller can therefore compose a profile-labelled or host-augmented config from mismatched source generations. This fails the selected-profile, exact-source-identity, and mixed-snapshot criteria; cross-platform capture and fault-injection coverage are also still pending.

### High — provider settings are still admitted only at side-effect time

No provider-admission code changed in this delta. The existing bypasses remain:

- `crates/thegn-svc/src/fly/machines.rs:87-102` maps every unknown size preset to `shared-cpu-1x`.
- `crates/thegn-svc/src/fly/mod.rs:242-270,537-621` can create an app and allocate a billed IPv4 before the complete region/image/size/org specification is proven.
- `crates/thegn-svc/src/vps/mod.rs:719-762` calls `ensure_ssh_key` before the configured region/size/image/name is validated by the provider.

The issue requires local typed provider grammar and zero remote requests for one-unit-invalid values, with preflight bound to the admitted revision. The current core admission does not validate these provider specs, so this acceptance remains unmet and is a direct remote-resource/billing bypass.

### Medium — compatibility diagnostics are count-bounded but not byte-bounded before retention

`crates/thegn-core/src/config_compat.rs:264-268` caps only the number of diagnostics. `normalize_project_tables` formats long user-controlled workspace slugs into each diagnostic at `:184-200` before that count cap is applied. The admission layer only redacts/truncates after normalization at `crates/thegn-core/src/config_admission.rs:721-725,1105-1122`.

A source within the scanner work budget can produce 256 very large compatibility strings, causing substantial amplification before the diagnostic projection is bounded. The added regression at `crates/thegn-core/src/config_admission_tests.rs:933-957` asserts per-message and aggregate byte bounds; it is intentionally unverified here and is expected to expose this finding until the producer itself bounds message storage.
