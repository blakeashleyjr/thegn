## Scope implemented

- Made `AppsConfig::BUILTIN_TABS` the core-owned catalog for `work` and
  `observe`. The generated JSON schema uses those IDs, and the host registry
  test requires every non-work catalog ID to have a builder on the target.
- Strict config validation now rejects unknown IDs with the supplied ID and
  known-ID list, and rejects a default `observe` tab unless `[observe]` is
  enabled. Duplicate order entries are accepted and normalized by retaining
  their first occurrence. File, environment, and `--set` values continue
  through the same resolver.
- `AppHost::reconcile` keeps slot and tile state by stable ID, changes the
  active tab when the configured default changes, falls back to that default
  when the active app is removed, and returns early for unchanged app-tab
  configuration. The only `run.rs` change is in `event_loop`'s successful
  config-reload branch: reconcile the tabs, lazily load the selected app, and
  rely on the existing dirty/relayout path for a full chrome redraw.
- Callback indices remain wake signals only; the event loop drains them and
  pumps the current slot set. Dropping a removed Observe tile drops its engine
  command sender, which ends its query loop after any in-flight query settles.
- Updated the example config and added regressions for schema IDs, unknown and
  disabled defaults, duplicate normalization, environment and CLI overlays,
  configured Observe order/default, live enable/disable/reorder/default
  reconciliation, stable slot state, and idempotent reload.
