## Finding

### F1 — P2: `cfg_attr` walker scans emitted attribute arguments as predicates

Locations: `crates/thegn-core/src/test_support/ratchet.rs:437-440` and
`crates/thegn-core/src/test_support/ratchet.rs:385-404`, with the identical
logic in the media and metrics copies.

`cfg_attr` has one cfg predicate argument followed by one or more attributes.
`has_platform_cfg` dispatches both `cfg` and `cfg_attr` to `predicate()` without
distinguishing those forms, and `predicate()` recursively walks every
comma-separated sibling. Consequently, a platform-looking identifier in an
emitted attribute is reported as a platform conditional even when the
predicate itself is feature-only. For example:

```rust
#[cfg_attr(feature = "x", derive(target_os))]
```

The first `feature` leaf is false, but the recursive walk enters `derive(...)`
and treats its `target_os` argument as a platform leaf. This is a ratchet
false positive: it can force an unrelated source file into a platform
allowlist and weakens the scanner's syntactic fidelity. The fix should parse
the first `cfg_attr` argument as the predicate and ignore ordinary emitted
attribute payloads (while retaining any deliberate handling of an emitted
`cfg` attribute, if that is part of the contract).

I added the direct regression
`platform_cfg_detection_walks_complete_predicates` at
`crates/thegn-core/src/test_support/ratchet.rs:554-556` and copied it
byte-for-byte into the media and metrics helpers. It is expected to fail on
the current implementation until F1 is fixed.
