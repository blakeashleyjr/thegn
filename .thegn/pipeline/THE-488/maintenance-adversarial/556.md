## Finding

### F1 — P1: a symlinked `src/` root still escapes the scanner

Locations: `crates/thegn-core/src/test_support/ratchet.rs:187-189`, with the
same logic in `crates/thegn-media/src/ratchet.rs:187-189` and
`crates/thegn-metrics/src/ratchet.rs:187-189`.

`sources_with` passes `manifest_dir/src` directly to `collect_paths`, while
the new symlink check is only performed for entries inside a directory at
`collect_paths:153-162`. If the crate's `src` directory itself is a symlink,
the initial `read_dir` follows it and every external `.rs` file is admitted
and read by path. That bypasses the fail-closed symlink requirement and can
make a ratchet scan an external or unexpectedly large tree. The added
`symlinked_source_entries_fail_closed_without_recursing` regression does not
cover this root case.

This review adds
`symlinked_source_root_fails_closed_without_external_traversal` to all three
identical helper copies at `:807-824`; it is expected to fail until the
implementation checks the source root with `symlink_metadata` (or equivalent)
before the first `read_dir` and reports the root path as a refused symlink.
