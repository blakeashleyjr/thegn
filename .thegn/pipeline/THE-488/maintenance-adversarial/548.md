## Findings

### F1 — P1: an empty allowlist still passes closed scans

Location: `crates/thegn-core/src/test_support/ratchet.rs:61-75` and `:439-456` (the same lines in the media and metrics copies).

`read_allowlist` filters an empty or comment-only file to an empty set, and `file_ratchet_with` only compares set differences. Therefore a missing file fails, but an existing empty allowlist returns `Ok(())` when the current scan finds no hits. This directly violates the primary instruction and issue requirement that a missing/empty allowlist is an error rather than “no pins”; it permits a deleted/truncated allowlist to silently reset a ratchet that currently has no debt.

I added `empty_allowlist_fails_closed_even_when_no_file_hits` at `:691-711` in all three identical helper copies. It is intentionally a failing regression until the implementation rejects empty/comment-only allowlists with the allowlist path in the error.

### F2 — P1: directory symlinks can recurse without a bound

Location: `crates/thegn-core/src/test_support/ratchet.rs:122-127` (same in media/metrics).

`collect_paths` calls `metadata`, which follows symlinks, and recursively descends whenever `is_dir()` is true. A repository-controlled `src/loop -> src` symlink can therefore recurse until stack/resource exhaustion; a symlink to a large external directory can make the ratchet scan outside the source tree and grow the path/body collections without a repository-size bound. This is a denial-of-service/resource-growth path in the test ratchet and is not covered by the injected I/O tests.

Use symlink-aware metadata and refuse or explicitly handle symlink entries before recursion, or track visited directory identities and fail closed on cycles. Add a deterministic symlink-loop/external-target regression on supported platforms (and a non-Unix skip/portable equivalent if symlink creation is unavailable).

### F3 — P2: traversal is path-based and has a metadata/read TOCTOU race

Locations: `crates/thegn-core/src/test_support/ratchet.rs:116-131` and `:150-162` (same in media/metrics).

The scan lists a path, checks its metadata, stores it, and reads it later by name. A concurrent rename/replace can change the object between those operations, so the ratchet can inspect a different file than the one it admitted, follow a newly introduced symlink, or miss a source mutation without any error. This weakens the fail-closed claim under concurrent checkout/generation activity. The current seam tests injected failures but do not exercise replacement between metadata and source read.

Either establish a stable source-tree snapshot/lock for ratchet execution, or use a symlink-safe opened-file/directory-handle strategy with identity revalidation and fail closed when the object changes. Add a deterministic seam test that changes the identity between metadata and read and asserts an error.
