## Smallest complete fix

1. Keep the three helpers duplicated, as the primary coordination brief
   requires. Implement the same small hand-rolled lexer/predicate-tree walker
   byte-for-byte in all three copies; do not add a Rust parser dependency or a
   new cross-crate test-only dependency.
2. Replace line-based comment stripping with lexical handling of line/block
   comments, escaped ordinary strings, and raw strings (`r"…"`, `r#"…"#`,
   including byte-string prefixes as appropriate). Attribute discovery must
   occur only in code, not comments or string contents.
3. Parse balanced `cfg` and `cfg_attr` attribute payloads. Walk every comma
   sibling and nested `not`/`any`/`all` expression; for `cfg_attr`, inspect the
   predicate argument and do not mistake later emitted attributes for the
   predicate. Match exact leaves for `unix`, `windows`, `target_os`,
   `target_family`, and `target_env`.
4. Make source traversal, directory-entry/file-type or metadata checks, path
   normalization, source reads, allowlist reads, and update-header reads
   fallible. Fail the ratchet with the exact path and underlying error rather
   than treating a missing/unreadable source or allowlist as absent. A missing
   or unreadable allowlist must not mean “no pins”. Preserve the existing
   shrink-only header/update behavior, but make update failures explicit too.
5. Add one byte-identity test (in the canonical core helper test module) that
   compares the core/media/metrics helper files. The copies' unit tests remain
   identical so each leaf crate exercises the repaired walker directly.
6. Reconcile the only newly flagged source: add `profile.rs` to
   `test/platform-cfg-host-ratchet.txt` with an adjacent written reason. The
   reason should state that SIGUSR2/`pprof` feature/platform gating and its
   no-op stubs intentionally remain co-located in this small profiling seam;
   moving it is larger than this maintenance fix and the entry is explicit
   debt. Do not silently mass-pin existing files and do not move production
   code unless primary review chooses that refactor.

Likely implementation files are the three helper copies and
`test/platform-cfg-host-ratchet.txt`; the five caller modules should continue
to use the same public `file_ratchet`/`has_platform_cfg` shape unless the
fail-closed result is intentionally kept internal. No production call-path
file needs to change for the allowlist reconciliation.

## Required regression/failure cases

Direct unit tests of the walker, copied identically to all three helpers, must
cover:

- `all(feature = "profiling", unix)` with the platform leaf second;
- nested predicates with the platform term in a non-first sibling, including
  nested `not`/`any`/`all`;
- `cfg_attr` with a platform term in its predicate;
- line/block comments that contain platform-looking text and comments inside a
  predicate;
- ordinary strings containing `//` followed later by a real platform
  attribute; and raw strings (including a `r#"…//…"#` form) followed later by
  a real platform attribute;
- injected traversal, directory-entry/path-normalization, source-read, and
  allowlist-read failures proving the ratchet fails closed and names the exact
  path/error. Prefer deterministic test seams or fixture shapes over permission
  tests, which are unreliable when tests run as root.

The existing temp-crate round-trip tests should retain header preservation,
new-hit failure, clean pass, exclusion, and stale-entry failure coverage while
being adapted to the fallible filesystem API. Add an explicit missing/failed
allowlist case; the current `unwrap_or_default` behavior would incorrectly
continue with an empty set.
