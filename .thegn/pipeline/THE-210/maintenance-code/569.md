# THE-210 maintenance code — native dispatch 569

## Verdict

implementation-ready

## Implemented

- Reused gate state is keyed by the stable SHA-256 `RepositoryId` derived from
  Git's canonically resolved `--git-common-dir`, not the caller path or
  `DefaultHasher`.
- The retained verified common-directory filesystem identity is checked against
  Git's resolved authority before reused-state admission.
- Unix state-directory, lock-creation, lock-acquisition, and identity-admission
  failures select the existing unique throwaway worktree. The shared `wt` is
  not inspected or mutated after that selection failure.
- An isolated gate gets a private target directory under its unique workspace
  by default. An explicitly configured `gate_target_dir` remains an explicit
  operator opt-in and is not cleaned up by the gate.
- The lock remains held by `Workspace` through preparation, materialization,
  setup, gate execution, verification, and reused-workspace cleanup.
- Platforms without the Unix verified workspace seam bypass reused-state
  admission before opening the shared gate root and run a native unique
  worktree. Gate commands use the existing cross-platform shell invocation
  helper.
- Preparation and cleanup errors remain infrastructure errors. `gate_tip`
  now preserves a bounded, sanitized concrete reason (including operation/path
  context) so `land` and merge-drain output do not collapse it to a generic
  headline.

The existing THE-597 hardening already failed closed before shared-worktree
mutation; this change completes isolation and diagnostics without reworking
that lifecycle.

## Regression coverage

- A held reusable lock now causes a second gate to run in isolation while the
  warm worktree and ignored artifact remain unchanged.
- A deterministic lock-acquisition failure (a sidecar directory) proves the
  isolated gate succeeds and a pre-existing shared path's content and mtime are
  unchanged.
- A barrier-backed concurrent gate records and verifies each requested OID;
  the first invocation keeps the reusable worktree while the contender uses a
  unique worktree.
- Linked and symlink-aliased worktrees are asserted to resolve to one gate
  identity.
- The Windows fixture now exercises a passing native unique gate and asserts
  that the Unix-only reused state root is not created.

## Follow-up and limits

Full Windows verified file/directory admission is intentionally not part of
this lane, as approved by the primary plan. The missing seam is
`crates/thegn-host/src/platform/gate_path.rs`; Windows currently isolates before
that Unix-only implementation. Adding verified Windows no-follow/identity
admission is a separate platform-security workstream.

No configuration or queue-architecture changes were made. Cargo, builds,
focused tests, Clippy, nextest, and full suites were not run because the
dispatch CPU constraint centrally schedules Rust validation across the batch.
