## Changes

- Consolidated TUI and CLI theme I/O behind one hardened store path. Reads open
  once with final-component no-follow semantics, validate handle metadata, and
  consume at most 64 KiB + 1 byte. Theme and config writes now use unique
  same-directory files created exclusively, preserve existing config
  permissions, and atomically rename without touching pre-positioned legacy
  temp symlinks.
- Made host and completion catalogs deterministic and bounded in retained
  paths/file reads: non-theme junk is filtered before the 256-theme allowance,
  a bounded heap retains the lexically first theme files regardless of
  filesystem iteration order, and CLI scan/metadata/parse failures are warned.
- Enforced Gogh `variant` as a checked contract. Light schemes require a
  lighter background than text and dark schemes require the inverse;
  contradictory parsed or directly constructed schemes are rejected while
  preserving the documented background-to-bg0 and foreground-to-text mapping.
- Started the off-loop user-theme scan early, awaited its result asynchronously
  at the first palette chokepoint, passed the loaded catalog into the event
  loop, and resolved onboarding preview/dismissal through that same catalog.
- Updated the in-flight OpenSpec design to document the variant-consistency
  rule.
