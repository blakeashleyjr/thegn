## Evidence that the bug remains

1. `crates/thegn-host/src/attention_status.rs:113-130` builds attention metadata from `db.worktrees()`. At line 126, registered worktree identity is currently `wt.branch == "home"`. Lines 132-145 add session-only groups and repeat the same assumption at line 139 by comparing the name's branch component to `"home"`. Both values can change independently of home identity.
2. `crates/thegn-host/src/hydrate.rs:1220-1242,1315-1325` obtains Git-backed branch observations for sidebar display. It projects the observed HEAD branch into `DbWorktree.branch`; it does not rewrite the identity-bearing tab name. `attention_status::collect_attention` is called at `hydrate.rs:1890-1892` and reads registry rows directly, not this branch projection. Registry `branch` is creation metadata (`worktree_snapshot.rs:1-2`), so its value can also vary by how/when the row was registered.
3. `crates/thegn-host/src/sidebar.rs:1513-1548` reconstructs dormant workspace groups. It finds the home DB row using `w.branch == "home"` at line 1517 and excludes all rows whose branch is `"home"` at line 1546. With home tab `app/home` checked out on `main`, the row is not found as home and can be emitted again as an ordinary row after a synthetic home row. A real branch named `home` on tab `app/home~` can be selected as home and omitted from the ordinary rows.
4. The stable identity is already represented in existing model fields. `thegn_core::repo::home_tab` returns `{slug}/home` (`crates/thegn-core/src/repo.rs:147-150`); `branch_tab` deliberately escapes a real branch named `home` to `{slug}/home~` (`repo.rs:152-166`, with the non-alias test at `repo.rs:338-350`). Live/persisted session groups also carry `GroupKind::Home` (`crates/thegn-host/src/session.rs:16-40,221-239`), independent of the Git branch.
5. A checked-out-main home row is a supported data shape already in source: `crates/thegn-host/src/measure/mod.rs:252-255` registers `repo/home` with branch `main`. Thus the failing case is not hypothetical schema expansion.
6. Targeted source search found the branch-string identity checks in the two production locations above. `repo.rs:163` also compares a branch to `"home"`, but this is the correct reserved-name escaping rule for `branch_tab`, not a worktree identity decision; leave it unchanged. Other home labels and explicit `GroupKind::Home` checks are identity/model logic, not branch-string classification.

## Production call path and impact

Hydration builds `SidebarStatus` on the hydration worker; `collect_attention` populates per-path scores and attention ranks, and the UI uses the home flag only as the tie-break after score urgency (`attention_status.rs:413-425`). The wrong flag can therefore reorder equal-tier worktrees, changing which worktree is ranked as home-first.

Separately, hydration passes Git-backed observations into `sidebar::build_rows`; its dormant-workspace path calls `gather_groups` (`sidebar.rs:1426-1453`) to union live groups with registered rows. The branch-based home lookup/filter can duplicate the home checkout and omit an ordinary worktree on branch `home`. This is visible even when no attention signal is raised.

## Smallest complete fix proposal

Use the stable tab identity for registry-backed rows and the explicit session kind for session-only rows:

- In `attention_status.rs`, classify a registry row as home by comparing its `tab_name` with the canonical home tab for its slug (or an equivalent helper based on `home_tab`), never by reading `branch`. For a session-only entry, use `g.kind == GroupKind::Home`, not the parsed branch component. Keep the existing path-keyed union and order tie-break unchanged.
- In `sidebar.rs::gather_groups`, identify/filter the home registry row by its reserved `tab_name` identity, not its live branch projection. Continue rendering the home row with the fixed `home` label and live branch in status/detail fields.
- Do not add a schema field or migration: `tab_name` is already the persistent identity, and a real branch called `home` cannot alias the reserved home tab because it maps to `home~`.
- Leave `repo.rs::branch_tab` reserved-name escaping unchanged.

Candidate production files: `crates/thegn-host/src/attention_status.rs` and `crates/thegn-host/src/sidebar.rs`. Candidate regression tests belong in their existing module test sections. The persisted `GroupKind` model in `session.rs` is already explicit; registry rows that enter attention/sidebar code should use their stable tab identity.

## Failure cases and regression coverage

1. Home tab `{slug}/home`, registry branch `main`: must remain home in attention ranking and dormant sidebar reconstruction.
2. Ordinary tab `{slug}/home~`, registry/live branch `home`: must remain ordinary in attention ranking and remain visible as an ordinary dormant sidebar row.
3. Keep equal attention tiers in the attention test so the home-first tie-break observes the classification, rather than testing only an isolated helper.
4. In the sidebar test, build a dormant workspace containing both rows; assert one synthetic/registered home row at `{slug}/home` and an ordinary row for `{slug}/home~`, with no duplicate home path and no dropped branch-home row.

## Ordered implementation and test plan
