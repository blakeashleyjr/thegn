# THE-574 adversarial source review — native dispatch 541

verdict: revisions-needed

## Review basis

Reviewed the implementation commit `3482e231` against `.thegn/maintenance/issue.json`,
`.thegn/maintenance/primary-plan.md`, `CLAUDE.md`, and `docs/ARCHITECTURE.md`.
The review covered the remembered-agent resolver, both materialize/prewarm call
paths, the spec-batch drain, the diagnostic ring contract, and the new tests.

## Findings

### F1 — repeated prewarm work is not deduplicated (high)

`crates/thegn-host/src/handlers/worktree_launch.rs:280-293` invokes the injected
`relaunch` resolver on every eligible call; `REPORTED_REFUSALS` is consulted only
after the resolver has already returned an error. A refusal leaves `specs` as
`Ok(shell specs)`, so `crates/thegn-host/src/handlers/provision.rs:552-568`
takes the success arm and never inserts the tab into `prewarm_failed` (the only
automatic-prewarm suppression is `run.rs:8627-8638`). The next prewarm tick can
therefore repeat DB/session/provider/sandbox resolution indefinitely. The warning
is deduped, but the expensive refusal-producing attempt is not, contrary to the
acceptance requirement not to flood repeated prewarm/materialization attempts.

The fix needs a refusal outcome/state that suppresses automatic retries while
retaining the already-resolved shell and allowing an explicit focused retry or
configuration/provider change to clear it. Add a call-path regression that
counts resolver invocations across repeated prewarm refusals.

### F2 — process-lifetime dedupe state grows without a bound (high)

`crates/thegn-host/src/handlers/worktree_launch.rs:77-78` stores every unique
`(worktree, agent, refusal-kind)` as owned `String`s in a global `HashSet`, and
`:108-113` never evicts or caps entries. Worktree paths and agent names are
caller/config-derived and worktrees can be created and removed repeatedly, so a
long-lived host retains unbounded path/name memory even after the worktrees are
gone. This is a resource-growth issue in the new process-lifetime registry and
also makes a large refusal workload contend on one ever-growing mutex-protected
set. Use a bounded representation/retention policy that is explicit about the
trade-off with process-lifetime dedupe, or scope/reset the registry to the host
session/worktree lifecycle.

### F3 — raw resolver errors enter the always-on diagnostic ring (medium/high)

`bounded_reason` at `worktree_launch.rs:95-105` only truncates
`anyhow::Error::to_string()`, and `:122-131` emits that raw text into a WARN
event. `launch_spec_full` can return provider, sandbox, credential-overlay, and
external setup errors, not just the two typed refusal structs. The WARN ring is
always enabled and is copied into debug bundles, while the repository's log
redaction guidance requires secret-bearing text not to reach logs. A provider
error containing a token, URL credential, or command output would therefore be
retained and bundled. Emit an allow-listed/sanitized reason (or pass the error
through the existing text redaction chokepoint) while preserving an actionable
category and bounded detail.

### F4 — the ordinary-error test does not prove the acceptance observables (medium)

The tests at `worktree_launch.rs:713-750` verify the generic kind and the helper's
bounded string, then use `admit_refusal` to infer that a report was admitted.
They do not capture the emitted WARN for the ordinary provider/launch error, and
they do not install a command sentinel or otherwise prove that no unsafe Codex
command was executed. The typed test had the same observability gap; this review
adds a test-only tracing subscriber at `:752-775` that verifies one emitted
typed report includes the reason and shell-fallback text. The ordinary case
still needs equivalent emitted-event and no-execution assertions, plus a
focused test that exercises the real provider error shape rather than only the
permission-policy fixture.

## Acceptance coverage

- Safe shell preservation and `suppress_agent_record: true` remain visible in
  the source; the fold does not replace the shell on `Err`.
- The early silent `Ok(None)` gates (missing row, shell/clean-shell/tool,
  removed config) remain intact.
- WARN level, stable refusal categories, bounded reason length, and separate
  kind admission are present.
- The immediate tab-local UI follow-up called out by the primary plan remains
  explicitly documented and is not incorrectly claimed as implemented.
- No source-only review can claim the no-duplicate-session runtime gate, actual
  provider behavior, compilation, or test execution. Those remain pending.

## Test-only change made by this review

`crates/thegn-host/src/handlers/worktree_launch.rs:752-775` to assert that the
typed refusal's WARN event is observable, actionable, and emitted once. No
production behavior was changed by the review.
