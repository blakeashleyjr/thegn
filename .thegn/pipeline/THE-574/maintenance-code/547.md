# THE-574 maintenance implementation — native dispatch 547

verdict: implementation-ready

## Scope implemented

- Preserved the fail-open resurrection behavior: a remembered-agent refusal
  leaves the already-resolved shell in the batch, does not spawn an agent, and
  does not rewrite `worktrees.agent`.
- Added an explicit `RelaunchOutcome` for the relaunch fold. A refusal is now
  represented as `Refused` in the fold's internal outcome while the enclosing
  spec result remains a successful shell batch; live attach, quiet split, and
  ordinary not-applicable gates remain `NotAttempted`.
- Kept the diagnostic at WARN so it reaches the always-on diagnostics ring even
  when `THEGN_LOG` is unset. Refusal details use the existing log redaction and
  bounded display seams: sensitive shaped values are redacted, controls are
  removed, and the detail is capped at 512 characters/cells.
- Replaced the unbounded process-lifetime refusal `HashSet` with a 256-entry
  FIFO registry. Oldest entries are evicted; an evicted refusal may be emitted
  again because this state is diagnostic deduplication, not a durable ledger.
- Strengthened regressions for typed provider-ownership and ordinary provider/
  launch refusals. They capture WARN output, assert stable classification and
  actionable detail, preserve the shell command without selecting Codex, keep
  remembered attribution, verify repeat-report suppression, and exercise
  redaction and FIFO eviction.

## Explicit scope findings

- `prewarm_failed` was not updated. Doing so would suppress subsequent automatic
  prewarm scheduling, which is a behavioral/retry change explicitly excluded by
  the primary revision. The fold's `RelaunchOutcome::Refused` records the
  refusal without changing that scheduling policy.
- Immediate tab-local refusal UI remains a follow-up. This lane uses the
  established worker-safe tracing/diagnostics seam; WARN entries are recoverable
  through the always-on ring, `thegn doctor`, debug bundles, and
