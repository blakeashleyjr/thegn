The surrounding implementation confirms the behavior:

- `remembered_agent_relaunch` reads the remembered `worktrees.agent` row at

  resolves the remembered agent through the normal launch machinery at
  `:80-94`.
- `apply_relaunch` at `worktree_launch.rs:153-169` replaces only the matching
  pre-resolved shell slot when relaunch returns `Some`. A refusal returns
  `None`, so the already-resolved shell remains safe; the refusal reason is
  discarded before any channel/UI consumer sees it.
- The module contract at `worktree_launch.rs:27-40` requires live attach to win,
  quiet splits to remain shells, `worktrees.agent` to remain unchanged, and
  worktree tagging to prevent the next open from relaunching twice.

The current branch therefore has the reported failure mode: a remembered agent
can be refused by provider/account/sandbox policy, the tab safely opens the
existing shell, and the tab can still look agent-attributed because the stale
remembered record is intentionally retained, but no actionable refusal is
observable from this resurrection path.

Relevant refusal evidence in the shared machinery:

- `agent::DevcontainerLaunchRefused` is a typed refusal at
  `crates/thegn-host/src/agent.rs:183-197`, raised when the selected provider
  session is unavailable (`:2930-2938`) or rejects its trusted launch argv
  (`:3048-3065`). Existing regression coverage proves it refuses before a host
  shell is invoked (`crates/thegn-host/src/agent_tests.rs:1534-1617`).
- `agent::SandboxHalt` is another typed refusal, preserved into `SpecError::Halt`
  and surfaced by the existing modal/status path. It must continue to be
  non-fatal for this resurrection fallback.
- The credential-bearing workspace overlay gate at
  `agent.rs:3673-3710` can refuse an agent launch for an ambiguous trusted
  account/origin overlay. It currently formats the refusal into `anyhow`, so a
  future richer category must be added without making this issue depend on
  THE-565's unlanded enum.

Prerequisites for the remembered-agent relaunch are therefore: a DB row naming
an agent, a matching configured `[[agents]]` entry, no live daemon session, a
non-quiet/non-terminal worktree launch, and a launch spec that passes all normal
provider/credential/sandbox policy. A refusal at the final prerequisite is the
only condition this issue needs to report; absent records, shell/tool records,
config churn, and live attach remain ordinary silent fall-throughs.

## Smallest complete fix

Keep the change in `crates/thegn-host/src/handlers/worktree_launch.rs` unless
primary review identifies an already-established UI diagnostic hook that is
mandatory. The recommended implementation shape is:

1. Preserve the `anyhow::Error` returned specifically by
   `launch_spec_synced_with` instead of collapsing it to `None`. Keep DB lookup,
   missing-record, shell/tool, and missing-config cases as silent `None` so the
   existing fail-open ladder is unchanged.
2. In `apply_relaunch`, on that error leave the pre-resolved shell slot in
   place and emit one warning through the established tracing seam. Include the
   worktree, remembered agent, a stable refusal kind, and the bounded actionable
   error text (for example: remembered agent refused; shell fallback retained;
   fix the provider/account/sandbox and reopen or retry).
3. Deduplicate for the lifetime of the host process/session by
   `(worktree, agent, refusal-kind)`. This suppresses repeated prewarm and
   materialize attempts without suppressing a genuinely different refusal kind.
   A small process-local mutex/once registry is sufficient; it adds no DB I/O,
   no event-loop work, and no new persistent state. Keep the full reason in the
   first report. The kind helper should recognize the typed refusal(s) present
   today and have a generic provider/launch bucket so THE-565 can add richer
   categories later without changing the call path again.
4. Do not change `attach_is_empty`, `quiet_split`, terminal gating,
   `suppress_agent_record: true`, shell materialization, daemon session
   adoption, or `worktrees.agent`. Do not move any resolution work onto the
   loop. Any send/waker operation used by a UI projection must follow the
   existing channel-plus-waker contract; tracing alone avoids adding a new
   channel dependency.

This removes the targeted ignored result without adding another ignored result
on the primary refusal path. It also avoids refactoring `direnv_warm` or the
launch-spec machinery and does not depend on THE-565.

## Failure cases to preserve or cover

| Case                                                                         | Required result                                                                                  |
| ---------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------ |
| No remembered row; `shell`; `clean-shell`; tool drawer; removed config entry | Existing shell, no relaunch diagnostic, no DB rewrite                                            |
| Live daemon attach exists                                                    | Attach only; no agent relaunch, no duplicate session                                             |
| Quiet split/add                                                              | Shell gesture remains a shell; no relaunch diagnostic                                            |
| Typed provider ownership/origin refusal                                      | Existing shell remains; no agent command/unsafe host shell runs; one actionable report           |
| Ordinary provider/launch error                                               | Existing shell remains; no agent command runs; one actionable report                             |
| Same refusal retried by prewarm/materialize                                  | No repeated report for the same worktree/agent/kind                                              |
| Different refusal kind for the same worktree/agent                           | A separate report is allowed once                                                                |
| Successful relaunch                                                          | First missing leaf gets agent argv; other leaves stay shells; attribution remains byte-identical |
