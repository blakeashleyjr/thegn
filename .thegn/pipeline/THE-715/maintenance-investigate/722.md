## Failure cases and meaningful regressions

- Assignment of a registered worktree to a same-repo folder succeeds, including trimmed/case-insensitive name resolution if the request is name-based.
- Clear succeeds for a registered worktree, sets only `folder_id = NULL`, and leaves the folder row intact.
- Missing worktree row errors for both assignment and clear (no implicit row creation and no successful no-op).
- Folder id from another repo errors and leaves the target unchanged.
- A folder deleted or renamed between lookup and guarded write yields the failed-identity error; no silent success or cross-repo fallback.
- Scope denial is Git-scoped and consistent across HTTP, gRPC, MCP and plugin call paths.
- API route and `API_CALLS`, MCP `STATE_TOOLS` and its implemented cap list, gRPC cap list, plugin projection, and catalog surface coverage remain in sync. No `SURFACE_GAPS` additions.
