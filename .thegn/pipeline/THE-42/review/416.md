# THE-42 security/test/bug review — row 416

## Verdict

## Blocking finding

- **Stale now-playing deliveries can overwrite the selected provider (race).**
  `restart_media_watch` aborts only the watcher handle
  (`crates/thegn-host/src/media_ctl.rs:67-86`). Already-running transport tasks
  are not cancelled, and each task still sends an untagged snapshot after its
  operation (`media_ctl.rs:91-136`). The event loop accepts every queued
  snapshot in `media_watch::drain_snapshots` without a generation/config/player
  check (`crates/thegn-host/src/media_watch.rs:225-259`). For example, select
  player B while an operation for player A is in flight: the old A task can
  finish after B's watcher and make the badge/panel show A again (or an old
  `None` can clear B). The same race exists across a live config disable/re-
  enable and overlapping transport operations. Queue/source deliveries have
  generation checks, but the primary snapshot path does not, contrary to the
  design's requirement that snapshot deliveries be identity-checked. Add a
  watcher/config generation (or cancellation token) to snapshot deliveries and
  a regression test that delivers an obsolete snapshot after a restart before
  this reaches the merge queue.
