## Branch evidence and current failure

The defect is present at HEAD:

- `crates/thegn-core/src/calendar/grid.rs:1-2` describes the grid as carrying
  “ISO week numbers”; `:26-27` stores `DayCell.iso_week`, the actual ISO week
  for each individual date.
- `grid.rs:56-61` rotates the grid origin to the requested `week_start`, and
  `:80-90` fills every cell’s independent ISO number. Thus a row is not
  necessarily ISO-Monday-aligned when `week_start` is Sunday or Saturday.
- `grid.rs:113-116` currently implements `week_numbers()` as
  `self.weeks.iter().map(|w| w[0].iso_week).collect()`. This is the first-cell
  heuristic and is the production bug.
- `crates/thegn-core/src/calendar/locale.rs:15-33` resolves explicit and auto
  settings to Monday, Sunday, or Saturday. Auto can select Sunday/Saturday;
  this is a production path, not a test-only combination.
- `crates/thegn-host/src/calendar_docs.rs:164-201` resolves `[calendar]` into
  `CalUiCfg.week_start` and carries `show_week_numbers` into the popup.
- `crates/thegn-host/src/detail/calendar/render.rs:214-291` builds the core
  `MonthGrid` and requests `week_numbers()` when the flag is enabled.
- `render.rs:599-613` emits the returned value as the visible `wN` gutter.
  `detail/calendar/layout.rs:114-154` and `detail/calendar/mod.rs:306-321`
  share the same row geometry for drawing and hit-testing, so no second week
  calculation exists downstream.

Concrete boundary failures under the reviewed contract:

| Grid row                                      | Existing ISO-first-cell result | Why false                                   | Required configured-start result             |
| --------------------------------------------- | ------------------------------ | ------------------------------------------- | -------------------------------------------- |
| Sunday 2021-01-03 through Saturday 2021-01-09 | `w53` from Sunday 2021-01-03   | Sunday is ISO 53, Monday–Saturday are ISO 1 | Sunday-anchored week 1 for all seven cells   |
| Saturday 2021-01-02 through Friday 2021-01-08 | `w53` from Saturday 2021-01-02 | Sunday is ISO 53, Monday–Friday are ISO 1   | Saturday-anchored week 1 for all seven cells |
| Sunday 2020-12-27 through Saturday 2021-01-02 | `w52` from the first cell      | Monday–Saturday are ISO 53                  | Sunday-anchored week 53 for all seven cells  |
| Monday 2020-12-28 through Sunday 2021-01-03   | `w53`                          | All seven cells are ISO week 53             | Unchanged ISO week 53                        |

The existing core tests only check the length of the output at
`crates/thegn-core/src/calendar/tests.rs:106-110`; they do not assert the row
definition or any non-Monday boundary. `iso_week_numbers_are_not_hand_rolled_across_the_new_year` at `:86-94` protects the per-cell ISO field, not the row gutter.

## Smallest complete fix

1. In `crates/thegn-core/src/calendar/grid.rs`, keep `DayCell.iso_week`
   unchanged for per-cell ISO data. Replace the first-cell lookup with a pure
   configured-start week calculation:
   - derive the row’s configured-start date;
   - define week 1 of a year as the configured-start week containing January 4
     (the ISO minimal-days=4 rule);
   - select the row’s week-year across the previous/current/next year boundary;
   - return the seven-day distance from that year’s week-one start plus one.

   The helper must use `self.week_start`, checked date arithmetic, and preserve
   the existing Monday result exactly. It should not change grid construction,
   `DayCell.iso_week`, event spans, or host rendering/layout.

2. Update terminology only on the reviewed surfaces:
   - `grid.rs` module/function docs: “week numbers”; explain that the result is
     ISO-8601 only for Monday-first grids and otherwise uses the configured
     first day with the four-day minimum.
   - `crates/thegn-core/src/config_calendar.rs:37-38`: revise the
     `show_week_numbers` field doc. Because `CalendarConfig` derives
     `schemars::JsonSchema`, this is the generated schema description.
   - `config/config.toml.example:347`: remove the unconditional “ISO” claim
     and describe the configured-start contract.

   The core calendar module doc at `calendar/mod.rs:10` and the host layout
   comment at `detail/calendar/layout.rs:18` also contain “ISO” wording. They
   are documentation-only residue, but the primary brief explicitly scopes the
   fix to `grid.rs` plus the `show_week_numbers` doc/example/schema surfaces
   and says not to touch rendering layout; do not expand the implementation
   lane without primary review.
