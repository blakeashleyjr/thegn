# THE-284 implementation report — dispatch 631

Verdict: **revisions-needed**. The production behavior and regression cases are implemented, but the primary's structural correction is unresolved and compilation/tests were not run under the explicit CPU restriction. This artifact does not claim an implementation gate passed.

## Changes made

- Added a per-pane `QueryParser` with a 4096-byte retained-control bound for CSI, OSC, and APC. Oversized sequences are discarded through their semantic terminator; completed supported queries preserve their existing reply bytes and stream order.
- Routed normal-pane query handling and corner-pane emulator text through the stateful parser. The existing current-generation bit gates parsing/reply admission while stale tails still reach the emulator.
- Reset query state on reattach, session fallback, and exit. Pane ownership prevents state sharing across panes.
- Reported `write_reply` Full/Closed errors on the normal path as well as the corner path.
- Added regression cases for every split offset of supported CSI/OSC/APC queries, overflow recovery, parser reset/isolation, query-looking bytes inside control strings, the drain fairness boundary, stale-generation tails, corner relay consumption, and Full/Closed pane-input refusal.

## Structural review blocker

I read the local `queries::clipboard::Clipboard` implementation (the branch has no THE-244 commit). It is a specialized OSC 52 admission parser: it validates and retains a byte-exact set for retry under writer backpressure, while treating CSI as ordinary text and skipping APC/DCS/PM/SOS. The new query scanner therefore has a separate lexical state machine and bounded buffer. The two are both reset at the same pane lifecycle barriers, but this does **not** meet the primary correction's request to share a bounded-prefix scanner that can feed both matchers.

A true shared mechanism requires extracting one top-level terminal-control scanner that emits completed OSC/CSI/APC events, then routing those events into OSC 52 validation/admission and query response matching while preserving clipboard retry ownership and the existing OSC52 policy. I did not make that wider parser refactor under an assumption about ownership/event ordering. This is a concrete review blocker; do not treat the implementation as structurally complete until the primary resolves or approves that refactor.
