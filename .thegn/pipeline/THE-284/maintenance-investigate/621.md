## Smallest complete fix

Add a bounded stateful query responder alongside the existing pane-owned
clipboard parser, preserving the existing response grammar and byte ordering.
Carry the generation-current admission fact through both output branches: stale
queued tails must still feed the emulator in FIFO order, but must neither
complete a query across a reattach/fallback boundary nor cause a reply to be
sent into the new session. Reset query-parser state at the existing reattach,
fallback, and exit lifecycle points. Preserve separate responder state for
each pane.

The parser should scan incrementally without a per-byte allocation, retain no
more than a fixed documented bound for an incomplete control sequence, and
discard an oversized/malformed sequence through its semantic terminator before
resuming top-level scanning. Keep the existing CSI, OSC 10/11, and kitty APC
query matching and response bytes. Batch complete replies in stream order for
the current slice only where concatenated terminal responses remain
unambiguous. When `write_reply` refuses a nonempty response, surface the typed
reason (at minimum a warning matching the existing corner path); do not claim
delivery.

## Failure cases to prevent

- Any supported CSI/OSC/APC query split at each byte offset across PTY reads or
  `take_tagged_slice` fairness cuts gets exactly one existing-format response.
- Incomplete controls from one pane or generation cannot be completed by bytes
  from another pane or a post-reattach/fallback generation.
- Oversize and unterminated CSI/OSC/APC inputs remain bounded; after the
  relevant final byte / BEL / ST, trailing ordinary text or a later valid
  query is handled without a false reply.
- Kitty APC probes remain recognized in the normal pane path; for the corner
  path, only text emitted by `kitty_relay` is query-scanned and a kitty probe
  consumed by the relay is not answered twice.
- Multiple complete queries preserve reply order and multiplicity. Ordinary
  emulator output, including SGR and query-looking bytes inside another
  control string, creates no reply.
- A full/closed bounded pane-input queue is reported as refusal, not as a
  successful reply; one pane's backpressure or parser state does not affect
  another pane.
