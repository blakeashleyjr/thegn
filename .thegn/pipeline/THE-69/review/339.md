# THE-69 security/test/bug review — dispatch 339

## Verdict

PASS — ready for the merge queue.

## Review findings

- Fixed one host-edge terminal-control injection: configured budget scope text
  was persisted into notification source/message fields without sanitization.
  A scope (including a valid Unix worktree path) containing CR/LF could move
  termwiz's cursor outside the notification clip rectangle. Commit `87704822`
  escapes control characters in rendered/deduped scope text, declines unsafe
  worktree routing, and adds a regression test.
- No SQL or shell injection was found. Budget and notification values use
  parameterized SQLite operations and are never interpolated into a command.
- Emit-once identities remain stable per scope/window/dimension, persistence
  precedes transient notification channels, and concurrent refreshes use the
  existing atomic store-side insertion path.
- Database open/read/write errors degrade without blocking the event loop;
  budget reads and notification routing remain inside the existing blocking
  usage worker.
- Proxy enforcement and host alerts share cap equality and rolling-window
  classification. Kill-switch-only rows, disabled caps, unknown scopes, and
  lapsed windows do not manufacture cap notifications.
- No config key, capability, migration, control-schema change, vendor seam, or
  ratchet exception was introduced. The full gate includes the workspace-level
  `config_example`, `env_overlay_coverage`, and `config_validate` tests omitted
  by scoped suites.
