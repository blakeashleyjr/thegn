## Approved notes

- Periodic budget projection deliberately rides the existing usage poll. Since
  that ticker is disabled when `[usage] enabled = false`, a model-proxy user who
  disables usage gathering will not get periodic cap discovery unless a usage
  refresh is otherwise triggered. This is the seam explicitly selected by the
  design and is not an unsafe regression, so it does not justify a fresh
  revision/build round. If the product contract later requires budget alerts to
  be independent of usage tracking, give them a separate off-loop cadence
  rather than making disabled usage gathering perform account/network work.

  `.understand-anything/knowledge-graph.json` is absent. Architecture impact was
