## Issue and branch status

The captured THE-718 evidence reports 348 child starts during a 60-second steady-state window after a five-minute settle, with a fixed expected ceiling of zero. Most observed starts were `rev-parse` (229/min); additional groups were `remote` (45), `worktree` (24), `stash` (12), `status` (12), `-c` (11), and several commands at 3–4 each. The capture does not include full argv, so those labels are prefixes, not unique call-site identities. It also records earlier `git-upload-pack`, `git maintenance run --auto`, and `rev-list --objects --stdin` observations.

The bug remains on this exact branch. `hydrate_tuning.rs` sets the model refresh default to 5,000 ms and the background glyph TTL to 5,000 ms; `collect_sidebar_status` scans all session worktrees whenever their glyph cache is stale, and each scanned path calls `thegn_core::repo::main_worktree`, which shells out to `git rev-parse --git-common-dir` (`crates/thegn-core/src/repo.rs:73-82`, `crates/thegn-host/src/hydrate.rs:1618-1633,1648-1697,1706-1715`). The five-second scheduler emits model refreshes (`crates/thegn-host/src/hydrate_refresh_ticker.rs:258-267`; run loop handles `RefreshKind::Model` and starts `spawn_model_hydration` at `crates/thegn-host/src/run.rs:11884` and `12235-12290`). The scan fan-out is off-loop, but it still violates the idle spawn ceiling.

There is a second repeatable path: every model build calls `build_panel`; that function unconditionally schedules Git backend reads for status and stash count (`crates/thegn-host/src/hydrate.rs:2572-2580,2624-2667,2689-2693`). The default `GixGit` backend delegates `status` to `CliGit`, and `stash_count` is a CLI command (`crates/thegn-svc/src/git/mod.rs:1449-1466,1578-1582,431-442`). This matches the measured 12 `status` and 12 `stash` calls/minute at a five-second model cadence. Whether more panel reads fall back to CLI depends on the repo/read backend and must be checked against the primary's full argv capture.

## Main candidate fix and correctness risks

Smallest complete production direction is to separate the five-second sidebar/activity safety tick from the active panel's command-backed snapshot, and stop resolving each row's main-worktree root through a fresh subprocess. Retain panel status/stash/diff/branch data between idle model ticks; refresh them from the existing diff/ref watcher, worktree switch, or visible-section demand. For repo identity, pass roots already known from the worktree registry through the hydration path and resolve the active path once per build when registry data is absent. Avoid a global permanent cache unless it has invalidation on repo/path reassignment; stale root identity would cross-contaminate PR badges, submodule policy, or queue scope.

Failures the implementation/tests must cover:

1. A dirty file, staged file, untracked file, or conflict changes while idle: watcher-triggered refresh still updates panel and sidebar promptly; no false-clean snapshot.
2. Stash push/drop while idle: visible stash count/list updates on the next explicit demand/change refresh.
3. Branch switch, branch create/delete, fetch, worktree add/remove, or a path reused for another repository: root/branch/holder caches invalidate and never leak one repository's rows into another.
4. Missing/unreadable path or deleted worktree: failed root resolution does not become a false repo identity or clear a last-known dirty row; retry is not a per-tick process loop.
5. Expanded Branches/Files/Commits sections still load and update on demand; closed sections do not turn a 5s ticker into periodic Git CLI work.
6. Remote/provider worktrees preserve bridge-only/suspended behavior; never wake a suspended environment to satisfy idle hydration.
7. Auto-fetch disabled, offline, no-remote, failure/backoff, and multiple same-repo checkouts preserve coalescing and do not run early.
