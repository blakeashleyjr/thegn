# THE-463 implementation — native dispatch 527

verdict: revisions-needed

## Scope implemented

- Added `CalendarMutation` and typed `CalendarError::ReadOnly` denials,
  distinct from provider `Unsupported` errors.
- Added one account-policy adapter around every backend returned by the public
  `backend_from_account` factory. `read_only = true` clamps only create,
  update, and delete capabilities and denies those calls before provider or
  command-plugin invocation. `incremental` and `server_expand` pass through.
- Routed crate-local router capability lookup and create/update/delete dispatch
  through the account-bound adapter. Missing or duplicate account names return
  `NotConfigured` instead of selecting an arbitrary backend.
- Added bounded `thegn::calendar` warning diagnostics containing only account,
  provider, and operation fields for denied mutations.
- Narrowed the raw ICS, ICS URL, CalDAV, and command backend constructors to
  `pub(crate)`. Updated `calendar_plugin_alloc` to use the account-bound
  factory.
- Added focused regression coverage for contradictory provider capabilities,
  all three mutation verbs under both policy states, provider-vs-policy error
  distinction, read/fetch preservation, router/plugin pre-invocation denial,
  account ambiguity, and diagnostic-field redaction.

## Concrete blocker / unverified acceptance

The checkout has no production implementation of `ControlApi::calendar_ingest`:
the route exists, but the trait method remains its `Unimplemented` default and
there is no cache-ingest service path to invoke. Implementing a successful
ingest path or wiring it to account configuration would be a new feature and a
design expansion beyond the approved plan. The policy adapter does not wrap or
block ingest, and the focused tests prove read/fetch remains available for a
read-only account, but a successful `calendar.ingest` regression cannot be
written against a nonexistent production implementation. This needs primary
direction or a follow-up owner before that acceptance can be claimed.

The consumed-config-field ratchet remains explicitly out of scope. No control
route or wire schema was intentionally changed, but the public service error
surface changed; the snapshot command below is therefore recorded for primary
validation.
