## Findings

### 1. Fast-forward backfill records the wrong landed identity (P1)

`crates/thegn-host/src/integrate.rs:112-120` walks the exclusive range
`<branch_tip>..<target_tip>` and takes its first result. For a legitimate
fast-forward landing followed by one unrelated target commit, that result is
the unrelated descendant, not the branch tip that was integrated. The helper
therefore violates its own “first target-side commit that carries the tip”
contract for the fast-forward shape described by the primary instructions.

This is not an immediate ancestry bypass: cleanup still independently proves
the current branch head and supplied OID are ancestors of the target. It is a
cache-identity correctness failure, though: if the target is later rewritten or
prunes that unrelated descendant while retaining the branch tip, cleanup can
refuse an otherwise safely sweepable worktree because the recorded OID no
longer resolves. The new regression at
`crates/thegn-host/src/integrate.rs:3231-3247` captures this case and is
expected to fail against the current implementation until the derivation
semantics are corrected.

### 2. Ancestry output is unbounded in memory (P2)

`crates/thegn-host/src/integrate.rs:113-120` uses
`thegn_core::util::git_out`; `crates/thegn-core/src/util.rs:1416-1423` waits
for the complete `rev-list` stdout and materializes every OID before selecting
the first line. The required correction correctly avoids the incorrect
`--reverse --max-count=1` combination, but the replacement now has no bounded
output path. A legacy row whose tip is far back in a large repository can make
one sweep allocate the entire ancestry walk, and multiple missing rows repeat
that cost. Preserve the approved ordering while streaming/discarding after the
first line (or otherwise enforce a bounded subprocess output strategy).

### 3. Mandatory shape coverage does not exercise the sweep repair path (P2)

The integration unit test at
`crates/thegn-host/src/integrate.rs:3146-3229` exercises the shared helper for
plain, octopus, absorbed, and unmerged graphs, while
`crates/thegn-host/src/merge_sweep.rs:529-593` exercises only a plain merge
through ref resolution, CAS backfill, reload, and cleanup. There is no
end-to-end missing-OID sweep regression for the mandatory octopus-not-parent-2
or absorbed shapes, so a future mismatch in `derive_missing_landed_oid`, row
ref resolution, or the sweep integration can regress all three affected legacy
rows while the helper-only test remains green. Add focused sweep fixtures for
those two shapes, including queue backfill and physical cleanup assertions.

The test-only addition at
`crates/thegn-core/src/db_merge_status_tests.rs:226-238` also locks repair of
the empty-string legacy form, which was previously tested only for SQL guard
rejection, not successful sweep-compatible backfill.

  DB guards reject newly-created `landed` rows with no effective OID.
- The ancestry proof remains independent of derivation, and the final cleanup

  landed ancestry, and dirty state.

  review rather than claimed as a full concurrency gate.

  were added. No child dispatch, merge, push, tracker closure, row-status
  change, or main-branch edit was performed.
