## Scope completed

- Removed the policy-free `reqwest::Client::new()` fallback from the remote
  control transport.
- Kept `ControlClient::new` compatible with existing callers by retaining a
  typed `ControlTransportError` in the HTTP-origin transport slot when the
  policy-configured builder fails. The first request returns that typed error;
  no request can silently proceed with a different redirect policy.
- Preserved the single `reqwest::Client` per HTTP-origin client and its shared
  pool across `ControlClient` clones. Unix/TCP and WebSocket transports were
  not changed.
- Renamed and clarified the replacement regression as
  `different_http_origin_clients_keep_in_flight_work_on_old_client`. It proves
  that independently constructed clients for different effective origins do
  not cancel in-flight work held by the old client.
