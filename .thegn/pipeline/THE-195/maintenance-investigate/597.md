## Production call paths and prerequisites

`main.rs:565-568` parses `thegn api`; `main.rs:1286` dispatches it to
`cmd::api::run`; `api.rs:54-60` selects `Coverage`; `coverage()` calls
`surface_ledgers()`; and `thegn_core::capability::ledger()` computes the
counts from each surface’s implementation table and `CATALOG`/`SURFACE_GAPS`.
No daemon, socket, database, or network is required.

The CLI test path is independent today: `session::catalog_tests` calls the
test-only session registry and `coverage_problems`. HTTP, gRPC, MCP, and plugin
inputs already come from their existing reviewed projections (`implemented_caps`,
`GRPC_CAPS`, `MCP_STATE_CAPS`, and `plugin_host_call_caps`). `API_CALLS` remains
the generic route/client spine, and its route mirror test is a prerequisite for
route additions. Local CLI-only operations are represented by the session
registry and must remain covered by the catalog surface declaration or an
explicit gap; they must not be silently treated as route rows.

## Smallest complete fix

   helper (remove only its `#[cfg(test)]` gate). This preserves the reviewed
   local-command declarations and keeps one route/command implementation table
   for both the test and runtime paths.
2. Delete the duplicate `api.rs::cli_control_caps()` table and have
   `surface_ledgers()` call the session helper. Do not copy the 26 local IDs or
   alter `CATALOG`, `SURFACE_GAPS`, or the out-of-scope capability gaps merely
   to force a target count.
3. Refactor coverage document construction so human and JSON output consume the
   same snapshot of ledgers plus one metadata record. Include the existing host
   build revision (`diag::build_string()`, with its documented unavailable
   fallback) and a stable coverage-schema version. Keep the control wire schema
   version separate; this is CLI-local diagnostic output, not a new control
   route or wire DTO.
4. Add drift tests without duplicate count literals: assert the reported CLI
   ledger equals `ledger(Surface::Cli, &session::cli_control_caps())`, retain
   `cli_control_verbs_cover_catalog`, and assert the shared report document has
   revision/schema metadata. Exercise the same generated document shape for
   human and JSON rendering. Existing catalog/gap and route-mirror tests remain
   the guards for additions/removals.

The expected current CLI result should emerge from the catalog and shared
registry (88 working, 4 excused, 92 declared), not from an `88`, `4`, or `92`
assertion. The implementation must not close `search.*` or container gaps;
those are follow-up work owned by the related issues/roadmap.

## Failure cases to preserve and test

- Adding a new local CLI command must require one session-registry/catalog
  update and be visible in both test and report paths; deleting one must create
  a catalog drift failure rather than silently lowering the report.
- Adding/removing a routed operation must continue to be governed by
  `API_CALLS` ↔ `ROUTES`, and the shared CLI registry must see the route without
  a second API-report edit.
- Deprecated `project.*` aliases must retain the existing alias-aware coverage
  semantics; comparing raw vector lengths would produce a false mismatch.
- `SURFACE_GAPS` must remain an explicit, reasoned exclusion list. Report
  `excused` rows and reasons; do not count them as working operations.
- `browser.drive`/universal-stub assumptions must not be reintroduced; current
  core tests require no advertised universal stubs.
- Human and JSON output must carry the same rows and revision/schema metadata;
  no-daemon invocation must remain local and side-effect free.
