## `have()` production paths and prerequisites

`thegn-core::util::have` currently calls uncached `which_path`, which walks the
current `PATH` and calls `is_file()` for each candidate directory entry. A
positive-only session cache is safe under the primary decision: a hit can be
retained, but a miss must not be retained because a pane can install a tool
mid-session (`nix develop`, `cargo install`, etc.). `which_path` itself should
remain uncached so callers that need an actual path continue to observe current
PATH state.

The current production call sites are 30 textual invocations across the
following paths (test-only `sandbox_tests.rs`, documentation strings, embedded
shell `have()` functions, and the host-local `platform/sound.rs` helper are not
core `util::have` callers):

- Core selection/probing: `picker.rs` (gum/fzf interactive fallback), `placement.rs` (local runtime presence), `profile.rs` (terminal fallback), `sandbox.rs` (devenv and missing-tool reporting), `sandbox_backend.rs` (backend binary), `sandbox_cpucap.rs` (systemd-run/nice/ionice), `sandbox_dormant.rs` and `sandbox_mountcheck.rs` (colima), `sandbox_events_podman.rs` (podman prefix), and `worktree.rs` (cargo-clean fallback).
- Host selection/probing: `agent.rs` (dormant backend and timeout/gtimeout), `build_cache.rs` (sccache), `cmd/doctor.rs` (macOS integration visibility), `cmd/mod.rs` (gum confirmation), `desktop_notify.rs` (notify-send/osascript), `drawer_state.rs` (systemd-run containment), `handlers/provision.rs` (backend admission), and `managed_tool.rs` (npm/cargo prerequisites).

The relevant tool prerequisites are therefore PATH presence for `gum`, `fzf`,
terminal programs, `devenv`, sandbox runtimes, `systemd-run`, `nice`, `ionice`,
`colima`, `cargo`, `sccache`, `notify-send`, `osascript`, `npm`, and
`timeout`/`gtimeout`; no call requires spawning a process merely to answer
`have()`.

   `OnceLock<Mutex<HashMap<String, Option<String>>>>` and a small testable cache

## Regression tests and validation order

Add unit coverage beside `have()` in `crates/thegn-core/src/util.rs` using an
injected probe/cache helper so tests do not mutate the process-global `PATH`:

1. Positive direction: a successful lookup is cached; a second lookup for the
   same command returns true even if the injected probe would now miss.
2. Negative-to-positive direction: an initial miss is not cached; a later
   lookup that finds the command returns true and stores the positive path.
3. Concurrent access: multiple threads probe the same cache concurrently and
   all observe a valid result without a poisoned lock or lost cache entry.

The implementation should also preserve the existing behavior checks around
doctor tool presence, host-parity Nix root filtering, custom/remote shell
execution, configured regeneration redirection, and the hashing pipeline;
these are the relevant failure cases for the two wrapper conversions and the
retained sites. The primary should run the required validation in this order
after implementation:

1. A focused core test selection for the new cache tests (the exact nextest

3. `just lint` (format, clippy, shell, YAML/TOML and ratchets).
