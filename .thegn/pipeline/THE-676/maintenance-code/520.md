## Implemented

- Added a process-wide `OnceLock<Mutex<HashMap<String, Option<String>>>>` for
  `thegn_core::util::have`. Positive paths are cached for the session; misses
  are not inserted and are re-probed so a pane can discover tools installed by
  `nix develop` or `cargo install`. `which_path` remains uncached.
- Recovered poisoned cache locks with `into_inner()` so an unrelated panic in
  another thread cannot take down launch/probing paths. The cache is explicitly
  best-effort infrastructure.
- Added injected-probe regressions for positive caching, miss-then-hit
  re-probing, concurrent access, and poisoned-lock recovery. These tests do
  not mutate process-global `PATH`.
- Replaced the fixed local `command -v` shell in `cmd/doctor.rs` with
  `thegn_core::util::have`.
- Replaced the fixed local `command -v` probes in
  `agent.rs::host_shell_store_roots` with a direct path probe while preserving
  canonicalization, `/nix/store` filtering, deduplication, and best-effort
  omission. Absolute `$SHELL` paths are checked directly, so they do not rely
  on `PATH` being set; a regression test pins that behavior.
- Documented at both conversion sites that `which_path` differs from shell
  `command -v`: it does not check executable bits, and bare-name lookup returns
  no result when `PATH` is unset. `which_path` was not changed, as required by
  the approved plan.
