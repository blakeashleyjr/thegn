## Failure cases and design hazards if scope changes

No implementation is recommended now. If primary review later identifies actual recurring object reads and authorizes a scoped process, the design must first settle all of these:

1. Batch framing must handle partial header/body reads, exact declared lengths (including zero), binary payloads, and the response terminator without `String::from_utf8_lossy` or `.trim()` corrupting object bytes.
2. EOF or child death mid-header/body must invalidate the response and fall back to a one-shot operation. A malformed/oversized length must not allocate unbounded memory.
3. A stalled write/read needs a stated deadline; expiry must terminate/reap or quarantine the child and execute the old one-shot behavior, never strand the caller. This needs cancellation-safe ownership and concurrent-request serialization/multiplexing rules.
4. Child restart, idle expiry, detach/shutdown cleanup, and descendant reaping need a deterministic owner. A parked helper must block in its own thread with no polling/timer wake source. Any new long-lived thread must declare `platform::qos` (`Utility` or `Background`), and launch stays lazy/off-loop/after first frame.
5. Process identity must be scoped to the correct repository/common object database (including linked worktrees and alternates), and concurrent calls must not mix responses.

## Smallest complete recommendation and ordered follow-up

1. **Do not implement the cat-file process on this branch under the current evidence.** No production files are affected by the no-go outcome; keep the helper and callers unchanged.
2. If the parent wants to pursue the general spawn-cost problem, first produce a fresh, precise inventory of direct `util::git_out` call sites and measured repeated object-query demand. The current 77 figure is not a target count and the recorded rev-parse/status timings do not establish cat-file demand.
3. If that inventory yields a repeated object-read workload, revise the issue/coordination scope before coding so the actual eligible producers and repository lifetime owner are explicit. Then primary review must greenlight it.
4. Conditional regression tests for such a revised implementation should use a deterministic fake child/protocol harness: multiple requests share one child; fragmented header/body reads and binary bytes round-trip; clean EOF, crash between frames, and crash mid-body fall back once; oversized/malformed lengths refuse safely; a controlled hung child exercises the deadline/fallback; and explicit shutdown proves child reaping. Add an assertion that the parked child has no poll/timer wake mechanism. Do not use timing-only sleeps for partial-read/death cases.
5. No builds, cargo commands, benchmarks, or broad tests were run for this investigation, per dispatch instructions and CPU constraints.
