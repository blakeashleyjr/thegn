## Smallest complete fix proposal

1. Keep receiver registration before the Hello write. After Hello, use a biased or fair `tokio::select!` between `rx.recv()` and inbound `socket.recv()` so broadcast delivery remains as-is while idle transport traffic is serviced.
2. For inbound WebSocket messages: terminate on Close, EOF, or transport/protocol error; reply to Ping with Pong carrying the same payload (and ensure it is flushed); ignore Pong; ignore Text/Binary data without calling any `ControlApi` operation. Preserve broadcast lag semantics (`signal_lag`) and filter behavior.
3. Bound event-stream concurrency with a non-waiting permit acquired before upgrade (return an explicit overload response if exhausted), held through the upgraded task and released by RAII on every return/error/cancellation. The cap must cover both unix and TCP listener instances, rather than silently allowing one cap per listener. Existing `ControlState` instances are separately built for those listeners in `crates/thegn-host/src/daemon/mod.rs:392-405,437-452`; a shared event-feed limit/metrics object should be created once and cloned into both states. Tests and other struct literal sites in svc/host (`rg ControlState {`) need corresponding initialization.
4. Instrument observable active, rejected-at-cap, and completed/terminated counts (with close/error reason in structured lifecycle tracing) around the same RAII permit. No metrics exporter/gauge API was found under `crates/thegn-svc/src/control`; the primary should confirm whether structured tracing plus test-visible atomics satisfies “expose active/leaked connection metrics,” or name an existing external metrics sink to target. Do not add a general metrics feature or config option to this maintenance fix.
5. Do not move event-stream admission into THE-181 reverse-tunnel files and do not add handshake semantics owned by THE-277.

## Failure cases to cover

- Peer closes immediately after Hello while no broadcast event is published: handler exits, receiver drops, active count returns to zero.
- Peer sends Ping while the feed is idle: Pong with matching payload arrives promptly; stream remains subscribed until client closes.
- Client sends Text/Binary data: it cannot mutate sessions or any other API state; the server may ignore it or close under protocol policy, but must not interpret it as control input.
- Peer EOF, malformed/protocol frame, and socket read/write error: each path releases permit and broadcast receiver.
- More than the fixed cap connect concurrently: no waiting queue or unbounded task creation; excess connection is rejected before upgrade; active count never exceeds cap; permit becomes available after termination.
- Broadcast lag with `signal_lag` false/true retains existing behavior. A slow/non-reading client cannot block global event publication; the broadcast channel remains the buffering boundary, and failed/blocked delivery must not defeat inbound-close servicing indefinitely.
- Repeated connect/Hello/Close cycles return active count and `broadcast::Sender::receiver_count()` to baseline without needing a later event.
- Auth rejection and invalid query still occur before subscription/admission side effects.
