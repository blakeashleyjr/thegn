## Findings

### 1. Timed-out Git descendants are not terminated — resource-growth blocker

`nix/detect-legacy-post-checkout.py:59-67` creates a new session/process group,
but `:103-117` calls `process.kill()` only on the direct child and then closes
the local pipe handles. A Git wrapper can fork a descendant that inherits
stdout/stderr, have the direct process time out, and leave that descendant
running with the pipe open. The selector has already stopped, and the
`process.wait(timeout=0.5)` only waits for the direct child. Repeated automatic
non-CI shell entries through `flake.nix:469` can therefore accumulate orphaned
descendants and open pipes despite the detector's advertised two-second bound.
The Windows new-process-group flag has the same direct-child-only cleanup issue.

Fix the timeout/overflow path to terminate and reap the complete process tree
through a platform-appropriate group/job-object primitive, and add a fake-Git
regression that forks a child holding both output pipes, asserts the child is
gone after refusal, and repeats the detector to check bounded process/fd
growth.

### 2. Inherited Git environment can redirect the detector to an unrelated repository

`nix/detect-legacy-post-checkout.py:49-57` copies the complete ambient
environment into every Git query. The first query at `:177-180` trusts
`git rev-parse --show-toplevel`; with inherited `GIT_DIR`, `GIT_WORK_TREE`,
`GIT_COMMON_DIR`, or related Git environment variables, Git can report another
repository. The later identity check at `:190-198` then validates that
redirected repository against its own `.git`, so it does not detect the
redirection or refuse. The detector remains read-only, but it violates the
repository-scoped/verified-authority contract and can report the wrong
repository's hook during shell entry.

Refuse or scrub the full Git directory/index/object/namespace environment
before the first query, consistent with the existing hook-test environment
scrub, and add a fixture with cwd in repository A and `GIT_DIR` pointing at
repository B that must refuse or inspect only A.

### 3. Required config-collision regression coverage is incomplete

`test/the429_checkout_hooks.py:221-237` checks only preservation of one regular
`.pre-commit-config.yaml`. The directory, valid symlink, dangling symlink,
FIFO, and replacement tests at `:286-311` exercise the detector's
`.git/hooks/post-checkout` candidate instead, not the former config-seeding
target. Because the implementation currently removes the seeder, this is safe
by absence, but the issue explicitly requires those config-path collision cases
to be covered so a future setup change cannot reintroduce `ln -sf` behavior.
Add the same byte/path/mtime/no-follow matrix at the worktree config path, plus
an actual replacement race around the shell setup seam.

### 4. Native worktree creation is optional in the routine regression

`test/the429_checkout_hooks.py:218-243` skips the production `thegn wt new` path
unless `THEGN_TEST_BINARY` is set. The default `test-the429`/`test` recipe
therefore proves ordinary Git checkout/worktree behavior but does not prove the
native creation command. The primary instructions state that the primary ran
the native fixture, but it was not run in this independent review; retain that
as a separately evidenced primary validation item rather than treating the
default focused test as complete coverage.
