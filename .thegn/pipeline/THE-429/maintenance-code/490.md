## Implemented scope

- Removed `hookExtras` installation of the branch-controlled `post-checkout`
  payload from `flake.nix`.
- Deleted the tracked executable `test/git-hooks/post-checkout.sh`; no supported
  checkout hook executes `heal-worktree.sh` or seeds `.pre-commit-config.yaml`.
- Preserved `PREK_ALLOW_NO_CONFIG=1` as optional developer compatibility and
  left generated pre-commit/pre-merge/pre-push gate configuration intact.
- Added immutable Nix-store detector `nix/detect-legacy-post-checkout.py`.
  It is read-only, bounded to 64 KiB, uses no-follow open, requires the main
  checkout's ordinary `.git/hooks` identity and matching ownership, allows only
  an exact local hooksPath resolving there, refuses custom/global/system/
  worktree paths and ambiguous path types, and reports exact legacy bytes for
  manual cleanup. It never deletes or overwrites anything.
- Documented optional local-gate versus CI/merge enforcement, linked-worktree
  setup, explicit legacy cleanup, and the deliberately non-race-safe explicit
  `just heal-git` boundary. No THE-371 shared-config implementation was copied
  or changed.
- Added `test/the429_checkout_hooks.py`, which performs actual hermetic Git
  checkout and `git worktree add` operations against malicious branch payloads,
  checks sentinel non-execution and ignored config preservation, and exercises
  the detector's exact digest, foreign bytes, regular/directory/live-symlink/
  dangling-symlink/FIFO/oversize, concurrent-read, custom/global path, and
  linked-worktree cases.

## Acceptance mapping

1. Malicious branch checkout/worktree payloads: covered by the focused fixture;
   sentinel remained absent.
2. Foreign hook/config collision preservation and no automatic config seeding:
   covered for regular files, directories, symlinks, dangling symlinks, FIFO,
   custom/global paths, and ignored linked-worktree config.
3. Legacy detector: exact known digest, bounded read, no-follow special-path
   refusal, ownership/path checks, zero writes, and concurrent detector runs
   are covered. No check-then-unlink race is presented as safe because there is
   no automatic migration operation.
4. Existing generated gate definitions and `PREK_ALLOW_NO_CONFIG` remain in
   place; documentation states that local hooks are convenience only.
5. The production `thegn wt new`/TUI/control worktree seams still converge on
   the ordinary core Git worktree operation, but their compiled execution was
   not run under this dispatch because Cargo/build/full-test commands are
   centrally scheduled and prohibited here. This is an explicit pending
   validation item, not a claimed pass.
6. The live legacy hook in the canonical shared checkout was not inspected,
   removed, or otherwise changed by this worker. Primary must perform the
   reviewed explicit deployment cleanup separately; old copies remain unsafe
   until that user-authorized action occurs.
