## Smallest complete in-scope fix

Keep the behavior in `crates/thegn-svc/src/ipc.rs` and preserve the existing `spawn_blocking` and `bind_lock` critical section:

1. On an initial failed Unix liveness connect, attempt `remove_file(&sock)`. Treat only `NotFound` as already cleaned up. Return every other unlink error with context naming the socket path and preserving the original I/O error; do not proceed to bind and do not report `AlreadyRunning`.
2. If bind returns `AddrInUse`, try connecting again to the same cloned `sock` while still inside the existing critical section. Return `AlreadyRunning` only on successful connection. If the probe fails, return the original bind error (or a contextual error retaining it); do not infer a live daemon from `AddrInUse` alone.
3. Do not broaden cleanup or move the probe/bind steps outside the lock. Preserve the endpoint path used throughout the decision. The existing race test must continue to show one winner, no winner unlinking, and successful reachability.

The code should avoid changing the Windows named-pipe behavior or the public `BindOutcome` API. A successful Unix `connect` is the liveness evidence available in this seam; this is not a protocol health handshake.

5. **Racing binders:** retain the existing eight-binder test and its endpoint reachability assertion to protect winner election and prevent unlinking a winner.
