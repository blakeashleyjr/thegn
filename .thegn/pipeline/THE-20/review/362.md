## Adversarial findings corrected

Commit `b93d0fd7` (`fix(the-20): close skill seeding failure paths`) fixes four
filesystem-edge defects found during this review:

1. `skills seed` accepted any directory containing an empty `.git` marker and
   then wrote harness assets into it. The target must now resolve through Git
   as the exact worktree root; an ordinary directory or fake `.git` marker is
   rejected before writes.
2. Layout survey failures and per-file write/remove failures were converted to
   diagnostics followed by exit status 0. They now remain best-effort across
   other targets but produce a nonzero result after the bounded pass.
3. When a previously managed/ignored skill became unmarked or user-modified,
   its old generated `info/exclude` entry remained and silently hid the user's
   file from `git status`. The exclude updater now removes those stale exact
   entries, preserves unrelated lines, and refuses a symlinked exclude file.
4. A failed `write_all` or `sync_all` left an incomplete temporary file behind.
   The atomic writer now removes its own temp file before returning the error.

Regression tests cover fake worktree markers, inaccessible layout roots, and
the managed-to-user-owned ignore transition.
