## Finding F1 — no-dot fractional-second directives bypass cadence protection (high)

Location: `crates/thegn-core/src/config.rs:68-79`, especially the match at
`70-77`; the rendering sink is `crates/thegn-host/src/detail/calendar/render.rs:430-442`.

`chrono` accepts `%3f`, `%6f`, and `%9f` as supported no-dot fractional-second
directives. They parse as `Item::Fixed(Fixed::Internal(_))`, but
`strftime_seconds_directive` only recognizes `Numeric::Nanosecond`, the public
`Fixed::Nanosecond*` forms, seconds, timestamps, and RFC formats. Consequently
these formats pass `validate_calendar`, remain non-empty through
`Config::post_process`, and reach `ClockFormat::Custom`; the renderer then
materializes sub-minute output while the existing world-clock refresh remains
minute-based. This violates the explicit “reject or normalize any
seconds/fractional-seconds format” criterion and is a user-configurable truth
failure, not merely missing coverage.

Regression coverage was added in
`crates/thegn-core/src/config_calendar_tests.rs:256-270` and
`crates/thegn-core/src/config_tests.rs:3618-3632` for `%3f` (and the strict
test also covers `%6f`/`%9f`). Those assertions are expected to fail until the
shared parsed detector recognizes the no-dot fractional forms and both strict
validation and tolerant normalization use that result. No production code was
changed in this review.
