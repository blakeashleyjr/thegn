## Evidence and production paths

- `docs/ARCHITECTURE.md:54-84` requires the event loop to block while idle and keeps blocking I/O and subprocess work off it. `docs/ARCHITECTURE.md:101-108` puts OS-specific process control in `crates/thegn-host/src/platform/`.
- `crates/thegn-host/src/notify.rs:80-105` constructs `SoundRuntime` and immediately starts a reload snapshot thread. `notify.rs:116-131` starts another reload on effective notification config replacement. `run.rs:7213-7218` creates the state; config reload reaches it through `run.rs:173-186` / `NotifyState::replace_cfg_and_push`.
- Notification producers reach `NotifyState::emit_sound` (`notify.rs:281-291`), which passes file/command requests to `notification_sound::emit` (`notification_sound.rs:314-316`). `enqueue` (`notification_sound.rs:107-142`) resolves file refs from the current snapshot and does a bounded `try_send` to a capacity-32 queue. Queue-full currently increments `dropped` and logs, but does not ring the fallback bell (`:128-137`).
- `ensure_worker` (`notification_sound.rs:144-187`) starts one serial worker. It calls `SoundPlayer::play` inline for files (`:157-170`) and `run_command` inline for command mode (`:172-180`). A wedged helper therefore blocks all later accepted jobs. The worker captures `Arc<SoundRuntime>` while the runtime retains its sender; the blocked `recv` loop forms a lifetime cycle, and there is no sound shutdown hook.
- `run_command` (`notification_sound.rs:298-312`) invokes `sh -c` with null stdin/stdout/stderr but waits via unbounded `.status()`. `Player::play` (`platform/sound.rs:113-124`) uses fixed argv and null stdio but also unbounded `.status()`. Neither establishes process-tree containment or a deadline.
- `SoundRuntime::reload` (`notification_sound.rs:78-105`) increments a generation and starts an untracked thread for every reload. Generation checks prevent stale publication, but do not limit concurrent snapshot builds or join/cancel them.
- `run.rs:1154-1170` explicitly shuts down the clipboard, desktop notification, resident, and process workers after the event loop; it does not shut down sound. The `NotifyState` owns the sound runtime (`notify.rs:43-46`), and the runtime's worker retains it.
- The sound documentation currently calls playback a “bounded off-loop worker” and says jobs may be dropped only when its queue is full (`docs/help/notifications.md:131-138`). It describes queue capacity, not playback duration or worker recovery.

## Failure cases and regression tests

The current failures are: a never-exit player or shell permanently blocks the single worker; a forked descendant survives direct-child timeout or shell exit; later jobs never run after a hang; queue-full rejection has no BEL fallback; reload storms create concurrent detached snapshot scans; shutdown has no cancellation/reap/join path. An exited parent is a separate process-group case from a still-running leader.

Add deterministic Unix fake-helper tests (temporary executable scripts/helpers, bounded waits, no Cargo invocation during this investigation):

1. A helper that exceeds the deadline is killed as a group and its direct child is reaped; assert the typed timeout result.
2. A helper forks a held grandchild, then either hangs or exits early; assert the grandchild/group is gone before the attempt settles and no zombie/direct child remains.
3. Queue a second successful fake sound behind a timed-out first helper; assert the worker processes it and timeout fallback is observable independently.
4. Fill the queue while a helper is blocked; assert producers return without blocking, pending memory stays within the fixed bound, and rejected work latches fallback.
5. Drive a reload storm with an instrumented snapshot builder; assert no more than one build runs at once, only the latest requested generation publishes, and pending work is constant-bounded.
6. Cancel/shut down during a hanging helper and pending reload; assert child tree cleanup, child reap, and worker/reload joins complete within the documented lifecycle bound.
