## Findings

Implemented the approved identifier-validation and target-construction scope. No design blocker was found. No related issue work was included.

- Added one canonical textual ID validator: positive ASCII decimal, no leading zero, at most 20 digits, and within `u64`. GitHub and GitLab provider JSON IDs are read directly as positive `u64` values; invalid run/job rows are discarded and counted. Targeted run responses with malformed or mismatched IDs return an error naming the observed value.
- Revalidated IDs at GitHub/GitLab provider boundaries and at CLI/control ingress before cache reads. Cache readers now validate run and log identifiers before reuse. Existing bare-array run caches remain readable; new cache entries persist discarded-row counts.
- GitHub commands now use validated argv builders, place options before `--`, and put workflow/run selectors after it. Workflow selectors use a separate printable name/path grammar; valid names with spaces and punctuation are preserved.
- GitLab remotes are parsed into an authority and plain path components. Ambiguous authorities, URL decorations, encoded paths, traversal, and malformed project components are rejected. Project paths are encoded as one API segment, branch refs are validated and form-encoded as one `ref` parameter, and `GITLAB_HOST` is bound to the remote/configured authority.
- Added explicit discarded-run counts to provider lists, the control response, the durable cache, and the CI panel note. Targeted run details carry discarded-job counts to the CLI and drill view.
- Updated the control API schema snapshot and added regression coverage for canonical IDs, malformed numeric JSON, discard counts, exact GitHub argv/GitLab endpoints, remote authority parsing, cache compatibility, CLI pre-cache rejection, control pre-cache rejection, and rejected target builders producing zero request constructions.
