## Failure cases to pin

- GitLab branch `feature&status=success` must serialize as exactly one `ref` parameter; likewise test `=`, `%`, `#`, and ordinary refs.
- Reject run/job IDs containing leading signs, leading-zero/noncanonical spellings, decimal/exponent JSON numbers or strings, leading option syntax, separators, `.`/`..`, encoded delimiters, fragments, controls, empty values, and over-limit length before any provider command/API request. Use one bounded unsigned decimal grammar for both GitLab numeric IDs and GitHub numeric IDs; use the identical validator for values parsed from provider JSON and values read from caches.
- Workflow selectors need their own supported grammar so valid workflow names and `.github/workflows/...` paths are preserved while option-like or control-bearing selectors are rejected.
- Parse Git remotes as SSH or URL authorities plus path components. Reject malformed/ambiguous authorities, traversal, controls, and ambiguous percent-encoding; encode project components for their path role and pin the final builder result to the parsed provider host/project/operation.
- Exact argv tests must prove options precede `--` where the CLI supports it and identifiers follow it. Validation remains required even with a terminator. Exercise run detail, logs, rerun, cancel, trigger, and branch-filter command builders.
- Invalid CLI/control inputs must not reach cache read or provider call; invalid cached/provider JSON identifiers must not be emitted or reused. A mutation must not return success for an option-like selector or a help-mode exit. Tests should assert constructed argv/URL and zero provider requests for rejected values, with no network or real mutation.

## Smallest complete implementation proposal

1. Add pure, provider-aware validators and pure builders in `thegn-svc::ci` (or a narrowly scoped sibling module). Keep numeric run/job/project identifiers typed through validation; provide an explicit workflow-selector/ref type rather than applying an ID grammar to those values. Preserve the existing provider-neutral public model shape only if every conversion into or out of that shape validates.
2. At the `GithubCi`/`GitlabCi` implementation boundary, validate again before every `run_cli`/`run_bounded_log` invocation. Replace hand-built GitLab query/path concatenation with structured query/component encoding and a strict remote authority/path parser. Build GitHub argv with options before `--` where supported, then positional selectors; do not rely on `--` instead of the validator.
3. Expose the same pure validators to `thegn-host` and apply them at command and control ingress before cache/provider work. Revalidate provider JSON when parsing, cached `CiRun`/job entries before return/reuse, and log-cache IDs before serving. On malformed cached/provider entries, fail closed or discard the invalid row; do not silently turn invalid identifiers into actionable strings.
4. Return an explicit validation error identifying the observed malformed component. Ensure mutation helpers propagate nonzero/error outcomes and never treat help/alternate-mode output as success.
