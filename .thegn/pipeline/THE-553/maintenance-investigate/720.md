## Evidence and failure cases

- `replay.rs:133–139`: `bytes_used` grows by `bytes.len()` only; `bytes.into()` creates one boxed payload per event, and each event also occupies a `VecDeque<Event>` slot.
- `replay.rs:146–155`: every resize appends an `Event` and calls eviction, but the current accounting sees zero bytes. At the captured source this permits arbitrarily many same-time resize events under even a 1-byte setting (matching the supplied audit evidence).
- `replay.rs:175–185`: eviction breaks before checking either budget whenever one event remains. A single oversized output event is consequently retained above `max_bytes`.
- `replay.rs:202–206`: keyframe entries whose event sequence is evicted are removed, but keyframes themselves are separately stored; vector/deque retained capacity is not measured by `bytes_used`.
- `replay.rs:577–598`: existing budget regression covers only a series of 16-byte payloads and asserts payload accounting `<= max_bytes`; it does not exercise resize floods or the single-final-event case.
- Edge cases relevant to the scoped implementation: same-timestamp floods; `max_bytes` zero or smaller than event overhead; one chunk much larger than the cap; repeated tiny chunks; eviction after retained resizes; duration zero (currently disables duration eviction at `:182–183`); and ordinary reconstruction/search/export after eviction. Truncating an arbitrary byte suffix can begin inside UTF-8 or an ANSI control sequence and loses parser context, so a truncation policy must explicitly document the resulting fidelity boundary. Dropping a chunk with a marker also changes reconstruction/export semantics and needs a defined marker representation.

## Smallest complete scoped fix proposal

In `crates/thegn-host/src/replay.rs`, add a documented fixed per-event accounting charge, applied uniformly to byte and resize events; include it in `bytes_used` at append and subtract it for every event removed. The comment should explain that this is a conservative logical charge for the stored event/collection slot and fixed allocation overhead, not a measured RSS guarantee. Preserve payload-byte accounting separately so arithmetic and tests remain clear. Make eviction continue until both byte and duration constraints hold even when only one event remains; if that last event cannot fit, remove it and leave the recording empty. Keep `evicted`, keyframe cleanup, and resize-to-baseline updates correct.

For an input chunk larger than the entire budget, select and document the lane-authorized behavior before coding. Preferred minimum-complexity contract: retain only the newest suffix that fits after the event overhead, when that overhead can fit; otherwise retain no event. Explicitly document that this tail can start mid-sequence and replay fidelity is bounded at that truncation/eviction boundary. If primary review considers suffix truncation unsafe, choose drop-with-marker instead and include the marker in the same accounting and replay/export semantics; do not leave an oversized singleton.

The scoped byte budget is not a proof of total process-memory/RSS bounds. Keyframe Vec allocation/capacity and VecDeque retained capacity are not directly measured by this charge; there is no aggregate coordinator across panes; and config reload only changes the config used by subsequently spawned recordings. Those broader requirements from the issue acceptance should be recorded as deferred follow-up scope rather than claimed solved here.
