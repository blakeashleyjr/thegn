## Changes

- Added a documented 64-byte logical charge for every retained event and keyframe marker. `bytes_used` now includes payload plus those slot charges; `payload_bytes_used` tracks payload separately. The code states that this is a logical budget, not an RSS guarantee, and excludes retained collection capacity.
- Applied and removed event charges for byte and resize events. Keyframe append and orphan cleanup now add and subtract marker charges.
- Removed the final-event eviction exemption. An event that cannot fit is removed, including its associated keyframe; resize eviction still advances the reconstruction baseline.
- Oversized byte chunks retain their newest suffix if the event and any due keyframe marker fit. The source comments document that truncation is a replay fidelity boundary and cannot restore parser/grid context preceding it.
- Added regressions for a same-timestamp resize flood, oversized-chunk suffix retention, marker charge/release, eviction to empty under a zero budget, and duration-zero behavior. The existing byte eviction regression now also checks total logical accounting.

## Deferred acceptance and limitations

Per the primary plan, this artifact does not implement process-wide/RSS bounds, an independent event-count limit, resize coalescing, aggregate budgets across live panes, applying lowered budgets to existing recordings, snapshots, VecDeque/Vec capacity retention, or THE-555 search work. Fixed per-entry accounting bounds the logical sum charged by the recorder; it does not bound allocator capacity or total process memory. Retained-front eviction and chunk truncation can lose parser/grid context, as documented in the source.
