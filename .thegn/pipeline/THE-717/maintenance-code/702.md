# Dispatch 702 — THE-717 implementation

Verdict: implementation-ready

## Implemented

- Added a Linux `strace -f -qq --seccomp-bpf -ttt -e trace=execve` spawn-rate
  measurement for `soak` and `soak-daemon`. Traces begin with each real thegn
  root, while existing procfs metrics continue to sample the actual UI PID.
  `soak-daemon` traces both the UI process tree and its separately launched
  daemon tree.
- The count window starts immediately after the existing adaptive settle and
  resource/thread baselines, and ends at the end of the existing idle window.
  Timestamp filtering excludes launch/setup, settle sampling, tracer startup,
  and cleanup events. The fixed `SPAWN_RATE_CEILING=0` is not baseline-derived
  and has no CLI override.
- Added fail-closed handling for absent strace, target/tracer exit before the
  window ends, empty/malformed traces, and missing timestamps. No `/proc`
  fallback is used. macOS reports `unsupported` in text and JSON, never zero.
- JSON adds `spawn_rate` with status, method, count, ceiling, grouped/sorted
  offender entries (`argv[0]` basename plus its first three arguments), and
  trace-root count. Text output prints the same offenders and a ceiling
  failure names the observed count.
- Added `test/perf/lib/spawn-trace.py` with canned parser fixtures and a
  `--self-test` entry point. Added Linux `strace` to `devShells.default` and
  documented the new axis and THE-706/THE-716 motivation in `CLAUDE.md`.
  Re-enter `nix develop` for the new shell dependency to appear.
