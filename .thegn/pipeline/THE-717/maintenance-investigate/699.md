## Smallest complete fix proposal (no production edits made)

1. Extend only `test/perf/cpu-sample.sh` with a fixed, non-CLI-overridable `SPAWN_RATE_CEILING=0` constant and an explicit spawn-rate measurement result. Scope it to `soak` and `soak-daemon`, release runs, and the post-adaptive-settle idle window. Do not baseline-derive it and do not add an allowance for current OCI behavior.
2. Prefer strace tracing from process launch, with `-f -qq --seccomp-bpf -e trace=execve`, and retain timestamps so only events between the post-settle window start and end count. Tracing must include the UI process tree and the separately started daemon process tree in `soak-daemon`; derive a stable count window after both trace roots start, while ignoring startup and shutdown records. The harness must continue sampling the actual thegn process rather than accidentally measuring the strace wrapper. Emit grouped offender keys using argv[0] and the first arguments plus counts; on failure name commands such as `podman ps --format json` and `docker ps --format '{{json .}}`.
3. If exact tracing is unavailable on supported Linux runs, fail clearly or use a distinctly labelled `/proc` polling fallback that explicitly reports it is a lower bound and can miss short-lived processes. Never describe polling as exact. Make the tracer backend/method visible in output/JSON. macOS behavior needs the platform decision above.
4. Add `strace` to `devShells.default` in `flake.nix`, Linux-guarded, and mention the re-evaluation requirement in the implementation notes. Update the existing `CLAUDE.md` perf-suite paragraph at lines 98-108 to list spawn rate next to zombies/fds/threads/read syscalls. Leave `justfile` wiring unchanged unless an actual recipe mismatch is found: both commands already invoke the relevant scenario.
5. Keep state isolated using the existing `perf_make_tmp` environment. No production modules or production call sites need edits for this gate.

## Regression cases and failure modes

- Parser/counting fixture: events before settle and after window end are ignored; multiple exact `execve` lines for one argv key aggregate; distinct argv keys remain separate; empty idle interval reports zero.
- Ceiling control: an in-window `true` (or equivalent synthetic command) produces nonzero count, exits 2, and prints offender plus count; no in-window calls passes with the fixed zero ceiling. The ceiling must not be user-overridable or learned from a baseline.
- Scenario coverage: verify both `soak` and `soak-daemon` include the UI; verify `soak-daemon` also includes a process started by the explicit daemon launcher. Ensure startup setup, adaptive-settle calls, tracer commands, and cleanup are not counted as idle-workload execs.
- End-to-end proof required by the issue: once THE-716 lands, run both soak commands against the fixed tree and a controlled regression build that starts `true` each idle tick; both should pass fixed and fail injected with a useful offender report. If THE-716 has not landed, preserve that dependency and expect the current OCI behavior to fail rather than seed an allowance.
- Run `shellcheck test/perf/cpu-sample.sh` and the narrowly scoped spawn-counter/parser tests. Do not run Cargo/build/full-workspace tests during this investigation. Implementation-stage integration runs should be scheduled under the primary's CPU policy.

Failure cases the implementation must handle explicitly: missing `strace`; unsupported OS; tracer startup/exit failure; trace output malformed or empty; trace window timestamps unavailable; daemon absent in `soak-daemon` (the existing resource check already fails this); thegn exiting before the full window; and process-tree events from the separate daemon launcher being omitted. A missing/incomplete trace must never pass as zero spawns.
