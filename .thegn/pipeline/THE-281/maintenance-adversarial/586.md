## Findings

No source-level revisions are required.

- `crates/thegn-svc/src/control/client.rs:1195-1201` now formats the typed
  `Url::host()` value. The pinned `url 2.5.8` `Host` formatter emits exactly
  one bracket pair for IPv6 and leaves DNS/IPv4 hosts unbracketed.
- `crates/thegn-svc/src/control/client.rs:1198-1201` retains `Url::port()`;
  in the pinned dependency this is the explicit, non-default port, so HTTP 80
  and HTTPS 443 are omitted while non-default ports are retained. The derived
  WS/WSS scheme has the same corresponding default-port rule.
- `subscribe_events_opts` (`client.rs:796-856`) and `attach_opts`
  (`client.rs:892-963`) both use the corrected helper for the `Host` header
  and `websocket_url` for the URI. No alternate remote upgrade path or
  string-heuristic bypass remains in the searched source.
- The helper is pure and performs no shared mutation, spawning, I/O, or
  unbounded allocation. No race or resource-growth issue was found.
- The focused matrix now asserts exact authority, unary URL, and derived
  WebSocket URL values for IPv6, IPv4, and DNS, including HTTP and HTTPS,
  absent/default/non-default ports (`client.rs:1661-1745`). The added HTTP
  IPv6 cases close the only matrix gap found during review.
- Scoped IPv6 is intentionally not a supported input at `url 2.5.8`; the
  rejection assertion at `client.rs:1747-1750` matches the primary plan and
  prevents silent behavior drift if the dependency changes. Direct `ws://` or
  `wss://` input remains outside the pre-existing `HttpOrigin` contract;
  accepted HTTP(S) origins generate WS/WSS URLs, so this is not a source
  revision for this issue.
