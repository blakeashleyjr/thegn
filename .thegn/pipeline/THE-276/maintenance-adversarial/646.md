## Finding

- **Medium — `EventDecoder` still has quadratic copying under fragmented input.** In `crates/thegn-core/src/control_wire.rs:565-575`, every `push` with a nonzero consumed cursor calls `Vec::drain(..cursor)`. If a complete short frame is followed by a large incomplete frame delivered in small chunks, each push shifts the growing partial tail. For an input of size N split into small chunks this copies O(N²/chunk_size) bytes, so the acceptance requirement for linear decoder work is not met by the reusable streaming decoder. The current WebSocket paths call `decode_message` once per already-bounded message, so this pattern is not currently driven by remote WebSocket traffic; it remains a complexity defect in the public core streaming API and should be fixed before claiming the decoder criterion.
