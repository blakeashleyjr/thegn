# THE-276 dispatch 638 implementation report

Verdict: implementation-ready

## Changes

- Added a core maximum encoded frame size of `MAX_WIRE_PAYLOAD + 5` and an exact-one-frame WebSocket message decoder. It rejects empty input, truncated frames, declared payloads over cap, oversized messages, trailing bytes, and concatenated frames with typed errors.
- Changed `EventDecoder` to track a consumed cursor and compact only on the next push, preserving arbitrary chunk boundaries without shifting the remaining buffer for each decoded frame.
- Configured both tungstenite limits at all six connection sites: event subscription and pane attach over Unix, TCP, and HTTP(S). `Cargo.lock` pins tungstenite 0.29.0. Its `max_frame_size` checks the frame payload length before reserving it; `max_message_size` checks the reassembled message payload. Both exclude WebSocket framing headers, so the control frame cap includes the inner five-byte control header.
- Bootstrap now requires one valid `Hello`, checks its protocol version, starts the stream pump, then forwards only that validated greeting. The pump uses the same exact-one-frame decoder for all subsequent event and pane messages.
- Added deterministic regressions for clean one-frame messages, empty/truncated/oversized messages, trailing bytes, concatenated frames, the 257-frame greeting burst, one-byte-at-a-time streaming, and fragmented WebSocket binary frame reassembly.
