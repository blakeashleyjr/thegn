# THE-23 row 410 completion

Implemented architect revision 1, keeping the devcontainer CLI provider inside
the sandbox trust boundary.

## Delivered

- Added a conservative provider-capability predicate. The CLI provider is now
  considered only when sandboxing is enabled, the backend remains auto, the
  effective profile is open, networking is ordinary NAT without allow/block
  filters, no VPN or isolation floor is requested, file access is workspace
  scoped, and no per-pane CPU/memory ceiling would be lost. Other policies use
  the existing native OCI resolver.
- Preserved trusted image/build/compose precedence by making a devcontainer
  provider ineligible when those source fields were already pinned by user
  configuration before the repo overlay.
- Cleared the environment for `devcontainer up`, restoring only safe runtime
  variables and the effective `sandbox.env_passthrough` values. The provider
  session carries that same explicit list into host-side `exec` panes through
  the existing PTY environment firewall.
- Added focused capability and fake-provider environment tests, including a
  proof that an arbitrary host variable is not visible during `up`.
