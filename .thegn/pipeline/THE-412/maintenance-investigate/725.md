## Failure cases / scope decisions

- Thread creation returns `io::Error`: currently `.expect` unwinds through lazy Observe construction. Desired scoped behavior is a typed construction error propagated into `SlotState::Failed`, with a visible warning/reason and no panic.
- Idle worker is in its one-second sleep when source ownership ends: current stop flag does not wake it; source returns before worker exit. Desired behavior is wake + join before source destruction completes.
- Worker is in `StatsSampler::sample()` when stop is requested: an interruptible wait cannot interrupt that call. `Drop` must still check cancellation before publication where practical and join after the sample finishes. Thus the prompt shutdown bound depends on `StatsSampler::sample()` duration; source inspection did not establish a hard upper bound for it.
- Poisoned ring lock currently silently skips appending; `now_secs()` maps clock-before-epoch to `0.0`. Neither is part of the scoped defect and should remain unchanged absent primary direction.
- Full issue text also mentions generation tokens, strict shutdown outcome, cancellation of hung query tasks, lock poisoning/sampler panic/clock-failure tests, and supervisor sharing. The primary-reviewed coordination scope explicitly narrows this lane to owning/joining the sampler, interruptible stop, non-panicking spawn failure, and a prompt idle-drop regression test; it explicitly excludes THE-187 logic. Do not expand into query-engine cancellation, shared metrics supervision, or THE-187 without primary review. The detached-engine retention is an unresolved broader lifecycle dependency: this scoped fix cannot promise HostSource destruction while a remote query is hung.

## Smallest complete scoped fix

- In `gtui-query/src/host.rs`, make construction fallible (`try_new`/`Result` with a typed spawn error), retain the `JoinHandle`, and replace the fixed sleep with an interruptible wait. A `park_timeout(1s)` worker plus `Thread::unpark()` on stop is a small fit: preserve the existing 1 Hz cadence, avoid another crate/thread/channel, and wake an idle worker promptly. Keep `StatsSampler::sample()` off the UI and runtime threads. On drop, request stop, unpark, and join; decide/report the impossible-to-join panic outcome without silently detaching. Check stop before publishing a completed sample, with join completion as the definitive cancellation acknowledgement.
- Propagate construction failure through `ObserveTile::new` and `build_observe_tile` into the existing `SlotState::Failed(String)` path in app registry/slot construction. Add a warning/user-facing failure reason; do not catch a panic as the normal failure path. Keep the actual work scoped to Observe construction and the builder API; do not modify host metrics sampling semantics or THE-187 range selection.
