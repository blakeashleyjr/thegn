# Dispatch 573 — THE-288 implementation

Verdict: implementation-ready

## Implemented

- Replaced detached copy-per-request threads with one named clipboard worker.
- Enforced a 1 MiB byte cap with refusal rather than truncation.
- Added a depth-one latest-wins queue; replacing pending or active work cancels
  the older request without emitting a stale failure.
- Added 2 s spawn/write, 5 s helper-exit, and 10 s whole-operation deadlines.
- Added Unix process-group cleanup on timeout, replacement, fallback, and
  shutdown; the direct child is reaped after group termination.
- Added a clipboard-specific platform spawn seam. Windows intentionally keeps
  the existing direct-child behavior pending THE-274; no new Job Object
  implementation was added in this issue.
- Added content-free asynchronous success/failure outcomes to the event loop.
  Callers now report pending work and no longer claim success at thread spawn.
  Clipboard payloads and helper output are absent from diagnostics/status text.
- Added focused regression coverage for oversized refusal, non-zero helper
  fallback behavior, and cancellation of a helper that does not read stdin.
