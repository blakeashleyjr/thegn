## Bug status and exact evidence

The audited defect is still present, with current line numbers:

- `crates/thegn-host/src/clipboard.rs:41-55` documents copy as fire-and-forget,
  converts the complete borrowed text with `text.to_string()` at line 47, and
  starts a new detached `std::thread::spawn` at line 48 for every copy.
- `clipboard.rs:49-53` tries every detected candidate serially on that detached
  thread. A failed candidate can therefore add another unbounded wait to the
  same copy operation.
- `clipboard.rs:192-215` implements `pipe_to`: it calls `Command::new(...)
.spawn()` at lines 201-206, writes the complete payload with blocking
  `stdin.write_all(text.as_bytes())` at line 211, drops stdin, and calls
  blocking `child.wait()` at line 214. There is no startup, write, exit, or
  shutdown deadline, no cancellation flag, no process group, and no tree kill.
- `pipe_to` has no retained child/group handle after it returns, so a helper
  that forks a descendant cannot be cancelled as a tree. A helper that never
  reads stdin can block the detached thread in `write_all`; a helper that reads
  but never exits can block it in `wait`.
- There is no queue or byte admission at the copy boundary. A burst creates one
  OS thread and one full `String` per call. The worker is not owned by the
  application lifecycle, so shutdown cannot request or join it.
- Existing tests at `clipboard.rs:247-259` only cover success/nonzero exit and
  an unspawnable command. They do not exercise a blocked write, blocked exit,
  descendants, cancellation, shutdown, queue capacity, payload cap, or async
  result delivery.

The issue’s stale audit citations therefore remain materially accurate even
though their line numbers moved.

## Smallest complete scoped fix

1. Replace the public fire-and-forget copy function with an owned
   `ClipboardWorker`/cheap clonable submit handle. Start exactly one worker for
   the interactive session, with a fixed-capacity queue of one. Document the
   policy in the code: a clipboard has one current value, so a pending older
   copy is discarded in favor of the latest request. Keep at most one bounded
   in-flight helper and one bounded request payload; reject a request above a
   fixed internal byte cap before cloning/enqueuing it. A fixed cap (recommended
   1 MiB unless the primary chooses another existing product limit) avoids
   adding a new user-facing feature/config key.
2. Give each request a monotonically increasing generation. On replacement or
   shutdown, signal cancellation, kill the owned helper tree, close stdin, and
   reap the direct child before accepting/finishing the next request. Ignore
   stale completion notifications from superseded generations.
3. Implement explicit budgets for the helper attempt: a startup/pre-write
   deadline, a bounded stdin-write phase, and a bounded exit phase. Do not use
   `write_all` plus `wait` on the worker without a deadline. The write phase
   needs a cancellable/nonblocking platform-safe strategy (or one fixed writer
   operation whose child-group cancellation closes the pipe); a same-thread
   blocking write is not an acceptable implementation. Treat any timeout,
   write error, nonzero exit, or failed spawn as failure and advance to the
   next candidate only within the overall bounded request budget.
4. Put the Unix helper in the existing process-group seam before exec and use
   the group handle for timeout, replacement, and shutdown kill followed by
   direct-child reap. Keep Windows on the current direct-child/deadline scope;
   do not add or broaden Job Object containment in THE-288. Record THE-274 as
   the explicit follow-up needed before Windows can claim whole-tree cleanup.
5. Send only a content-free result through the existing event-loop channel and
   pulse the `TerminalWaker`: generic success (`Clipboard copied`) or failure
   (`Clipboard copy failed`/`Clipboard helper timed out`). Do not log, trace, or
   include the copied value, a prefix, a redacted value, or the URL in the
   result. Remove the four optimistic success surfaces and the URL-bearing
   Share/Forward status; they must no longer report success before the worker
   outcome. Passing the worker handle through `CiActionCtx` and the help-overlay
   key/link paths is preferable to a process-global singleton.
6. Retain the existing candidate order and fallback semantics. Keep OSC 52 and
   default-register writes as separate existing behavior. Shutdown must request
   the worker stop and join it within the application cleanup deadline before
   the terminal is restored.

Likely implementation files are `crates/thegn-host/src/clipboard.rs` and its
unit tests, `crates/thegn-host/src/run.rs`, `actions.rs`, and
`help/overlay.rs`, plus a narrow platform seam change only if the existing
group handle does not expose the exact clipboard ownership/Windows-degraded
operation needed. No config, paste, image-paste, terminal-write, or THE-152
changes are required.

## Failure cases the implementation must close

- Repeated copy bursts: one worker thread, one pending latest request, and a
  fixed maximum retained payload; no thread-per-copy or unbounded queue.
- Helper never reads stdin: write phase reaches its deadline, helper group is
  killed, direct child is reaped, and the worker reports failure promptly.
- Helper reads stdin but never exits: exit deadline kills/reaps the group and
  reports failure; fallback attempts remain bounded.
- Helper forks a descendant that holds the pipe or continues after the leader
  exits: Unix group kill occurs before joining/retiring ownership, and the
  descendant is gone; Windows remains explicitly covered only after THE-274.
- Copy replacement while a helper is active: the old generation is cancelled
  and cannot publish a stale success/failure; the latest request is the only
  retained pending value.
- Shutdown during spawn/write/wait: stop is idempotent, active helper is
  cancelled/reaped, worker joins, and no clipboard helper remains owned by the
  process.
- Missing helper, nonzero helper, EPIPE, oversized request, or closed result
  channel: no panic, no payload diagnostic, bounded cleanup, and a content-free
  failure outcome where the UI is still alive.

## Ordered implementation and regression-test plan

1. Confirm the primary’s chosen fixed byte cap and per-phase/overall deadline
   constants; preserve the existing helper candidate order. Reuse/extend the
   host platform seam without duplicating process-group syscalls.
2. Implement the single worker, latest-wins queue, generation/cancellation
   state, admission cap, and owned child lifecycle in `clipboard.rs`; keep the
   existing pure candidate tests.
3. Wire worker creation, result delivery, waker pulse, and shutdown/join into
   `run.rs`; route all copy call sites through the handle and remove optimistic
   or content-bearing success statuses. Do not alter OSC 52/register semantics.
4. Add focused unit tests for queue capacity/latest-wins, byte rejection without
   retaining the input, generation suppression, candidate fallback, and
   content-free success/failure messages.
5. Add Unix process integration regressions using a controlled helper fixture:
   non-reading stdin times out; a never-exiting helper times out; a forked
   descendant is killed/reaped; replacement kills the prior generation; and
   worker shutdown leaves no helper/descendant. Assert elapsed time against a
   generous test bound, not an exact scheduler duration.
6. Add the platform-appropriate Windows direct-child deadline regression and a
   test/documentation assertion that whole-tree containment is not claimed
   until THE-274 lands. Do not add a false Windows descendant guarantee here.
7. After primary greenlight and implementation, run only the focused host
   checks/tests authorized by the primary and the touched tests first; the
   primary owns broader validation. This investigation intentionally ran none.
