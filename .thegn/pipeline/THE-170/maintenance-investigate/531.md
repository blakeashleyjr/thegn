finds exactly three sites:

## Smallest complete fix

1. In `thegn-svc::plugin::PluginIssueBackend`, replace the leaked identity
   field with `Arc<str>` initialized from `plugin:<id>`. Change the public
   `IssueBackend::provider_id` contract from `&'static str` to `&str`, and
   return a borrow from the adapter. Update built-in implementations, test
   doubles, `IssueRouter::provider_id`, `provider_ids`, and
   `list_per_provider` to carry borrows tied to `self`. This preserves static
   literals for built-ins, avoids per-call cloning, and lets adapter/router
   drops release dynamic identities. `Arc<str>` leaves a cheap safe sharing
   option for any future router/async ownership without a registry or
   interning map.
2. Replace `ForgeError::NotConfigured(&'static str)` with an owned-capable
   payload. Preferred shape for review: `Cow<'static, str>` so existing
   literal diagnostics remain borrowed while the runtime-build message is
   owned; `Arc<str>` is an equivalent fallback if the primary prefers uniform
   sharing. Convert all constructors in the eight inventoried files and keep
   `describe`, `SeamError::class`, ladder fall-through, panel matches, and
   retry classification behavior unchanged. In particular, the `graphql`
   runtime error must move its formatted string into the owned variant.
3. Update the stale host comment and keep the test-only `test_lane` leak
   unchanged with its existing rationale.

No global mutable string registry, interning map, generation tag, or new
feature is needed.
