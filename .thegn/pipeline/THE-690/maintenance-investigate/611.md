coordination brief identifies this as the fifth blocker after THE-685 through

## Current-branch verdict: bug confirmed

The bug remains on this exact branch, unchanged from the primary citation:

- `merge_cleanup.rs:94-104` (`LocalResources::revalidate`) calls
  `oci_resources_absent` after the registry, bridge, session, tenancy, and
  dispatch guards.
- `merge_cleanup.rs:108-130` only bounds and scans `PATH`.
- At `:119-127`, the first filesystem entry matching any backend binary from
  `Backend::all_oci()` immediately returns
  `OCI runtime discoverable; historical resource ownership requires explicit
cleanup`. There is no runtime invocation, container enumeration, mount
  inspection, or worktree-path comparison.
- A bounded absolute PATH with no candidate binaries returns `Ok(())`, but a
  machine with an unrelated `docker` or `podman` file always refuses before it
  can inspect whether a container references the worktree.

This confirms the primary's measured environment fact: Docker and Podman are
present in `/run/current-system/sw/bin`, while the two observed containers
(`cms-garage-1` and `cms-postgres-1`) have no mount for any kept worktree. The
refusal is therefore caused by binary presence, not custody.

This is the third occurrence of the same design error in the sweep chain:
THE-687 used missing cache data, THE-688 used a persisted layout row, and
THE-690 uses an installed executable as a permanent refusal. Each proxy stands
in for the real ownership question. No fourth instance was found in the
reviewed call path; the existing `has_cleanup_tenancy` and
`has_cleanup_dispatch` predicates are explicitly out of scope and do inspect
their intended registries.

## Production call paths and prerequisites

The automatic removal path is:

```text
CLI: cmd/merge.rs::sweep
  -> merge_sweep::sweep
  -> sweep_with_db (landed + target + TTL/--force selection)
  -> merge_lifecycle::remove_landed_with_config
  -> LocalResources::settle
  -> LocalResources::revalidate

  -> destroy_one_checked / Verified::remove_checked
```

The same cleanup logic is reached by the UI `sweep-merged` action and by the
startup/post-fold sweep. `merge_sweep::spawn` (lines 355-362) uses
`tokio::task::spawn_blocking`; the UI action dispatches that function from
`handlers/merge_queue.rs:236-253`. The CI refresh background lane also calls
the sweep from `ci_refresh.rs:167-170`. The CLI is already outside the UI
event loop. Thus the runtime query must remain inside this existing blocking
cleanup path and must not be moved into an event-loop handler.

Prerequisites that must remain intact before the OCI check:

- local/unmanaged environment admission in `LocalResources::settle`;
- all existing agent, bridge, session, tenancy, and dispatch guards;
- `Verified::probe`'s canonical worktree, Git identity, ancestry, and clean
  status checks;
- the final revalidation and non-forced `git worktree remove` backstop;
- TTL selection, landed identity backfill, layout teardown, branch-retention
  holds, and `--force` semantics. `--force` may bypass only the TTL clock.

`crates/thegn-host/clippy.toml:15-29` bans synchronous child waits in the host
outside sanctioned off-loop sites. Any new runtime subprocess must use the
existing bounded capability-capture seam (or an equivalent locally justified
off-loop pattern) with an explicit timeout and byte cap. A hung daemon,
permission failure, nonzero query, malformed output, or output overflow is an
unknown ownership state and must refuse with wording that says the runtime
could not be queried.

## Smallest complete fix

Keep the change at the `merge_cleanup` admission boundary. Do not refactor the
four earlier fixes or introduce a new ownership feature.

1. Replace the current PATH-only `oci_resources_absent` behavior with a
   bounded runtime ownership probe. Keep the existing bounded PATH validation,
   deduplicate the `podman` rootless/rootful entries that name the same binary,
   and discover only candidate runtime executables. If no OCI runtime is
   discoverable, return `Ok(())` exactly as the current no-runtime case does.
2. For each supported discovered Docker/Podman executable, enumerate all
   containers, including stopped containers (`ps -a -q`), then make one
   bounded inspect query for the returned IDs using a mount-source-only format.
   Do not issue one inspect process per container. Use the existing capability
   capture path with an explicit sub-two-second timeout and output cap no
   larger than its 16 KiB policy; reject a truncated or otherwise malformed
   response rather than treating it as empty.
3. Canonicalize the target worktree path before comparison. Canonicalize each
   nonempty mount source and refuse when it equals the target or is at/under
   the target (`source.starts_with(target)` as a path-component comparison),
   so a subdirectory bind also blocks deletion. A symlinked or relative source
   must be resolved before comparison; if it cannot be canonicalized, treat it
   as a match/unknown and refuse rather than letting it pass as unrelated.
4. Preserve fail-closed behavior for a discovered runtime that cannot be
   spawned, is unavailable, times out, denies access, exits unsuccessfully, or
   produces unparseable/over-cap output. The refusal should name that the OCI
   runtime could not be **queried**, distinguishing genuine unknown custody
   from mere installation.
5. Treat a successfully queried runtime with no matching mount as absent
   ownership and let the existing cleanup continue. Do not alter
   `--force`; the same admission guard must run in both force and ordinary
   sweeps.

The minimal production surface is expected to be
`crates/thegn-host/src/merge_cleanup.rs`. Existing pure management argv helpers
in `crates/thegn-core/src/sandbox_manage.rs` cover listing but do not currently
provide a mount-source inspect builder. Adding a core API is unnecessary for
the narrow fix unless the primary elects to centralize the Docker/Podman
dialect; vendor command construction should not spread beyond the chosen
runtime-probe implementation boundary.

One design dependency needs primary confirmation: `Backend::all_oci()` also
names reserved/unverified OCI-like binaries beyond Docker and Podman. A
discoverable unsupported dialect must not be silently ignored; either add its
known read-only query form in the same probe or classify it as
"could not be queried" and refuse. The acceptance data specifically requires
Docker and Podman, so the smallest safe implementation can support those two
formats and fail closed for any other discovered OCI candidate.

## Regression-test plan

Add focused tests beside the existing cleanup/runtime tests, using a temporary
fake executable directory and the test environment guard. The fake `git`/`sh`
links keep fixtures hermetic; a fake Docker/Podman script supplies deterministic
`ps` and `inspect` responses. Do not depend on whether a real runtime is
installed on the host. Keep these tests under nextest because `TestIsolation`
mutates process-global environment.

The required matrix is four custody states × both `force` values:

| injected runtime result                                                               | ordinary sweep                           | `--force` sweep                    |
| ------------------------------------------------------------------------------------- | ---------------------------------------- | ---------------------------------- |
| no runtime discoverable                                                               | due clean merged worktree is collected   | clean merged worktree is collected |
| runtime present, unrelated container/mount                                            | collected                                | collected                          |
| runtime present, exact or descendant worktree mount (running or stopped)              | kept with custody refusal                | kept with custody refusal          |
| runtime present but unqueryable (exit failure, timeout, or over-cap/malformed output) | kept with “could not be queried” refusal | kept with same refusal             |

Also include focused parser/path cases for an exact source, a source under the
worktree, a symlinked source that canonicalizes under it, a relative source,
and a source that cannot canonicalize. Assert that an uncanonicalizable source
is conservative (kept), not a miss. Assert that `ps -a -q`/inspect observes a
stopped-container fixture, not just a running one, and that a runtime query is
bounded rather than waiting for a sleeping fake forever.

The full sweep fixtures should assert both physical preservation/collection and
report vocabulary. In particular, they must distinguish a real mount refusal
from an unqueryable-runtime refusal and confirm that no queue/cache/bookkeeping
mutation occurs when admission is refused. Existing dirty/ignored/force tests
remain the coverage for the unrelated cleanup protections.

Review `test/smoke.sh` around lines 770-875. Its `sweep_fixture` currently
constructs `sweep-bin` with only `git` and `sh` at lines 825-833 specifically to
hide installed OCI tools. After the probe fix, remove that workaround and run
the sweep with a deterministic fake runtime/no-runtime PATH, or retain it only
with a comment explaining that it deliberately tests the no-runtime branch.
The smoke case must still exercise the real end-to-end sweep and preserve its
existing assertions for non-ignored edits, ignored build-state collection, the
retained branch, and the cleanup hold. Do not allow the workaround to mask the
Docker/Podman-installed acceptance case.
