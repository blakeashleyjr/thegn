# THE-690 maintenance implementation — native dispatch row 612

Implemented the primary-approved Docker/Podman ownership probe on
`blake/the-690-oci-ownership-probe`. The source review is clear, but the Rust
code is not compiled in this dispatch because the task explicitly prohibits

central validation. No full gate is claimed.

## Scope implemented

- Replaced PATH-only OCI binary refusal at the `merge_cleanup` admission
  boundary with a bounded Docker/Podman probe.
- Enumerates stopped and running containers with one `ps -a -q` call and uses
  one batched `inspect --format` call per discovered runtime.
- Deduplicates the rootless/rootful Podman entries by executable name.
- Uses the existing capability capture lane with a five-second per-command
  timeout and 16 KiB output limit. Timeout refusals say that the runtime timed
  out and include the five-second budget.
- Rejects nonzero, malformed, truncated, non-UTF-8, and over-cap responses as
  `could not be queried`; discovered reserved/unknown OCI binaries are named
  in a fail-closed refusal.
- Canonicalizes the target and mount sources, treats exact/descendant
  component matches as owned, rejects string-prefix false positives such as
  `/worktree-copy`, and treats an uncanonicalizable source as owned.
- Leaves all existing tenancy, dispatch, session, cleanliness, TTL, branch,
  layout, hold, and `--force` behavior unchanged; `--force` still runs the
  same admission probe.
- Added deterministic focused tests for no runtime, Docker allow/deny and
  malformed behavior, reserved runtime refusal, Podman deduplication, parser
  truncation, canonical symlink/relative/unreadable sources, and path-component
  boundaries.
- Extended `test/smoke.sh` with a hermetic Docker shim covering unrelated
  mounts (swept), worktree/subdirectory mounts (kept with and without
  `--force`), nonzero/garbage/timeout queries (kept with query refusal), while
  retaining the minimal `git`+`sh` PATH as the deliberate no-runtime case.
