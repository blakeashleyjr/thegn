# THE-198 implementation — native dispatch row 598

## Verdict

**Revisions-needed.** The implementable portion is committed: the RSA advisory
exception now carries structured owner/review metadata and exact `rsa 0.9.10`
reachability evidence, and a dependency-free regression guard pins that
policy and lockfile chain. The complete primary plan remains blocked by
cargo-deny's configuration model ([advisory ignore configuration](https://embarkstudios.github.io/cargo-deny/checks/advisories/cfg.html)):
advisory ignores are keyed only by advisory ID, so the tool cannot enforce an ignore scoped to both
`RUSTSEC-2023-0071` and `rsa@0.9.10`. A package spec in
`advisories.ignore` is interpreted as a yanked-package exception, not an
advisory exception. I did not silently use that incorrect syntax.

## Changes

- `deny.toml` replaces the bare advisory string with a structured advisory
  entry. Its reason names the exact resolved package/version, owner, review
  triggers, RustSec link, and the accepted reachability argument:
  `octocrab 0.54.1 -> jsonwebtoken 10.4.0 -> rsa 0.9.10` is linked, but the
  application constructs octocrab with a personal bearer token only; no
  AppAuth/private-key signing call site was found.
- `test/the-198-rsa-policy.sh` parses `deny.toml` and `Cargo.lock` with Python's
  stdlib TOML parser. It fails if the exception loses its structured metadata,
  if a bare advisory-wide entry returns, or if the reviewed exact dependency
  chain changes.
- No octocrab, jsonwebtoken, RSA, native forge ladder, or production auth code
  was removed or changed. THE-670 remains the follow-up for replacing octocrab
  and retiring this exception entirely.

## Reachability evidence and trust boundary

The resolved lockfile records:

```text
octocrab 0.54.1 -> jsonwebtoken 10.4.0 -> rsa 0.9.10
```

The service's native GitHub path is selected by the default forge ladder in
`crates/thegn-svc/src/forge/mod.rs` and reaches
`crates/thegn-svc/src/forge/native.rs`. Its client construction uses
`.personal_token(token)`, where the token comes from `GH_TOKEN`,
`GITHUB_TOKEN`, or the existing `gh auth token` CLI path. The same native
implementation gates the live request to local worktrees and public GitHub
origins before making the GraphQL call. No application call site constructs
`AppAuth`, `EncodingKey`, `create_jwt`, or another RSA private-key operation;
the linked private-key implementation is dependency code that is not invoked.
Existing native regression coverage also verifies that remote/foreign origins
are rejected before credential admission.

This is an operator/local credential boundary, not a claim that the linked RSA
code is safe. The exception is accepted only for the reviewed exact graph and
expires for a patched RSA release or when THE-670 replaces octocrab.

## Concrete blocker

The primary acceptance criterion requiring a package/version-scoped cargo-deny
ignore cannot be represented by the supported cargo-deny schema. The current
structured entry is still advisory-ID scoped at tool level, with exact package
and version constrained in its reviewed reason and regression guard. A primary
revision must either accept that formally documented limitation, adopt a
supported policy/tooling mechanism that truly scopes the advisory, or approve
removing the RSA feature/dependency (which is outside this plan's explicit
instruction to retain octocrab and the ladder).
