## Finding

The bug remains on this exact branch. `wt new` accepts `--folder`, but when it is omitted both creation paths pass `None` to the shared creation helper, which then skips filing. The `Config` schema has no `default_folder` field, its default/overlay machinery has no corresponding value, and there is no validation for an empty or whitespace-only configured default.

The smallest complete design is a plain top-level config key, `default_folder`, next to `branch_prefix` and other root-level worktree creation defaults. Represent it as `Option<String>`: omitted means no automatic folder, while an explicitly supplied empty string remains distinguishable and can be rejected by strict config validation. Resolve the effective folder once in `create_and_register`: explicit `--folder` takes precedence; otherwise use the configured value. Both single-repo creation (including `--from-issue`) and `--program` creation already converge there. Keep folder identity scoped by repo using the existing `file_registered_worktree` → `Db::ensure_folder(repo_path, name)` path.

## Failure cases to cover

1. `wt new` without `--folder` and with a valid `default_folder` creates and files the new worktree.
2. Explicit `--folder` wins over the configured default.
3. `wt new --from-issue` inherits the default through the same single-create path.
4. `wt new --program` applies the default independently to each created repo member; reruns and repeated creations reuse the same case/whitespace-insensitive folder within a repo.
5. Two different repos configured with the same default name get repo-scoped folders, not one cross-repo identity.
6. `thegn config validate` rejects `default_folder = ""` and whitespace-only strings before any worktree creation.
7. Empty default (the built-in default) preserves current behavior: no implicit filing.
