# THE-189 maintenance-code — native dispatch 552

verdict: implementation-ready

## Scope

Implemented all accepted findings F-001 through F-005 from the primary
revision. The shared 500ms refresh worker remains the sole scheduler; no new
idle wake source, config key, provider seam, or per-feature timer was added.

## Changes

- Replaced the unbounded replacement command channel with a mutex-protected
  latest-value slot. Reloads do not wake the worker; the next existing ticker
  boundary observes the newest schedule.
- Added sibling-owned `RefreshGeneration` coalescing state so any untagged
  PR, CI, calendar, reminder, LOC, usage, or weather request wins over a
  scheduled request in the same drain, in either arrival order.
- Fenced scheduled publication/cache writes for weather, CI, PR, calendar,
  LOC, and usage immediately before their writes or deliveries. In-flight
  provider/network/scan work is intentionally allowed to finish and is
  discarded at the fence; hard cancellation was explicitly outside this lane.
- Fenced reminder notification raising at the notification boundary and
  released `ReminderCursor::inflight` when a stale reminder acknowledgment is
  dropped by the event-loop envelope admission path. This preserves later
  reminder checks after a reload.
- Added focused regressions for latest replacement coalescing, stale
  publication fencing, untagged-wins behavior, all seven live ticker classes,
  and cursor release after a dropped stale reminder acknowledgment. The live
  replacement test now drives a real `ScheduleOwner` around the production
  worker and verifies A→B→C replacement behavior.

## Wiring changed

`run.rs` changes are limited to generation-origin bookkeeping for the seven
scheduled classes, passing the shared fence into their workers, and abandoning
the cursor for a stale `CalendarReminderResult` envelope. No scheduling logic
or blocking I/O was added to the loop.
