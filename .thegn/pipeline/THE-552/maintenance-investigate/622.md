## Finding: defect remains

The cited line numbers were stale, but the same behavior is present in current
source:

- [`replay.rs`](../../../../crates/thegn-host/src/replay.rs#L211):
  `Recording::reconstruct(at_ms)` makes a fresh emulator and calls
  `feed_into(&mut emu, 0, at_ms)` (current lines 213–216).
- [`replay.rs`](../../../../crates/thegn-host/src/replay.rs#L219):
  `feed_into` skips every event for which `ev.at_ms <= from_exclusive` (lines
  222–229). Thus with `from_exclusive = 0`, all retained events at timestamp 0
  are skipped, including bytes and resize events. A first resize at zero is
  omitted from geometry as well as first output.
- [`replay.rs`](../../../../crates/thegn-host/src/replay.rs#L268):
  `search_next` replays each event and samples after every event (lines 276–292),
  but forward search only returns matches with `ev.at_ms > from_ms`. Therefore
  from `from_ms = 0`, it cannot return a timestamp-zero match; reverse search
  from a later timestamp can. The issue packet's broad claim that search
  “finds it at 0” is not true for current forward-search semantics.
- Search can sample an intermediate state in a group of events sharing one
  millisecond and return that timestamp, while `reconstruct(timestamp)` can
  represent only the final state after the entire group. The returned timestamp
  can therefore reconstruct a different grid from the one search matched.
- `export_cast` iterates all retained events (current lines 307–330), so it does
  not use reconstruction's timestamp-zero exclusion.

Current tests in `replay.rs` (roughly lines 427–617) cover normal later-time
reconstruction, resize, search and export, but none constructs events exactly
at `rec.epoch`, asserts `reconstruct(0)`, or covers same-millisecond event
groups. Replay overlay tests (roughly `replay_overlay.rs:503–610`) likewise use
positive offsets and do not exercise same-timestamp incremental boundaries.
Existing construction APIs already accept explicit `Instant`s, so zero-time
tests can be deterministic without sleeps.

   (`pane.rs:832–836`). Both bytes and resizes can therefore receive elapsed

4. `Action::EnterReplay` opens `ReplayOverlay::new` for a nonempty recording
   (`run.rs:23403–23420`). `ReplayOverlay::new` reconstructs at `rec.end_ms()`;
   seek uses timestamp-exclusive `feed_into` for forward motion and rebuilds on
   backward motion (`replay_overlay.rs:77–95`, 114–125).
5. The run loop calls `advance_clock`, renders the overlay from its scratch
   emulator, and routes replay keys/search into the same overlay (references in
   `run.rs:9113`, `13500`, and `17220–17235`). Thus the mismatch affects normal
   center-pane replay, independently of corner-stream filtering.

The stored sequence bookkeeping is already partially present: `Recording` has
`evicted` and `next_seq` counters and keyframes carry `event_seq` (`replay.rs:56–77`),
but `Event` itself contains only `at_ms` and `kind` (`replay.rs:41–46`), and the
overlay tracks only `fed_upto: u64` timestamp (`replay_overlay.rs:58–62`). A
timestamp cannot identify whether all or only some same-millisecond events have
been consumed, especially when more events are appended at the current
timestamp while replay is paused.

## Smallest complete fix proposal

Keep the fix within `crates/thegn-host/src/replay.rs` and
`crates/thegn-host/src/replay_overlay.rs`:

1. Separate inclusive reconstruction from incremental-forward semantics.
   Reconstruct a fresh emulator from the retained front and apply every retained
   event with `at_ms <= requested_at_ms`, including all events at zero. Do not
   treat timestamp zero as a sentinel.
2. Give incremental playback an event-sequence cursor. Prefer storing the
   monotonically increasing event sequence on each `Event` (or consistently
   deriving it from `evicted + deque_index`), and have feed-after-cursor apply
   each not-yet-consumed retained event whose timestamp is at or before the
   target, then return/update the next sequence. Initialize the overlay cursor
   to the first event after the inclusive reconstruction; forward seek/playback
   advances it; backward seek reconstructs and resets it. Clamp/rebuild if ring
   eviction overtakes the cursor, so stale scratch state does not survive a
   changed retained front. This explicitly uses sequence identity because a
   millisecond timestamp cannot represent a position within or after a
   same-millisecond group.
3. Make `search_next` sample after each complete timestamp group, not after
   each event. Its reported timestamp must reconstruct to the same sampled
   grid. Preserve current direction semantics (`>` forward and `<` reverse),
   meaning zero is found by reverse search from a later position; if primary
   interprets acceptance as forward search from zero including the current
   frame, that API semantic needs an explicit decision before implementation.

No changes are indicated for `pane.rs`, `panes.rs`, `run.rs`, export format, or
configuration. Existing sequence/eviction state is in-memory only; no format or
database migration is needed.

## Ordered implementation and regression-test plan

1. In `replay.rs`, add deterministic fixtures that pass `rec.epoch` directly:
   multiple byte events and a resize at exactly zero; assert `reconstruct(0)`
   contains the output and reflects the resize. Also cover an event just after
   zero to prove later data is excluded from the zero reconstruction.
2. Implement inclusive fresh reconstruction and the sequence-based incremental
   cursor, including retained-front/eviction handling.
3. In `replay_overlay.rs`, test a group of multiple same-time events followed
   by a later event: reconstruct/backward seek, forward seek, repeated feed
   intervals, pause/resume cursor preservation, and backward-seek rebuild must
   apply each event exactly once. Use visible terminal state that would expose a
   repeated feed; do not sleep or shift events away from zero.
4. In `replay.rs`, test search/reconstruct agreement for timestamp zero and a
   same-millisecond group whose intermediate state matches but final group
   state does not. Search must not report a timestamp whose reconstructed grid
   lacks the query. Cover reverse search back to zero; preserve current strict
   forward boundary unless primary approves changing it.
5. Run the focused `thegn-host` replay tests with `cargo nextest` after
   implementation, then hand off for primary's central clippy/workspace nextest/
   smoke gates. No builds, cargo commands, or tests were run during this
   investigation, per the dispatch scope.
