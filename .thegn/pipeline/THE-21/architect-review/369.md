## Review basis

Reviewed the complete THE-21 diff from merge-base `caef2f0e`, the architecture
design, both chunk specs and completion reports, repository architecture and
contribution standards, the pure engine/config/store code, every host event and
action path, control/catalog/schema projections, and the current-main migration
state. `.understand-anything/knowledge-graph.json` is absent, so the optional
knowledge-graph overlay could not be generated; dependency/blast-radius review
was performed directly from source and call sites.

The core matcher/config shape, additive-at-its-original-base storage, catalog
rows, HTTP/gRPC/MCP projections, help/completion wiring, and basic notification
producer migration are substantial and compile cleanly. This is nevertheless a
revision because live behavior is incomplete or unsafe at the architecture
boundaries:

- notification events lose their underlying kind and routed effective priority,
  while direct producers still bypass the one route decision;
- `pr_checks` and `pr_review_requested` have no live producers, documented
  workspace/repo/agent-role facts are never populated, and idle duration is
  incorrectly borrowed from debounce;
- concurrent processes can independently admit the same once/rate-limited event,
  overflow is not durably audited, and state plus pre-dispatch audit are not
  atomic;
- one-shot CLI producers can exit with queued work, and the supposedly store-free
  CLI dry-run actually opens/migrates SQLite;
- `tools.run` accepts agents/bare harnesses through the default open adapter,
  merge ancestry is lost, successful non-notify outcomes are not surfaced, and
  a timed-out tool keeps running;
- current `main` now owns schema v62/v63 while this branch independently claims
  v62, so the migration must be reconciled before landing.
