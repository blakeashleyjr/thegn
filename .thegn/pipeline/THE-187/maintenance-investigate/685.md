## Smallest complete fix proposal

Keep the production change within `crates/gtui-query/src/host.rs`:

- Replace retained `StatsSnapshot` values with a small fixed-size host-metric sample containing timestamp, CPU percent, used memory GiB, and load-1. Timestamp remains UTC Unix seconds, matching the existing frame and external-source domain.
- Set retention to the supported 24-hour maximum and enforce both a 24-hour timestamp horizon and a fixed sample-count ceiling for the nominal 1 Hz sampler (86,401 entries allows both endpoints). The fixed-size sample makes the count ceiling an explicit memory bound; document that sampling cadence is nominal and the count ceiling remains authoritative.
- Factor insertion/pruning and range selection into pure helpers that accept timestamps/ranges as values, so fake-clock tests can exercise the production policy without spawning a sampler thread.
- Insert out-of-order timestamps in sorted order. For equal timestamps, replace the existing entry with the latest received sample; this gives one stable row per timestamp and deterministic output. Discard an arrival already older than the retention cutoff. Apply both age and count pruning after insertion, preserving chronological order.
- Pass each `Query.time_range` to frame construction and include only timestamps satisfying the inclusive interval `from <= sample_time <= to`. Do not rewrite or widen the requested interval. A disjoint/invalid interval yields the normal two-field frame with empty columns; a partly retained interval returns only available in-range samples. This makes the returned timestamps expose partial retention without inventing samples or returning out-of-window values.
- Keep unrecognized expressions as empty value series and preserve one frame per query.

The maximum-range alignment is deliberate: Observe's supported range is capped at 24 hours (`embed.rs:82-87`), and HostSource can retain that window at its nominal 1 Hz cadence subject to its explicit fixed capacity. Queries beyond the UI maximum still receive only retained samples lying inside the exact requested bounds; HostSource must not silently move the lower bound.

## Regression cases and ordered implementation/test plan

2. Test shuffled/out-of-order inserts produce chronological frame timestamps; test duplicate timestamps replace deterministically with the latest received metric values; test stale out-of-order arrivals cannot resurrect data outside the retention horizon.
3. Add a query helper accepting explicit UTC endpoints and test inclusive `from` and `to`, exclusion immediately outside either endpoint, a point range, an inverted range, and a range disjoint from retained data.
