# THE-677 generation pruning implementation

Dispatch 641 · branch `blake/the-677-reap-stale-generations`

## Implemented

- Added the pure `disk_reclaim::plan_generations` policy. It selects only
  footprints older than the configured floor and always retains the newest
  touched fingerprint footprint for each package name. Equal mtimes use a
  deterministic ID tie-break; duplicate identities keep their first row; age
  subtraction saturates for future timestamps.
- Added `[disk] generation_min_age_days`, default `14`, matching
  `idle_clean_days`, its `THEGN_DISK_GENERATION_MIN_AGE_DAYS` overlay, strict
  duration-range schema validation, example documentation, and config coverage.
- Added generation pruning at the existing background disk-scan tail. It walks
  only freshly measured worktrees and their `debug`/`release` profiles. Each
  profile must have a regular `.cargo-lock` file that locks without waiting;
  lock errors skip that profile. Active, building, dirty, and awaiting
  verification worktrees are exempt. No Cargo process is started.
- Inventory comes from `.fingerprint/<package>-<id>`. Artifact association uses
  a filename stem ending in the same opaque ID; incremental directories use the
  same suffix. Unsafe, unreadable, or symlinked profile paths skip inventory.
  Deletion removes fingerprint metadata first, then mapped `deps/` files and
  `incremental/` directories. Partial deletion is counted file by file.
- Added per-profile structured fields for measured-before, planned, actually
  removed, measured-after bytes, and failures. These values remain separate from
  whole-`target/` reclaim bytes. CLAUDE.md and the architecture guide document
  the policy and its limitations.

## Guarantee and limitation

There is no off-Cargo authority that can determine whether an artifact will be
live for an arbitrary future Cargo build. The implementation guarantees only
the age floor and newest-per-package retention rule, synchronized against a
profile build by Cargo's lock. It makes no bound on rebuild cost if a footprint
association is wrong. The original “never removes the live generation” and
“no full-workspace rebuild” claims are not made.

The host inventory maps artifact paths by matching the fingerprint ID suffix.
The focused fixtures exercise that convention, but the real local Cargo profile
was not available for an on-disk before/after observation in this dispatch; the
central reviewer should confirm that the current Cargo artifact naming matches
the association rule before accepting its observed reclaim amount.

## Regression coverage added

- Core: newest package footprint, younger-than-floor retention, exact floor
  eligibility, future timestamps, deterministic equal-time tie, duplicate IDs,
  empty inventory, package independence, and exact selected-byte totals.
- Host: selected full-footprint deletion, retained newest footprint, real
  removed-byte count, held-lock skip, dirty and active exemptions, and one
  profile inventory failure not suppressing another profile.
