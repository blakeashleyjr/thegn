# THE-677 generation pruning inventory fix

Dispatch 650 · branch `blake/the-677-reap-stale-generations`

## Implementation

- Fixed Cargo artifact association in `thegn-host::measure::disk` to match the
  fingerprint package and opaque generation ID. It handles `lib<crate>-<id>`
  library outputs, `<crate>-<id>` dep-info and executable outputs, target names
  with package separators, and Cargo's hyphen-to-underscore crate-name
  normalization. Package boundary matching keeps `pkgx` artifacts out of a
  `pkg` footprint.
- Applied the same package-aware matching to incremental directories.
- Made the lock-acquired condition explicit: inventory proceeds only for
  `File::try_lock() == Ok(())`; contention and lock errors skip the profile.
  Rust 1.96 documents this method as `Result<(), TryLockError>` and says `Ok(())`
  means the exclusive lock was acquired:
  <https://doc.rust-lang.org/1.96.0/std/fs/struct.File.html#method.try_lock>
- Expanded the host regression fixture to cover library, `.d`, and executable
  outputs, retained-generation outputs, and a similarly prefixed unrelated
  package. Added direct coverage for hyphen-normalized crate names and matching
  boundaries. The active-worktree regression also asserts that an unregistered
  task slot is inactive.
- Updated `CLAUDE.md` and `docs/ARCHITECTURE.md` with the artifact mapping rule.

The `slot_active` source path only reads the in-process registry mutex; it
doesn't access XDG state or open the database. The profile fixture's existing
git-status check remains isolated by its temporary repository and ignored
`target/` directory.

## Guarantee

The guarantee remains the approved retention policy: respect the configured
age floor, retain the newest touched footprint per package, synchronize with
Cargo through the profile lock, and delete fingerprint metadata before mapped
outputs. This does not guarantee that every future build will avoid a rebuild
or bound the rebuild cost of a mistaken association.
