## Why implementation is blocked

The policy can decide only from facts the scanner supplies. Neither file age, the fact that a same-named artifact has a newer mtime, nor absence from `Cargo.lock` proves an artifact is unreachable from the current Cargo unit graph. In particular, integration-test binaries have no lockfile entry, and an older-looking dependency artifact can still be the exact cache hit Cargo wants. The checkout has no captured `.fingerprint`/`deps` sample to establish a safe matching rule, and no current source/API in this path provides authoritative live-generation identities. Deleting by guessed hash/target-name equivalence would violate “never removes the live generation.”

A decision is needed on a trustworthy, bounded source of the current Cargo artifact set before this work can be complete. A viable implementation prerequisite would be a Cargo-produced inventory tied to the exact build configuration/unit graph (including profile, target triple, features, and integration-test targets), or a supported Cargo stale-artifact pruning interface with the required safety semantics. The current code has neither. Cargo-derived liveness must also be synchronized against builds that are not registered in `crate::task::slot_active`; a scan/delete race with external `cargo test` remains a failure case unless the liveness mechanism owns or coordinates with those builds.

The primary's policy direction is still the right home once that prerequisite exists: keep discovery/deletion on the background disk measurement path, feed already-measured generation candidates into pure `disk_reclaim` planning, and retain every existing exemption. The smallest complete implementation cannot be specified as code-level changes until the source-of-truth and external-build synchronization are decided. Do not ship age-only, lockfile-only, or “newer same name” pruning as a substitute.

- Lockfile omission for legitimate `tests/*.rs` binaries must never classify them as foreign.
- A stale mtime cannot make a currently referenced generation reclaimable.
- Multiple target kinds, features, profiles, and target triples cannot be collapsed by filename prefix or mtime ordering.

- Generation discovery/deletion racing an active external Cargo process must preserve all in-use inputs; thegn-owned active/building/awaiting-verification/dirty exemptions must remain intact.

- Deletion errors or a changing tree must not over-report recovered bytes; notifications/logging should report actual bytes and before/after totals.
- A repeat scan after pruning must be idempotent and must not recreate a full-workspace rebuild by deleting current fingerprints/dependency artifacts.
