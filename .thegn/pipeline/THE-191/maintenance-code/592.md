# THE-191 maintenance-code / dispatch 592

verdict: implementation-ready

## Scope delivered

- Extended offline `thegn plugin list` human and JSON output with one stable
  lifecycle vocabulary: `disabled-by-config`, `starting`, `healthy`,
  `degraded`, `crash-disabled`, `stopped`, and `unknown`.
- Config-disabled plugins report `disabled-by-config` from authoritative config
  state. Enabled plugins report `unknown` because this CLI has no attached
  compositor or persisted supervisor health snapshot; neither output mode can
  imply `healthy` from discovery or process absence.
- Added explicit live-health-unavailable metadata and `null` last-failure,
  restart-count, and backoff fields when no snapshot exists. Human output keeps
  inspection exit-zero semantics; `plugin check` retains validation failures.
- Failure projection redacts secret-shaped text and reuses the existing
  bounded display-label helper, so future failure values are bounded and carry
  no terminal control characters.
- Added regression tests for every vocabulary name in both output forms,
  unknown-vs-healthy handling, config-disabled state, and bounded/redacted
  failure metadata. Documented the offline policy in `docs/help/plugins.md`.

## Explicit follow-ups / design boundary

No new control boundary or persistence store was introduced. Live crash,
backoff, restart, and reload state remains loop-local in
`crates/thegn-host/src/handlers/plugins.rs`; the supervisor in
`crates/thegn-svc/src/plugin/session.rs` still has no health snapshot. The
compositor-to-control publication and authoritative snapshot seam is a follow-
up. `stale-generation` is also intentionally omitted because THE-165 is not
landed and no generation authority exists here.
