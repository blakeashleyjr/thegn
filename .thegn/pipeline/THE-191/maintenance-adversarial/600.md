## Findings

No blocking source findings within the primary-approved scope.

The implementation correctly keeps the offline CLI truthful:

- `PluginHealth::from_config` maps only config-disabled entries to
  `disabled-by-config` and maps enabled entries to `unknown`; it never infers
  `healthy` from discovery or process absence (`plugin.rs:77-105, 139-148`).
- Both output modes serialize the same stable state enum, and the JSON row
  retains the existing config/discovery fields alongside the flattened health
  fields (`plugin.rs:28-38, 115-126, 250-279`).
- Missing supervisor state is explicit (`live_health = unavailable`, reason
  `no attached compositor`) and restart/failure metadata remains null rather
  than being fabricated (`plugin.rs:64-105, 152-167`).
- Failure projection reuses the existing redaction and bounded display helper;
  the focused test asserts the bounded, control-free result
  (`plugin.rs:108-113, 422-437`).
- The complete flattened machine-readable row is now locked by
  `json_list_row_keeps_config_and_health_fields_in_one_stable_projection`
  (`plugin.rs:410-424`).

## Explicit deferred acceptance boundaries

These are real issue-level gaps, but are intentional under the primary plan and
must not be reported as delivered:

1. There is still no compositor-to-CLI/control attachment or persisted health
   snapshot. Consequently an offline enabled plugin cannot expose live
   `starting`, `healthy`, `degraded`, `crash-disabled`, or `stopped` evidence;
   it reports `unknown`. The authoritative runtime transitions remain loop
   local in `handlers/plugins.rs:475-515`, while the supervisor registry does
   not publish plugin health in `session.rs:93-105`. The primary explicitly
   prohibited creating that new control boundary in this lane. This is the
   follow-up seam, not a claim that the full live-status acceptance criterion
   has passed.
2. `stale-generation` is not emitted because THE-165 is unlanded and there is
   no generation authority to consult. The implementation deliberately keeps
   the typed vocabulary to the primary-approved seven states
   (`plugin.rs:25-60`).
3. The future snapshot publisher must cap failure input before any expensive
   redaction if it can receive data larger than the existing bounded session
   line. The current CLI path never populates `last_failure`; its output is
   bounded and the current session line machinery is already capped. This is a
   hardening requirement for the deferred attachment, not a current bypass.

The docs now state that crash/backoff state is process-lifetime and is not
persisted across daemon/compositor restart; the offline command reports
enabled plugins as `unknown`/unavailable after restart
(`docs/help/plugins.md:107-113`).
