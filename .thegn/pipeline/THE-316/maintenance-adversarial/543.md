## Findings

### P1 — a failed transition POST is incorrectly classified as safely unapplied

`crates/thegn-svc/src/issue/jira.rs:671-685` wraps every `post_empty` error as
`PartialUpdate { unapplied: ["status"] }` whenever a title was applied. That
includes `IssueError::Network` and `IssueError::Timeout`, and also errors from
an intermediary after Jira may already have accepted and executed the POST.
The implementation does not perform a verification fetch on this path. A
caller following the advertised per-field retry contract can therefore retry a
workflow transition that already landed, duplicating Jira automations,
notifications, or timers. The same unsafe assumption is codified by
`crates/thegn-svc/src/issue/jira.rs:1287-1335`, which treats a 503 as proof that
status is unapplied and approves retrying it alone.

This needs an explicit ambiguous-outcome treatment: for example, verify the
current category before declaring status retryable, or expose an unknown
field outcome and prohibit automatic retry until the caller reconciles it.
Do not label a transport/intermediary failure as `unapplied` without evidence.

### P2 — the typed partial result is lost at the control/API boundary

The Jira/service layer has a structured `IssueError::PartialUpdate` at
`crates/thegn-svc/src/issue/mod.rs:34-38`, but
`crates/thegn-host/src/daemon/service.rs:1708-1710` converts it into a formatted
`anyhow` string. `crates/thegn-svc/src/control/http.rs:233-247` then exposes
only the generic `internal` error envelope. Direct Rust callers can pattern
match the fields, but control clients, automations, and UI actions cannot
reliably consume the per-field result as a machine-readable contract. The
primary plan explicitly motivated a typed result so callers could retry safely;
the main external update path currently discards that type. Either preserve a
bounded structured partial-update response at this boundary or explicitly
document that the contract is internal-only and provide a safe reconciliation
path for control callers.

### P2 — request-body assertions are missing from the new HTTP tests

`crates/thegn-svc/src/issue/jira.rs:1076-1100` records only method and URL path.
Consequently the tests do not detect a regression that posts the wrong
transition ID or sends the wrong title field while retaining the same request
sequence. Add body assertions for the title PUT and transition POST (including
the selected transition ID) in the success/partial test fixture.
