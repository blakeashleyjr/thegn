## Findings

### P1 — all Jira 4xx transition responses are still treated as safely unapplied

`crates/thegn-svc/src/issue/jira.rs:251-259` classifies every `jira HTTP 400..499` response as a definitive transition rejection. The POST handler at `:694-698` then immediately reports `status` in `unapplied` and skips the final issue fetch. That is too broad for the primary contract: only a 4xx known to mean that Jira refused this transition is `NotApplied`; an HTTP timeout (408), rate-limit/proxy response (429), or other intermediary-generated 4xx can be returned after the POST was received and executed. A caller following the partial-result retry contract can therefore duplicate a workflow transition.

The new test `crates/thegn-svc/src/issue/jira.rs:1337-1379` models an HTTP 408 followed by a failed verification fetch and expects an `Unknown` outcome with no `unapplied` status. It is not run here by instruction; against the current predicate it should fail because the implementation returns `Api("jira HTTP 408")` immediately after the POST. Narrow the definitive set (or classify the response using provider-specific evidence), and keep ambiguous 4xx responses on the verification/Unknown path. Add coverage for each ambiguous class selected by the fix, especially 408 and 429.

### P2 — the ambiguous branch loses the original typed POST failure

When an ambiguous POST is followed by a failed verification fetch, `crates/thegn-svc/src/issue/jira.rs:718-725` replaces both typed failures with a synthesized `IssueError::Api` string. This preserves a bounded human message, but it does not preserve the original `Network`/`Timeout` classification or error chain. Consequently `IssueError::PartialUpdate::source` and `SeamError::class` at `crates/thegn-svc/src/issue/mod.rs:131-153` report `Other`, so a transport-unknown result cannot retain the normal transient classification. This is also weaker than the issue's “propagate typed transition ... failures” criterion. Preserve the typed source (while keeping the bounded verification context) or explicitly adjudicate this loss as part of the follow-up contract.
