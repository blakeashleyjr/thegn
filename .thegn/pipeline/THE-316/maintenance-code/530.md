# THE-316 implementation — dispatch row 530

verdict: implementation-ready

## Scope and findings

Implemented the primary-approved Jira-only plan on
`blake/the-316-propagate-jira-transition-failures-instead-of-returning`.
There is no concrete design blocker. The implementation changes exactly these
source files:

- `crates/thegn-svc/src/issue/jira.rs`
- `crates/thegn-svc/src/issue/mod.rs`

`docs/api/control-v1.json` is unaffected.

The issue headline criterion was already met before this row: commit `c6eaa4d0`
changed Jira transition submission to the shared empty-response helper, and the
current `JiraBackend::update_issue` calls `post_empty(...).await?`. Lookup and
POST failures therefore already propagate as typed errors; this row did not
re-fix that criterion.

## Implementation

- Added one structured `IssueError::PartialUpdate` variant with static applied
  and unapplied field names plus the original boxed `IssueError`. Its Debug,
  Display, error-chain source, and `SeamError` classification preserve the
  bounded/typed source context.
- Jira updates now apply title first, then status. A title failure stops before
  any transition request. If status lookup or POST fails after a title write,
  the partial error reports `title` applied and `status` unapplied.
- Centralized the semantic target mapping (`new`, `indeterminate`, `done`) and
  verified the final fetched Jira `statusCategory` before returning success.
  A mismatch is an error and reports the fields already applied.
- Kept provider diagnostics bounded: no raw response body is included; the
  existing HTTP seam remains responsible for bounded bodies and status/error
  classification.
- Added local axum/TCP-fixture regression coverage for title short-circuiting,
  typed lookup and POST failures, unavailable/stale transitions, empty and
  204 responses, category verification and domain-category equivalence,
  title-first ordering, partial results, and retrying only the unapplied field.
