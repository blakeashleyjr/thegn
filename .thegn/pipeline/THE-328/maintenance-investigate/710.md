## Failure cases to close in the scoped fix

1. Absolute `dest`, `..` traversal, nested path separators (both `/` and `\\`),
   empty/dot names, control characters, and a component exceeding the chosen
   portable byte limit are rejected before filesystem mutation.
2. A planted destination symlink causes a hard error; its target contents stay
   unchanged and the provider is not spawned.
3. A normal existing destination is updated atomically; readers cannot see a
   partially written credential. A temp-name collision or write/flush/rename
   failure is fatal and does not spawn the child.
4. A successful Unix materialization is exactly mode `0600`; on Windows the
   owner-only DACL operation must succeed before writing content. Any
   restriction failure is returned, never discarded.
5. Failed materialization must remove its owned temporary file where possible.
   Do not claim crash cleanup or lifecycle cleanup: generation ownership is
   deferred.

Potential races that remain outside this lane unless scope is widened: an
attacker replacing the state directory or an ancestor during path-based
operations; race-free refusal of a symlink that appears after a preflight
`symlink_metadata` check; hardlink/inode ownership policy; cross-start collision
and lifecycle cleanup. The atomic rename prevents following a final symlink as
a write target, but a simple precheck alone cannot prove race-free refusal.
Implementation must resolve this explicitly within the primary-approved
contract or report it as a blocked requirement rather than overclaiming.

## Smallest complete proposed fix

1. Add a pure destination validator in the share layer, invoked for every plan
   file before creating the state directory. Restrict to one nonempty plain
   component and reject absolute/prefix/root, dot/parent, either separator,
   control bytes, and overlong names. Keep errors free of file contents.
2. Materialize through a private atomic-write primitive. Prefer a narrow
   extension of `thegn_core::fsperm`'s existing implementation if it can meet
   scoped requirements: unique same-directory temp, exclusive/no-follow
   creation, permissions established before bytes, file sync, atomic publish,
   fatal permission errors, cleanup on failed publication. Add a safe
   destination-type check that rejects a pre-existing symlink without opening
   or truncating it. The primary must decide the exact race contract: if
   race-free symlink refusal is mandatory, implement the publish/check in the
   platform seam using dir-relative/no-follow operations rather than relying
   only on a path precheck.
3. Keep `start`'s existing order: complete and validate all materialization
   before `Command::spawn`. Surface contextual errors without secrets.
4. Add focused tests in `crates/thegn-svc/src/share/tests.rs` (or the pure
   validator's colocated tests): table-driven invalid names; symlink target
   preservation plus no-spawn assertion; successful 0600 mode on Unix and
   owner ACL success semantics on Windows; replacement content and no
   partial-publication check; injected/constructed publication or permission
   error fails before spawn and leaves no temp artifact. Synthetic canary
   contents only. Any race test must assert exactly the race guarantee the
   chosen platform primitive provides.
