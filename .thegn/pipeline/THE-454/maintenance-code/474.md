# THE-454 maintenance implementation — native dispatch row 474

## Implemented

- Added a service-level pooled calendar HTTP transport with separate public and
  explicitly trusted-private client pools. Clients disable automatic redirects,
  ambient proxy use, cookies/default auth, and automatic decompression.
- Added a custom DNS resolver that validates every returned address and hands
  those same checked addresses to reqwest. Public mode rejects private,
  loopback, link-local, unspecified, multicast, mapped-special, shared,
  documentation, benchmarking, reserved, and other non-global IPv4/IPv6
  destinations; private mode admits intentional local unicast destinations but
  still rejects unspecified, multicast, and broadcast addresses.
- Added bounded streaming response primitives shared by calendar and tracker
  adapters. Success bodies are capped at 32 MiB before vector growth; error
  bodies are drained without retention under an 8 KiB bound. Encoded responses
  are rejected before reading. Connect, read-idle, and absolute operation
  deadlines are distinct; CalDAV token recovery performs at most one retry
  under the original absolute deadline.
- Added core URL parsing/normalization for HTTP(S) and ICS-only webcal URLs,
  rejecting unsupported schemes, malformed URLs, userinfo, and fragments.
  Added the trusted `allow_private_network` account option, default false, with
  configuration/example/help documentation.
- Reworked ICS and CalDAV backends to use the shared transport, retain
  request-local credentials, refuse all redirects before inspecting Location
  (with the existing non-redirect 304 cache response preserved), validate
  protocol media types, bound CalDAV sync-token/request bodies, and use generic
  redacted transport errors. Calendar account Debug output redacts URL,
  username, and token values.
- Added deterministic fixtures for all redirect statuses with relative and
  absolute Locations, no redirect-target requests, ICS auth retention only at
  the source, CalDAV sync-token body non-replay, one-shot token recovery,
  oversized chunked bodies, encoded bodies, oversized error bodies, address
  policy/mapped/mixed-answer checks, URL validation, secret-redacted config
  diagnostics, and pooled transport construction paths.

## Acceptance coverage and unverified work

Source and focused regression coverage are present for URL policy, redirect and
body replay behavior, streaming caps, encoding refusal, error draining, media
policy implementation, address admission, account Debug redaction, and
CalDAV retry bounding. Tests were not executed. The native gate still needs to
exercise real DNS rebinding fixtures, proxy-environment bypass attempts,
never-ending-body idle/total deadline behavior, exact-at-cap success bodies,
all documented MIME variants, repeated router reuse/account isolation, and
resource-bound measurements. These are unverified, not claimed as passed.

The deliberate compatibility exception is HTTP 304 for ICS: it is handled as
the existing conditional-cache result and never follows or reads Location;
301/302/303/307/308 and all other 3xx responses are refused.
