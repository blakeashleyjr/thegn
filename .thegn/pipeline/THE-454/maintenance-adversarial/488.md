## Findings

### 1. Medium — shared calendar pools leave per-host idle capacity unbounded

Location: `crates/thegn-svc/src/http.rs:121-165`, especially the
`Client::builder()` chain at `151-164`.

The two process-wide clients correctly share pools by private-network policy,
but the builder does not set `pool_max_idle_per_host`. Reqwest 0.12's default is
`usize::MAX` (`reqwest-0.12.28/src/async_impl/client.rs:301-302` in the local
dependency source). Repeated router construction therefore retains an
unbounded number of idle connections per origin until idle expiry. Calendar
accounts and their origins are configuration-sized, and the polling path
reconstructs routers, so a large or frequently changing account set can grow
socket/file-descriptor and pool state without an application-owned bound.

This conflicts with the approved design requirement to reuse pools without
unbounded per-origin caches. Set an explicit finite idle-per-host bound (and
add a source-level/integration regression that exercises reconstructed
backends); preserve request-local auth, ETag, query, and sync-token state.

### 2. Medium — DNS policy denial is collapsed into ordinary network failure

Locations: `crates/thegn-svc/src/http.rs:210-213` and `108-117`; the only
same-client rebinding assertion is `crates/thegn-svc/src/http.rs:803-817`.

`CalendarResolver` returns the same `resolver_error()` for a forbidden answer,
but `CalendarHttpClient::send` maps every non-timeout `reqwest::Error` to
`CalendarHttpError::Network`. Both calendar backends consequently expose a DNS
destination-policy refusal as `CalendarError::Network`, and
`CalendarError::is_transient` treats it as retryable. The current same-client
DNS test only asserts `.is_err()`, resolution count, and zero listener hits;
it cannot distinguish policy denial from an ordinary failed connection, which
the primary instructions explicitly require.

Preserve a distinct policy-denial signal through the resolver/connection seam
or provide an equivalent deterministic classification at the backend boundary.
The regression must assert the classification, while retaining the same-client
re-resolution, forbidden-answer, mixed-answer, and zero-target-hit checks.
