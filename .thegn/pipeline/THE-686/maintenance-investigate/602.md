## Exact evidence that the bug remains

1. `crates/thegn-host/src/merge_cleanup.rs:301-373` is still the admission
   cleanliness probe. After the filter-driver, skip-worktree/assume-unchanged,
   and submodule safety checks, it runs:

   ```text
   git status --porcelain=v1 -z --untracked-files=all
       --ignored=matching --ignore-submodules=none
   ```

   Any non-empty output returns `Err(Refusal::Dirty)` at lines 366-371. Git
   reports pre-existing ignored build output as `!!` records, so an ignored-only
   worktree is rejected exactly like tracked or untracked user work.

2. `crates/thegn-host/src/merge_cleanup_tests.rs:227-244`,
   `dirty_ignored_untracked_and_unknown_status_never_mean_clean`, creates one
   fixture each for `tracked`, `untracked`, and `ignored`, and asserts all three
   return `Err(Refusal::Dirty)`. The `ignored` assertion is the regression that
   THE-686 must intentionally revise; the tracked and untracked assertions must
   remain strict.

3. The current admission call is `Verified::probe` at
   `merge_cleanup.rs:516`. The final re-check is `Verified::remove_checked` at
   `merge_cleanup.rs:581-600`, which calls `self.revalidate()` before removal;
   `revalidate()` at `544-564` calls `Self::probe()` again. Consequently, the
   current code asks the same emptiness question both at admission and at final
   validation. `merge_cleanup_tests.rs:328-347`,
   `final_validation_preserves_new_ignored_files_and_replaced_directory`,
   proves that a new ignored file after admission must still abort removal.

4. `--force` does not weaken the dirty guard. `merge_sweep.rs:184-189` uses
   `force` only to bypass the TTL selection; it still calls
   `merge_lifecycle::remove_landed_with_config` at `209-219`, which calls
   `Verified::probe` and all cleanup guards. The comments at
   `merge_sweep.rs:74-79` state the intended contract: force means “ignore the

## Smallest complete fix

Keep the existing `--ignored=matching` probe; do not simply remove that flag.
The one-line removal breaks the final-validation test and loses the distinction
between an ignored build directory that already existed and one that appeared
during cleanup.

1. In `merge_cleanup.rs`, factor the status result into a small admission
   observation (for example, the bounded NUL-delimited porcelain bytes plus an
   `ignored_only` marker). Parse each porcelain record fail-closed: an empty
   output is clean; records whose status is exactly `!!` are ignored-only; any
   tracked, untracked, malformed, or otherwise unknown record returns the
   existing `Refusal::Dirty`. Preserve the current filter-driver, index flag,
   submodule, bounded Git command, and error/refusal behavior.
2. Store the admission observation in `Verified`. The existing Git wrapper caps
   stdout at 2 MiB, so retaining the bounded status bytes is the smallest
   branch-local design and avoids a new hashing dependency. If the probe exceeds
   the existing bound it must continue to refuse conservatively.
3. Make `Verified::revalidate()` capture a fresh status observation and compare
   it to the stored admission observation in addition to its existing identity
   checks. A different observation returns a typed third refusal (recommended
   name: `Refusal::Changed`) displayed as `edited since landing` or equivalent.
   This is important: calling the revised admission predicate twice without
   comparing snapshots would silently admit a newly appearing ignored file.
4. Keep `Refusal::Dirty` for admission-time tracked modifications and
   untracked-non-ignored files. Keep `Refusal::Unsafe` for the existing identity,
   resource, filter, special-index, submodule, and Git-probe failures. Check
   every `Refusal` match after adding `Changed`; the known production match sites
   are `merge_lifecycle.rs`, `merge_cleanup.rs`, and the focused tests.
5. Carry whether the admitted snapshot contained ignored state through the
   successful removal result. Extend `CleanupOutcome::Removed` and
   `SweepReport` only as needed so the CLI/off-loop sweep reporting can print
   `swept <branch> (discarded build state)` for that case. Keep clean removals
   distinguishable from ignored-state removals.
6. Route a changed final snapshot to the kept/edited reporting path, with
   output equivalent to `kept <branch> — edited since landing`. Do not infer
   this from a free-form reason string if a typed refusal/outcome can carry it.
   Update the synchronous lifecycle warning, `thegn merge sweep` output, and
   the background sweep message consistently. No change is needed to TTL or
   `force` selection semantics.

This preserves both propositions required by coordination: ignored-only state
present at admission is removable after TTL, while a different status snapshot
at any later guard is a cleanup veto. Tracked and untracked non-ignored content
never passes admission, with or without force.

## Failure cases and regression matrix

The implementation must preserve these cases:

- clean worktree: swept when due; `force` sweeps it before TTL;
- ignored-only worktree: swept when due and reports discarded build state;
- tracked modification: kept with or without `force`;
- untracked non-ignored file: kept with or without `force`;
- ignored file appearing between admission and final removal: kept as edited,
  and the file/worktree remains;
- ignored-only snapshot unchanged through all guards: removal succeeds;
- changed/malformed Git status or any existing identity/resource safety guard:
  refusal remains fail-closed;
- fresh landed row: no-force respects grace period, while force bypasses only
  that clock.

Required tests, in order:

1. Rename/revise `dirty_ignored_untracked_and_unknown_status_never_mean_clean`
   so tracked and untracked still assert `Refusal::Dirty`, while ignored-only
   admission succeeds. Retain the corrupt-index and missing-path refusal cases.
2. Add focused status-observation tests for empty, ignored-only, tracked,
   untracked, and malformed/unknown records. Assert the existing filter-driver
   canary and all special safety guards remain untouched.
3. Update `final_validation_preserves_new_ignored_files_and_replaced_directory`
   to assert the new changed refusal/reporting shape for a newly appearing
   ignored file; retain the replacement-directory identity failure.
4. Extend the `merge_sweep` fixture coverage to run the landed-worktree matrix
   for clean, ignored-only, tracked-modified, and untracked-non-ignored states
   with both `force = false` (an expired row) and `force = true`. Assert physical
   existence/removal, queue/cache retention, `collected`/kept categories, and
   that force never removes tracked or untracked user work.
5. Add reporting assertions for `swept … (discarded build state)` and
   `kept … — edited since landing`, plus the unchanged grace-period case. The
   tests must cover both the direct CLI report projection and the background
   sweep data if the implementation exposes both separately.
