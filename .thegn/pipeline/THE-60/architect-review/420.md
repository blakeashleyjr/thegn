## Blocking finding

The old implicit `Tier::ToolVersions` install was removed from core, but
`host_provision.rs` was not rehomed to the provider. Its existing remote/OCI
provision path still detects declarations and then receives no install step;
the new local-only `mise_provider::install` rejects remote/provider targets.
Thus a provider worktree with `.tool-versions`/mise declarations silently
opens without its declared tools, and there is no target-aware explicit
operation to repair it. Remote activation also returns `Reserved` without
using the existing remote detection probe, so remote declaration/status/trust
parity is incomplete. This is a functional and design-boundary gap, not a
style issue; the required correction and focused verification are specified in
the revision chunk.
