## Failure cases and security effects

- A pasted MPD password remains in config serialization and can appear through
  derived `Debug`; it is cloned into `ResolveOpts` and `MpdEndpoint`.
- An explicitly configured `keyring:`, `env:`, or `file:` string currently gets
  sent as the literal MPD password; it is never resolved.
- If the implementation is changed to call the existing broker as-is, both an
  explicitly configured missing ref and an unavailable keyring become `None`.
  Without a separate configured/unconfigured status the caller can proceed as
  anonymous. Current leaf construction also treats endpoint connection/auth
  errors as an unavailable backend and skips it (`lib.rs:448-450`), obscuring
  the credential failure as media absence.
- `MPD_HOST=password@host` is parsed and retained in the leaf endpoint with no
  broker event or consumer attribution. The normal config scanner cannot see
  environment content.
- Current MPD endpoint and options `Debug` output can include credentials;
  MPD endpoint clones spread the secret. `MPD_HOST` also changes error/log
  safety requirements: diagnostics must only see the sanitized host/socket.
- Runtime auth uses MPD's `password <value>` command. The leaf must keep the
  value only until that command is written, and errors must not format the
  command or value.

## Smallest complete fix shape

Reuse `SecretRef`, `SecretAudit`, and the existing host resolver; do not add a
second store or resolution path. Keep wire compatibility for the existing
`media.mpd.password` key and interpret its historical bare value as
`BareAs::Literal`; scheme forms select the existing env/file/keyring backends.
Serialize only the original ref/literal config representation, never a resolved
value. At runtime, resolve once at a host-side helper shared by all six media
entry points and pass a non-`Debug`, non-`Clone` secret owner to the leaf. That
owner should zeroize on drop and be moved into the endpoint with no extra secret
clone. Do not expose a value-bearing endpoint/options debug representation.

The helper must distinguish unconfigured, missing, unavailable, and resolved.
An explicit missing/unavailable credential must stop the MPD attempt with a
typed refusal that names `media:mpd`, never the ref value; no unauthenticated
fallback. Preserve existing no-password behavior only when the field is truly
unconfigured. `MPD_HOST` parsing must move to this audited host boundary: retain
the current `password@host` precedence/endpoint behavior (explicit config
credential takes precedence), represent a non-empty embedded password as a
literal ref and resolve it through the broker with consumer `media:mpd`, and
send only the sanitized endpoint plus moved secret to the leaf.

Add the MPD field to `secret_refs` and literal warning/migration selection.
Extend `thegn secret migrate`'s actual config rewrite to this field: the
existing generic scanner drives list/audit/presence, but the migrate command
has explicit issue/CI loops and will otherwise leave MPD literals unmigrated.
Update the config example/help/schema-facing fixture as needed; the public key
can remain `password`, so no gratuitous key rename is warranted.
