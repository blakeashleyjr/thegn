# THE-212 implementation — dispatch 687

## Outcome

Implemented the primary-approved scope without a schema migration or edits to
the reap region. Chunk scopes are parsed on the host before the SQLite write
lock, then supplied to a shared core admission operation. That operation
re-reads the roster under `BEGIN IMMEDIATE` and serializes scope overlap,
`after:` satisfaction, stage capacity, duplicate policy, audit notes, and row
insertion. A roster change that introduces an unprepared active sibling returns
a retryable snapshot refusal; the host refreshes prepared facts outside the
transaction. A stable overlap is refused, while disjoint claims can use the
remaining stage capacity.

`session open --stage --chunk`, `dispatch claim --chunk`, and retained
`dispatch put --chunk` use the shared admission path. Chunk puts require a
configured stage so capacity is enforceable. `dispatch claim
--allow-scope-overlap <reason>` and `dispatch put --force
--force-reason <reason>` record the non-empty reason as a row note and expose
it in command output. Session open has no override. Incoming chunk files are
always read and parsed before admission, including forced claims. Active
siblings with unreadable or malformed scopes refuse admission and name the row
and path; terminal and no-chunk siblings are ignored. JSON list output labels
scope as `chunk_files_from_file_at_display_time` to distinguish it from
admitted ownership.

Added regression coverage for the file-backed two-connection overlap race and
disjoint control, `after:` status, fail-closed unreadable siblings, no-chunk
legacy rows, reasoned force auditing, the `dispatch claim --chunk` bypass,
retained chunk put, and incoming-file replacement between preparation and
claim. Updated CLI documentation and the CLI behavioral contract.
