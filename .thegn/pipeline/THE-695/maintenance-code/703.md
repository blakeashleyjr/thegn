# THE-695 — native dispatch 703 implementation report

**Verdict:** implementation-ready

## Findings and implementation

The approved revision identifies the cause as the release-channel clamp, not config deserialization. Stable remains the default and Trackers remains experimental; this change does not alter that policy. The enablement mechanism is `THEGN_CHANNEL=dev`, confirmed in `channel_state::resolve` and `Channel::parse` (`crates/thegn-host/src/channel_state.rs:101-108`, `crates/thegn-core/src/channel.rs:24-45`).

- Added a cumulative process-wide feature bitset and `clamped(feature)` query. `clamp_and_record` is now used at both `main.rs` config clamp sites (`crates/thegn-host/src/main.rs:1008,1264`), TUI startup (`crates/thegn-host/src/channel_state.rs:124`), and both daemon config refresh paths (`crates/thegn-host/src/config_source.rs:78,97`).
- Both `main.rs` clamp sites emit a tracing WARN with channel and clamped features after diagnostics initialization. TUI startup also records the clamp and emits a WARN. No unconditional per-command stderr output was added.
- The `wt new --from-issue` and `issue list` refusal paths now explain that the configured tracker is experimental and disabled on stable, and say `THEGN_CHANNEL=dev` enables it (`crates/thegn-host/src/cmd/wt.rs:749`, `crates/thegn-host/src/cmd/issue.rs:148`). The control API refusal uses the same explanation (`crates/thegn-host/src/daemon/service.rs:1736`). With no configured tracker and no recorded clamp, the prior `no issue tracker configured (set [issues] providers/accounts)` advice is unchanged.
- The issues panel now identifies the stable-channel clamp in both its header and empty state (`crates/thegn-host/src/panel/sections/issues.rs:300,481`).
- `config get` prints a one-line stderr notice for an `issues` key after Trackers was clamped; its stdout serialization path is unchanged (`crates/thegn-host/src/cmd/config.rs:345-386`).
- Updated the release-channel help text to explain that dependent commands may refuse with channel guidance (`docs/help/release-channels.md:37`). `test/smoke.sh` needed no update: no smoke assertion checks the old refusal wording.

Stable-channel `wt new --from-issue linear:THE-N` remains intentionally unavailable under the approved policy; it now reports the actual reason. It is enabled by running with `THEGN_CHANNEL=dev`.
