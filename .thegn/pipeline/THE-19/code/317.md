## Finding

The reported hook-shape asymmetry is not intended by the implemented serde
types. `HooksConfig` declares all six event fields as `Vec<HookEntry>`, and
`HookEntry` is an untagged enum accepting either `Command(String)` or
`Spec(HookEntrySpec)`. Only `wait = true` is event-specific: validation permits
it for `post_create` and rejects it elsewhere.

The strict schema walker recursively checks every `anyOf`/`oneOf` branch rather
than selecting a branch compatible with the value. Consequently, a string
entry passes the string branch but gets a false `expected table/object` error
from the object branch, while an object entry passes the object branch but gets
a false `expected string` error from the string branch. Switching the example
shapes would only reverse the errors. Emptying or commenting out every shipped
hook entry would make the example test green without making documented,
non-empty hook examples validate, so no such change was made.
