# THE-402 code dispatch 723

Verdict: implementation-ready

## Changes

- `ThemeStore` now owns the worker `JoinHandle` and an atomic shutdown flag. Drop signals shutdown through both the flag and a wake message, then joins the worker.
- The worker checks shutdown between messages and during watcher debounce. It drops the watcher before draining; accepted Save, Import, and Apply requests are executed in order, while watcher changes and scan requests are discarded. Shutdown can wait for the in-flight filesystem operation and accepted writes; there is no wall-clock guarantee if filesystem I/O stalls.
- Worker thread creation failure logs one warning and returns a degraded store. Mutations return the existing `theme store worker is unavailable` error, and the closed results channel lets `initial_catalog()` return through its existing unavailable path.
- Watcher construction and directory-watch failures each log one warning. The worker retains Background QoS.
- Added regression coverage for repeated create/drop joins, a 50,000-message watcher backlog, Save accepted immediately before Drop, and an injected thread-spawn failure including the startup catalog path. Updated the debounce test to shut down its worker explicitly.

## Deferred by primary plan

Request and Tokio result channels remain unbounded; no item/byte budgets, deferred-request bound, overload policy, or stalled-consumer result bound was added. Watcher-storm and queue-saturation memory ceilings therefore remain open from the issue's broader acceptance criteria. Shutdown also cannot bound a filesystem call that itself stalls. These are explicit primary-plan deferrals, not verified remediations.
