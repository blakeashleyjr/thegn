## Bug status: confirmed present

The audited line numbers are stale, but the defect remains on this exact branch:

- `crates/thegn-host/src/model_proxy_daemon.rs:130-143` reads
  `tgproxy.pid`, parses only a trimmed `u32`, calls
  `platform::pid_alive(i64::from(pid))`, and then calls
  `platform::terminate_pid(pid)` when the PID is merely live. The pidfile stores
  only `child.id()` at lines 85-87; no process start time or authenticated
  channel is recorded.
- `crates/thegn-host/src/platform/unix.rs:130-143` implements `pid_alive` and
  `terminate_pid` by casting to `i32`. `pid_alive` rejects `pid <= 0` only after
  receiving an `i64`, and `terminate_pid` accepts every `u32` before the cast.
  Consequently `u32::MAX` becomes `-1`; on Unix `kill(-1, SIGTERM)` has broad
  process semantics. Values above `i32::MAX` can likewise become negative, and
  zero is a process-group target if it reaches the syscall.
- A live, unrelated process at a reused PID passes the liveness probe and is
  terminated because there is no identity comparison. An unreadable, malformed,
  or empty pidfile is ignored, but a syntactically valid stale PID is not
  distinguished from the proxy.
- The existing `signal_pid` helper at `unix.rs:150-168` does reject zero and
  values above `i32::MAX` before conversion, but it is the monitor's separate
  interactive process-tab path; it does not protect the model-proxy stop path
  and does not supply proxy start-time identity.

Already-met criterion: `platform::signal_pid` demonstrates the required
pre-conversion positive-range guard for its own caller, but that guard is not
used by `model_proxy_daemon::stop`, so it does not close THE-159.

## Production call paths and prerequisites

1. UI startup reaches `crates/thegn-host/src/run.rs:1029-1032`, which calls
   `model_proxy_daemon::spawn_supervisor` after the first-frame setup. The
   supervisor is off the UI loop.
2. `spawn_supervisor` (`model_proxy_daemon.rs:214-253`) calls
   `ensure_running`; when the TCP probe is down, `spawn` writes config, starts
   `tgproxy` detached, and persists only the child PID. The proxy is opt-in:
   `[model_proxy].enabled` must be true.
3. `crates/thegn-host/src/cmd/proxy.rs:175-187` exposes the start path through
   `ensure_running`. `cmd/proxy.rs:190-197` exposes `thegn proxy stop`, which
   calls the vulnerable `model_proxy_daemon::stop` path.
4. `crates/thegn-proxy/src/lib.rs:48-60` makes the listen socket the
   single-instance lock; `main.rs:9-18` loads the config and runs the daemon.
   Its Unix graceful shutdown handler is at `lib.rs:65-75`. Socket reachability
   is not proof that the pidfile PID is the incumbent process, so it cannot
   replace PID/start-time validation for cleanup.
5. `thegn_core::util::detached` gives the child its own process group, but the
   proxy stop path signals a single PID and has no owned group handle. No
   process-group signal is required for the smallest fix.

Prerequisites for implementation are therefore: retain the existing opt-in and
off-loop lifecycle; define a versioned/structured pid state containing PID plus
platform process-start identity; capture identity immediately after spawn; and
make the platform cleanup operation validate the positive PID and current
identity before delivering TERM. State-read failures, vanished processes, and
identity mismatch must remove the stale state and return the normal no-op
outcome without signalling.

## Smallest complete fix proposal

Use a private proxy state record, for example `pid=<u32>\nstart_time=<u64>\n`,
with strict parsing (reject missing, duplicate, malformed, zero, and values
above the Unix positive `i32` PID range before conversion). At spawn:

1. Spawn `tgproxy` as today.
2. Ask the Unix platform seam for its current process-start identity using the
   just-returned PID. On Linux this is `/proc/<pid>/stat` field 22; parse after
   the final `)` and fail closed if the read/parse is unavailable.
3. Persist PID plus identity only after the lookup succeeds. If identity cannot
   be established, do not publish a stoppable state record; implementation must
   also arrange bounded cleanup of the just-spawned child rather than leaving an
   untracked daemon.

At stop, parse the record without casting, validate the PID through the Unix
seam, read the current start identity, and deliver SIGTERM only when it exactly
matches the recorded identity. Re-read/validate immediately in the same seam
that performs the syscall so the caller cannot accidentally bypass the guard.
Remove the state file for every stale, malformed, vanished, or refused case.
Keep process-group signalling absent from this path; if a future group cleanup
is needed, add an explicit owned-group handle/type rather than encoding group
semantics in a signed PID.

This keeps the change limited to the two authorized production files, preserves
the existing CLI and supervisor behavior, and prevents both broad negative-PID
signals and valid-but-reused-PID termination.

## Failure cases and regression tests

Tests should be arranged so refusal is proven by observing that a live fixture
child remains alive, not merely by checking an error value:

- Pure state/PID parsing: empty and malformed records; `0`; `u32::MAX`; and
  values above `i32::MAX` whose `u32 -> i32` cast would be negative. Assert no
  platform signal operation is reached (a test seam/counter is preferable to
  relying on a real broad signal).
- Identity match: spawn a harmless fixture, capture its actual start identity,
  and verify the matching record permits TERM and the fixture exits.
- PID reuse simulation: use the same PID with a deliberately different stored
  start time; assert the identity-checked operation refuses and the fixture
  remains alive. A synthetic identity comparator can cover the deterministic
  branch; a live fixture should cover the no-signal side effect.
- Malformed/empty state and vanished process: assert cleanup removes/ignores
  state and sends no signal. For a vanished process, reap the fixture before
  invoking cleanup so the PID is known to be gone.
- Linux `/proc/<pid>/stat` parsing: include a `comm` containing spaces or `)`
  and verify field 22 is selected, plus malformed/short stat data returning
  `None` and causing fail-closed cleanup.
- Keep the existing `signal_pid` positive-range tests intact; add proxy-specific
  tests at the model-proxy/platform boundary so the vulnerable path itself is
  covered.

Do not use a broad workspace test. The primary centrally owns validation, and
the user instruction for this investigation forbids builds, Cargo, and broad
tests. No builds, Cargo commands, or tests were run for this handoff.
