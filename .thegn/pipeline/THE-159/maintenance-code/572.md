# THE-159 implementation handoff — dispatch 572

Verdict: implementation-ready

## Scope and implementation

Implemented the primary-approved Unix safety fix. No concrete design blocker
was found within the approved behavior; Windows PID/start-time identity remains
the explicitly documented follow-up from the primary plan.

- Replaced the plain `tgproxy.pid` value with strict structured state:
  `pid=<u32>` plus `start_time=<u64>` (or the Windows-deferred
  `unavailable` marker). State rejects empty, malformed, duplicate, unknown,
  zero, and values above the lossless positive `i32` range before conversion.
- Captured Linux process identity from `/proc/<pid>/stat` field 22 immediately
  after spawn. Unix refuses to publish unverified state and kills the still
  owned child if identity or state publication fails.
- Unix proxy cleanup revalidates the positive PID and start time in the
  platform seam immediately before SIGTERM. Mismatch, malformed state, stale
  state, vanished processes, and unavailable identity never signal; cleanup
  removes the state file when it was readable.
- Hardened the existing Unix `pid_alive` and direct termination paths against
  zero/out-of-range values, preventing negative `u32 -> i32` casts from
  reaching `kill(2)`. No stored-state process-group signaling was added.
- Added focused regressions for `0`, `i32::MAX + 1`, `u32::MAX`, malformed and
  empty state, malformed `/proc` data, PID reuse via a changed start time,
  vanished processes, and matching identity termination. Live refusal tests
  assert the unrelated fixture remains alive.

The small additions in `platform/mod.rs` are seam dispatch only: they keep the
daemon platform-free while routing Unix identity/termination to `unix.rs` and
retain the primary-approved Windows range-only behavior. No Windows source was
changed.
