## Finding

The bug remains on the exact branch at `d96c73fbb68ffae3fc9ea4d4ba69da26ace6217f`. `folders.repo_path` has a foreign key to `workspaces(repo_path)` (`crates/thegn-core/src/db_migrate.rs:332-342`). `Db::ensure_folder` currently searches and creates a folder without registering the parent (`crates/thegn-core/src/db_workspace.rs:737-749`); a new folder insert therefore fails if the workspace row is absent. The failure is reached before merge lifecycle can file the worktree.

The issue's source description says hydration is the only production writer. That was accurate for the initial bug, but this branch also contains THE-696's `cmd/wt.rs::file_registered_worktree` workaround (`crates/thegn-host/src/cmd/wt.rs:437-462`): it checks the tombstone, derives name/kind, calls `put_workspace`, then calls `ensure_folder`. This fixes that one CLI path. It does not fix other callers, so THE-719 remains open in source behavior.

## Production path and prerequisites

- `folders.repo_path` is `NOT NULL REFERENCES workspaces(repo_path) ON DELETE CASCADE` (`crates/thegn-core/src/db_migrate.rs:335-341`). `create_folder` inserts the folder directly (`crates/thegn-core/src/db_workspace.rs:686-694`).
- `merge_lifecycle::apply_inner` dispatches `LifecycleAction::FileInto` to `file_into` (`crates/thegn-host/src/merge_lifecycle.rs:97-104`); the normal best-effort wrapper turns an error into `merge lifecycle bookkeeping unavailable: …` (`:160-164`). Checked land-in-place returns the bookkeeping error to its caller (`:167-184`).
- `file_into` gets the recorded repo path or falls back to `repo_root`, then calls `db.ensure_folder` before assigning the folder to an existing worktree row or registering an uncached worktree (`crates/thegn-host/src/merge_lifecycle.rs:251-289`). The workspace string is deliberately selected to match the sidebar's exact string identity (`:257-263`).
- Call paths reach this from CLI merge operations (`crates/thegn-host/src/cmd/merge.rs:493, 813, 829`), merge-queue handling (`crates/thegn-host/src/handlers/merge_queue.rs:998, 1027, 1061, 1088`), queue/driver paths (`crates/thegn-host/src/merge_driver.rs:242, 288`; `crates/thegn-host/src/merge_ops.rs:150, 306, 333`), and integration persistence (`crates/thegn-host/src/integrate_persistence.rs:263, 273`). `thegn land` uses checked lifecycle filing (`crates/thegn-host/src/cmd/land.rs:118`).
- Filing is attempted when merge lifecycle policy chooses `FileInto` (enqueue/failed/landed folder outcomes); the merge lifecycle is skipped for the main checkout (`merge_lifecycle.rs:97-100`). `[merge_queue] organize_folders` defaults true (`crates/thegn-core/src/config.rs:911, 1064`), and the captured issue identifies it as the default path. A repo never opened in the TUI has no hydration-created workspace row; on a new folder, the direct `ensure_folder` call hits the FK. Existing tests generally seed the workspace first (e.g. `merge_lifecycle.rs:741, 790`; `integrate_persistence.rs:322-325`), masking the condition.
- Hydration's registration rule uses `Path::file_name` with fallback `workspace`; it calls a path a `repo` when `repo::main_worktree` succeeds and `dir` otherwise, and skips a tombstoned workspace (`crates/thegn-host/src/hydrate.rs:794-821`). THE-696 follows the same rule at its own caller (`cmd/wt.rs:443-461`).

## Smallest complete fix proposal

Move the invariant to the common `ensure_folder` operation. Extend the `WorkspaceStore::ensure_folder` inputs with caller-supplied workspace display name and kind (or an equivalent small workspace identity value). Keep Git detection in `thegn-host`: `thegn_core::repo::main_worktree` shells out (`crates/thegn-core/src/repo.rs:73-85`), while architecture requires `thegn-core` to remain substrate-free (`docs/ARCHITECTURE.md:30-31`). Core can still use the supplied values and its existing `put_workspace` rule; do not add Git/process work to the DB layer.

Inside the DB implementation, perform the tombstone check, `put_workspace`, folder lookup/create in one transaction. If tombstoned, return a clear refusal (for example, “workspace … was removed from thegn; re-add it before filing its worktrees into a folder”) before inserting either row. Propagate tombstone-query errors instead of treating them as “not tombstoned.” This makes every caller obey the same rule and closes the FK window between parent registration and folder insertion. Preserve `put_workspace` semantics: first insertion assigns sidebar position; conflict updates name/last-active without changing an existing kind (`db_workspace.rs:92-103`).

Have host call sites supply the same basename/fallback and `repo`/`dir` rule as hydration. TUI deferred work already runs in `spawn_blocking`; use the workspace kind available from its model where reliable, or compute it there. CLI/merge/integration paths are off the render loop. Keep THE-696's up-front tombstone refusal before worktree creation in `cmd/wt.rs`, but make its eventual folder operation delegate to `ensure_folder` and remove its duplicate `put_workspace`. No new idle work or on-loop Git/DB I/O is required.

## Failure cases to pin

- Missing parent workspace + a new folder: currently raw SQLite FK error; after the fix, parent and folder are present and filing succeeds.
- Tombstoned workspace + folder request: must return a clear error and leave the workspace absent (no resurrection) and no folder row.
- Existing workspace: repeated folder creation reuses the case/whitespace-insensitive folder; existing workspace kind is not downgraded and its position is not reset.
- Merge lifecycle with no workspace row: `Enqueued` files to `Merging` (and equivalent configured landed/failed folder actions) without a FK warning.
- TUI folder creation/filing and `wt folder`: all direct production callers use the same guarantee; tombstone refusal remains visible/traceable rather than being converted into a successful durable write.

## Ordered implementation and regression-test plan

1. Update the `WorkspaceStore::ensure_folder` contract and `Db` implementation to accept workspace identity/kind; make tombstone check + registration + find/create atomic. Preserve folder name normalization and existing workspace kind.
2. Update and audit all four production callers above. Centralize or consistently share host-side name/kind derivation. Remove `cmd/wt.rs`'s duplicate `put_workspace` while retaining its preflight tombstone check.
3. Add a core DB regression proving `ensure_folder` called with no workspace creates both rows; add a tombstone regression proving it errors and creates neither; retain/extend reuse and kind-preservation assertions.
4. Add a `merge_lifecycle` regression that sets up a real repo/worktree, removes the workspace row immediately before applying `LifecycleEvent::Enqueued`, then asserts workspace, `Merging` folder and worktree filing all exist. The test must not pre-seed a workspace at the lifecycle call boundary.
5. Update folder caller tests/fixtures and THE-696 tests to assert delegation and refusal behavior. Once primary approves implementation, run only scoped tests for `thegn-core` folder DB behavior and `thegn-host` merge lifecycle / `wt folder`; run no build, Cargo command, or broad suite during this investigation.
