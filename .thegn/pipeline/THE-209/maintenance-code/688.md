# THE-209 implementation report — dispatch 688

verdict: revisions-needed

Implemented the primary-approved fail-closed scope. Unknown worker liveness is
distinct from a live session and a durable row exit stamp. Unknown rows produce
an actionable `unknown` verdict, stay active and slot-occupying, and are not
terminally transitioned by CLI `--apply` or the daemon periodic reaper. The CLI
reports unknown counts and reasons in human and JSON output. Daemon querying is
bounded by a five-second timeout; connect errors, list errors, and timeout map
to unavailable liveness, while a successful empty list remains a real snapshot.

## Regression coverage added

- `pipeline_reap`: unknown spawning/running workers with a complete handoff are
  non-actionable, carry retry/reconcile guidance, and increment their own count.
- `pipeline_claim`: unknown spawning/running rows block duplicate claims and
  continue to occupy stage capacity.
- `cmd::dispatch`: separate connect failure, list failure, and timeout cases;
  a reachable empty list still reaps a row carrying an exit stamp; applying an
  unavailable-liveness plan leaves a possibly live database row running.
- `daemon::pipeline_reaper`: restart with no exit stamp leaves the row running;
  live sessions stay running; existing stamped-exit parking and successful
  handoff behavior remains covered.

## Acceptance limits and source finding

Acceptance criterion 2 is only partly met. Reaping now requires the existing
durable `exit_code` or `exited_at_ms` row stamp before classifying artifacts,
but `stamp_dispatch_exit` still writes by row id and does not bind the stamp to
the correct session or daemon generation. I made no schema migration or stamp
shape change, as directed. The apply CAS still checks observed status only, so
the liveness/exit generation CAS criterion remains unfulfilled pending that
follow-up. THE-208 Lead ownership also remains out of scope.

The existing daemon reaper has a `CloseDone` to `done` transition, although the
primary plan prose describes it as park-only. I preserved the source behavior;
the change only makes unknown liveness non-actionable in both callers.
