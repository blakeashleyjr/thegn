## Implemented

- Extended the existing off-loop PR-queue pass to deep-fetch and reconcile
  review snapshots only when the explicit repo queue configuration watches
  `review`. Successful snapshots update THE-27's cache and chunk 1's roster;
  transient forge failures preserve stale tasks.
- Persisted once-keyed queued/revised/resolved notifications and emitted each
  bounded `pr.thread_unresolved` payload only after its atomic roster upsert.
  The refresh path does not launch a review agent, so a future automation
  consumer cannot race a second implicit dispatch.
- Suppressed the aggregate `ChangesRequested -> PrReview` runner whenever the
  per-thread reconciler owns review work. Empty provider aggregates remain
  human-visible instead of producing an empty generic task; CI, conflict, and
  merge decisions retain their existing paths.
- Added `review_task_handoff.rs` for the TUI-only lifecycle: queued-to-running
  persistence, exact configured role/command resolution with no default-role
  fallback, existing sandbox-floor enforcement, and the existing generic
  off-loop agent runner with the durable prompt.
- Made agent exit advisory. Resolution requires an unchanged pre-run baseline,
  a moved post-run PR head exactly equal to the task worktree's local HEAD, an
  unchanged task revision, a still-unresolved provider thread, and an expired
  durable cooldown before calling `Forge::resolve_review_thread`.
- Parked missing configuration, foreign/concurrent pushes, unsupported/auth/
  transient/rate-limited provider failures, and PR-level review decisions as
  `waiting_human`, with durable audit notifications and backoff where safe.
- Hydrated exact PR/thread/anchor/role/status/revision task rows from the
  durable roster plus THE-27's cached snapshot, rendered them under their
  watched PR, and wired the same `pr-review-task-handle` behavior to panel `h`
  and the command palette.
