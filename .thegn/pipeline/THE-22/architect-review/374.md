## Blocking findings

1. `pr_driver::refresh_review_tasks` substitutes `repo_root` when a queue row
   has no worktree and persists that path into the durable task. The handle
   guard therefore sees a worktree and can run the agent in the canonical
   checkout, contrary to the established by-number PR safety fallback.
2. Reconciliation overwrites the revision, prompt, expected head, role, and
   cooldown of a running row. Since head is part of the revision, the normal
   remote refresh caused by the agent's own push can change the row before the
   handler's post-run check, forcing a spurious requeue; a concurrent new
   comment also destroys the active durable inputs instead of becoming safe
   pending work.
3. The structured `ReviewTaskEvent` is logged and then projected only as a
   generic `NotificationReceived` event. No internal subscriber receives the
   required `pr.thread_unresolved` event and payload after the durable upsert.

These are lifecycle/safety defects, not style issues, so approval-with-notes
would be unsafe. They are consolidated into one revision chunk to avoid
multiple coder/build rounds.
