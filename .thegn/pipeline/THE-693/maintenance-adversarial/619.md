## Findings

### F1 — excluded raw MQ commands can be deleted as seeded state (high)

`crates/thegn-host/src/skill_seed.rs:79-123` adds both the raw and
marker-wrapped bytes for every MQ command to the cleanup authority, without
considering `cfg.skills.exclude`. The writer takes the opposite path at
`crates/thegn-host/src/skill_seed.rs:746-766`: when `mq` is excluded it treats
the command as user state and only removes it if `inspect_managed` proves an
existing marker. Therefore, in a repository where the path is not ignored, a
user can create an exact raw `mq-add.md` while `skills.exclude = ["mq"]`; the
cleanup status scan accepts it as seeded and the automatic sweep deletes it,
although the configured writer would not have produced or removed that file.

Regression coverage was added at
`crates/thegn-host/src/merge_cleanup_tests.rs:511-533`. It is expected to fail
against this revision until the authority mirrors the exclusion semantics.
The fix should derive the accepted bytes from the effective seeding plan (or at
minimum omit excluded raw command bytes), while retaining conservative
protection for unmarked files.

### F2 — final seeded-file validation has a deletion TOCTOU (high)

`crates/thegn-host/src/merge_cleanup.rs:741-751` reads and validates the
expected bytes, then unlinks by pathname in a separate operation. A user or
another local process can replace that exact untracked file after the read and
before `remove_file`; cleanup then unlinks the replacement. The subsequent
non-forced `git worktree remove` cannot backstop this case because the path has
already been removed by the cleanup code. The surrounding comment at
`crates/thegn-host/src/merge_cleanup.rs:1020-1032` explicitly acknowledges a
remaining race, but the remaining window still permits user-data loss and is
not covered by a deterministic regression test.

The final removal step needs an ownership-preserving strategy that does not
unlink a pathname after an unprotected content read (or must conservatively
leave seeded files for a mechanism with an atomic identity check). At minimum,
add a race-oriented test/design note explaining the platform guarantees and
what happens when replacement is detected; do not claim the current final byte
check closes the race.
