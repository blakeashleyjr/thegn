## Smallest complete implementation shape

Introduce a host-side, batch live-worktree snapshot keyed by canonical worktree path, using the existing `GitBackend::worktrees(root)` / `git worktree list --porcelain` seam once per local repository. Build/use it only from the existing blocking hydration worker or other already-off-loop command/daemon workers; never invoke Git from `run.rs` or rendering. Feed all hydrated consumers a transient current-branch value, including dormant rows, PR joins, event context, and worktree-list projections. For remote rows, resolve through the row’s `GitLoc` with `current_branch`; on failure/detached HEAD, represent unknown rather than authorize behavior from cached branch. `worktrees.branch` may remain as creation/display fallback metadata but must not authorize a decision.

Add `BranchRow.held_by` (or equivalent explicit worktree-path list) based on the same repository worktree snapshot in branch-panel hydration. Keep `is_head` as “the branch checked out by this panel’s worktree.” The branch menu/delete handler must either omit delete or give a clear held-by explanation when another worktree owns the branch. Recheck at the existing off-loop Git operation boundary to preserve Git as the final authority; that race handling remains THE-697’s separate scope.

No schema migration, watcher, background thread, wake source, feature, or worktree creation/naming change is needed. The snapshot’s path normalization and detached/unborn branch representation need to follow existing `GitBackend::worktrees` semantics; do not hand-parse porcelain independently in each caller.

## Failure cases to preserve

- External branch checkout/rename: displayed and consumed branch changes on the next model refresh; old branch must not be used for PR badge, event context, dispatch env, or branch-name target resolution.
- Same branch checked out in a sibling worktree: branch panel exposes the holder and suppresses/explains delete; current worktree `is_head` behavior still works.
- Detached HEAD, unborn worktree, deleted path, missing Git, provider failure, or malformed/unavailable snapshot: no stale branch may become authority; preserve the worktree row and fail closed for branch-dependent cleanup/mutation.
- Multiple worktrees holding different branches and duplicate/stale DB branch values: path-to-HEAD association must be exact; do not match by registry branch.
- Remote worktree: query its configured Git location without touching a similarly named host path; missing remote connection yields unknown, not cached authority.
- Existing home worktree identity remains stable even when its live Git branch is `main` or another name.

## Ordered implementation and test plan

1. Add a pure host helper that joins a batch Git worktree snapshot to registry rows by normalized path and explicitly represents detached/unavailable entries. Unit-test porcelain/seam mapping for multiple branches, detached HEAD, and a changed checkout.
2. In model hydration’s existing off-loop worker, collect the per-repository snapshot once and provide it to sidebar rows, dormant-row branch display, PR badge joins, and PR-close cleanup. Keep current live glyph scans/cache behavior and make their freshness/error policy consistent with this snapshot.
3. Reconcile the remaining registry consumers: `wt rm` branch lookup; local/remote agent/tool/dispatch branch context; `worktrees.list`; automation event enrichment; home identity; disk/palette labels. Keep `thegn list` Git-first and keep merge-queue outcome identities separate.
4. Populate branch-panel `held_by` from Git’s worktree list in off-loop branch hydration. Extend the row/menu action policy so a sibling-held branch has no misleading delete action or names its holder. Preserve the existing current-HEAD restriction.
5. Add focused regression tests using temporary Git repositories and ordinary `git` commands (no `thegn wt new`); fixture commits must pass `-c commit.gpgsign=false` per coordination. Cover outside checkout reflected in the reconciled value, stale DB value never selected for branch-sensitive behavior, and sibling-held branch delete policy. Add a narrow UI policy test for free/current/other-worktree branches.
6. After primary review/greenlight, run the specifically approved narrow crate checks only if permitted by the active implementation prompt. No build, Cargo, or tests were run during this investigation.
