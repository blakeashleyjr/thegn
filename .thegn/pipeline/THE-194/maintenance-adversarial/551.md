## Finding and disposition

### F-1 — golden test previously allowed truncated/extra lifecycle output

- **Location:** `crates/thegn-svc/tests/plugin_example.rs:60-71` (the
  assertions added in this review); the prior implementation only asserted
  `run.junk.is_empty()` before applying every parsed message.
- **Risk:** `spawn_ndjson` intentionally caps collected lines and reports
  `PluginRun::truncated`. Without checking that flag, a stale or hostile
  version of the exact checked-in script could emit valid NDJSON beyond the
  cap and still pass if the retained prefix registered and rendered the
  expected view. The prior loop also accepted additional valid frames, so the
  golden test did not pin the bundled one-shot lifecycle as tightly as the
  acceptance criterion's exact-file/drift guard requires.
- **Disposition:** resolved in this review's test-only change. The golden test
  now requires no truncation, exactly two messages, and the exact
  `register`-then-`update` sequence. No production code was changed.
