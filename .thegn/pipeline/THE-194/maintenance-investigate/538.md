## Finding: the bug remains

The shipped script currently emits this register frame at
`examples/plugins/hello.sh:12`:

```json
{"method":"register","params":{"plugin":"hello","contribution":{"id":"hello.seg","extension_point":"StatusBarSegment","label":"Hello","surface":"hello.segment"}}}
```

The public wire model defines `Contribution` as a flat object with required
`id`, `extension_point`, `label`, and optional `surface`, `cadence`, metadata,
caps, and chord (`crates/thegn-core/src/plugin_api.rs:266-286`). The production
handler takes the whole `msg.params` and deserializes it directly as
`Contribution` (`crates/thegn-host/src/handlers/plugins.rs:549-609`, especially
597-603). The current script's root object has no `id`; its `id` is nested
under the unknown `contribution` key. Therefore the exact shipped register
frame is invalid for the current protocol and maps to an invalid-params
diagnostic (`RpcErrorCode::Invalid`, with `bad contribution: ...`) when an
id-bearing request is answered by the handler (`handlers/plugins.rs:517-526,
727-735`). A notification without an id is only logged/dropped on this error.

The direct handler path is load-bearing in production:

1. `crates/thegn-host/src/run.rs` starts the plugin host after the first frame;
   this preserves the 0%-idle/startup invariants in `CLAUDE.md` and
   `docs/ARCHITECTURE.md`.
2. `crates/thegn-host/src/plugins.rs:264-335` discovers plugins, negotiates
   each manifest, schedules interval contributions, and queues loaded state.
   `:337-377` runs a one-shot plugin off-loop and sends its `PluginRun` back
   through the channel and waker.
3. `crates/thegn-host/src/handlers/plugins.rs:387-439` drains one-shot or
   resident messages; both routes call `apply_message`.
4. `apply_message` maps `register` to the direct `Contribution` decode above,
   then calls `PluginRuntime::register`. `update` separately decodes its flat
   `surface` plus `view` params (`:610-629`).

The test bypass is at `crates/thegn-svc/tests/plugin_example.rs:52-60` and
`:65-81`: it does run the staged copy of the exact `examples/plugins/hello.sh`
file through `spawn_ndjson`, but at `:67-69` ignores `msg.params` and clones
`neg.accepted_contributions[0]`. Thus the malformed register frame never gets
decoded or rejected, while the later update still renders against the runtime
surface cache seeded from the negotiated manifest. This explains how the
golden test stays green despite the shipped script being invalid.

  `surface:statusbar`, command `sh ../hello.sh`, one-shot mode, and the
  `hello.seg` interval contribution. The fixture's comments should continue to
  describe the manifest-owned cadence and the contribution's flat register
  payload accurately.

`crates/thegn-host/src/handlers/plugins.rs:597-609`: cover the old nested

`PluginRuntime`, negotiation, or the wire contract to accommodate the example.

Failure cases the regression coverage must lock down:

1. The old nested `{plugin, contribution}` params must not be accepted as a

2. The corrected flat payload must parse from the script's actual output and
   register, then the script's actual update must render `hello from a plugin`.
3. A stale id, extension point, label/surface, or cadence in the checked-in
   script must fail the golden test rather than silently substituting the
   manifest contribution.
4. Junk output and unexpected methods remain failures of the example test;
   no permissive test-time rewrite should be introduced.
