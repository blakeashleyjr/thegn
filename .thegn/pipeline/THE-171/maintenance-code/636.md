# THE-171 implementation report — dispatch 636

## Changes made

- Unix PTY teardown now verifies the process group is still present after the TERM grace and that its immutable PGID matches the still-owned child PID before sending SIGKILL. ESRCH means the group exited and no KILL is sent; inconclusive errors are logged and leave the group untouched. The child remains unreaped until after this operation, preventing its PID/PGID from being reused during the check and signal. The code documents that liveness check and signal are separate syscalls; a group can exit in between, but the retained child identity prevents the signal from being retargeted to a reused group.
- The pane-drop site now explains why it does not join the PTY reader on the UI thread: its bounded-channel send may wait for that same event loop, so joining can deadlock it.
- Windows Job Object teardown remains an immediate hard kill with no graceful TERM interval; this limitation is documented beside the Windows handle operation. Windows integration coverage remains outstanding.
- Added `pty_owner_tests::natural_exit_racing_kill_is_owned_and_reaped_once`. The fixture creates a private process group, asserts its child PID is its PGID before teardown, overlaps the owner Kill call with a natural-exit path, and counts the actual child `wait()` call to assert one reap. Existing concurrent teardown coverage continues to cover a child and grandchild.
