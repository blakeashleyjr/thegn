# THE-171 implementation report — dispatch 645

verdict: implementation-ready

## Revision 2 corrections

- PTY process-group teardown now sends TERM, waits the bounded grace period,
  then unconditionally sends KILL while the direct child remains unreaped.
  `killpg` treats ESRCH as an already-empty group. The signal-site comment
  explains that a PGID cannot be reused while members remain, so signaling
  after the leader exits is safe and necessary to terminate surviving
  descendants. The stored proxy-PID path remains identity-checked immediately
  before signaling.
- Removed the group leader liveness probe that skipped KILL after the leader
  exited. This was the path that left a surviving grandchild running.
- Reworked `natural_exit_racing_kill_is_owned_and_reaped_once`: it spawns
  `sh -c 'exit 0'`, uses `waitid(WEXITED | WNOWAIT)` to observe exit without
  releasing the child identity, then has two threads call the same owner
  concurrently. Both calls must return exit code 0, and the counted child wait
  must run exactly once. The fixture checks that its child PID is its PGID
  before teardown; there is no marker file or sleep-based test synchronization.
- Added the same private-PGID guard to the child/grandchild group teardown test.

## Accepted limitations

- Pane Drop deliberately does not join the reader on the UI thread: the reader
  can be blocked sending to the bounded channel drained by that loop. The daemon
  actor still closes its receiver and joins the reader off-runtime.
- Windows Job Object PTY teardown remains a hard kill; Windows integration
  coverage is still outstanding.
