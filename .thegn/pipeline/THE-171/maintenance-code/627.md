# THE-171 implementation report — dispatch 627

Verdict: `revisions-needed`

## Changes made

- Added a shared per-child PTY process owner. It serializes signal and reap
  paths, retains the child handle through Unix TERM/grace/KILL, and binds
  Windows PTY children to a kill-on-close Job Object through `platform/`.
- Routed ordinary PTY pane drop and daemon actor teardown through that owner;
  the detached reader now calls the same idempotent teardown path on EOF.
- Added a daemon shutdown coordinator that refuses new opens, snapshots and
  kills live sessions, waits for session removal, and joins retained actor task
  receipts. Signal/idle listener shutdown also invokes this coordinator before
  daemon registry and lease cleanup.
- Retained a PTY reader-thread receipt for daemon actors. The actor closes its
  receiver and joins the reader off the runtime before recording and database
  teardown.
- Added state-directory JSON lifecycle records containing daemon generation,
  session id, pid, phase, result, and update time. They are diagnostic-only;
  no recovery code loads or signals a persisted pid.
- Added a Unix regression test that owns a TERM-resistant child and grandchild
  and races two teardown calls through the same owner.

## Findings and limits

- The added regression test exercises the lifecycle owner with a private
  process group, but it does not yet exercise a real PTY actor's simultaneous
  Kill/Exit race or assert that all PTY descriptors are closed. Pane drop does
  not join its reader on the UI thread because that reader can be blocked
  sending to the shared bounded event channel; joining there could deadlock the
  event loop. The daemon path does close the receiver and join the reader.
- Unix teardown sends TERM, waits 300 ms, sends KILL while the direct child is
  still unreaped, then waits the child. It does not query group liveness before
  KILL. Windows Job Object termination is the existing hard-kill behavior, so
  there is no graceful Windows TERM window. Platform-specific Windows
  integration coverage remains outstanding.
- Rust compilation and test gates were not run, as required by the dispatch
  instruction to avoid Cargo/build/test workloads while the primary schedules
  validation centrally. Formatting and `git diff --check` passed. No full gate
  result is available, so this report does not claim implementation-ready.
