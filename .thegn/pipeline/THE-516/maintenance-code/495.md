## Findings addressed

- Identity encoding now returns typed errors, checks every component and the
  aggregate length with checked arithmetic before allocation, and distinguishes
  component and encoded-size bounds. ExactPath preflights borrowed native path
  bytes; display labels stop at the output budget while raw authority bytes are
  retained separately. Repository/worktree digest constructors are fallible.
- Git identity capture uses a bounded temporary-file stream, a two-second
  deadline, output-size checks, child cleanup, and the existing hardened
  `git_cmd` environment. It has no reader thread that can outlive a timeout.
- Worktree inspection captures the common directory before and after listing,
  rechecks common/admin identity across the multi-probe sequence, captures an
  OS admin-directory instance stamp for generation, and refuses unsupported
  stamps. Git porcelain parsing requires complete NUL framing, preserves a
  final CR byte, and rejects duplicate/conflicting branch or detached fields.
  Inspection fields are private with explicit projections.
- The ledger now represents detached branches as `NULL`, bounds values before
  SQLite decoding/allocation, requires consistent quarantine state/reasons, and
  uses partial uniqueness only for verified claims. Legacy/quarantined claims
  can coexist; promotion reports verified conflicts instead of selecting a
  first row. Expected generation plus operation/reconciliation revision are
  required for transitions, and each successful transition advances revision.
- v69 migration now rebuilds the prior foundation table into the corrected
  shape when recognizable, preserves claims, creates verified-only unique
  indices, validates the complete table/index shape before stamping, and fails
  closed on malformed pre-existing tables. Focused fixtures cover duplicate
  v68 legacy rows and malformed ledgers.
