# THE-516 foundation correction — native dispatch row 509

verdict: implementation-ready

This dispatch implements the primary revision-3 corrections within the
approved foundation chunks 1–2. It does not claim THE-516 is complete and does
not migrate allocation, tab/routing consumers, rename publication, feature
membership, or downstream provider/cache identities.

## Implemented

- Reworked the core Git identity stdout capture around a fixed two-slot
  ownership budget and one bounded shared reaper queue established before
  child spawn. Reader ownership, child ownership, setup failure, early leader
  exit, overflow, timeout, and reaping errors now retain capacity until the
  corresponding ownership is settled; unresolved queue/ownership failures
  fail closed rather than spawning an unbounded succession of helpers.
- Unix identity probes retain process-group cleanup while the direct child is
  still owned and unreaped, avoiding numeric-PID signaling after ownership is
  uncertain. Windows remains explicitly weaker: this core seam can kill only
  the direct child, so a descendant retaining stdout may retain one of the
  finite capture slots until it exits; no Windows descendant-containment
  parity is claimed.
- Corrected the injected-child capture regressions for mutable `Command`
  bindings and ensured the helper owns a piped stdout. Added finite-budget and
  reader-setup-failure regressions alongside the existing idle, overflow, and
  inherited-pipe cases.
- Changed Git admin generation capture to retain the opened `same-file`
  handle through inspection and to require creation metadata read from that
  same handle. The stamp combines the handle object identity with the
  supported OS creation identity; it fails closed when creation metadata is
  unavailable and no longer uses mutable ctime or inode/device alone.
- Fixed the inspected-record ownership compile defect by making the exact
  record cloneable and comparing retained generation stamp bytes explicitly.
- Added borrowed `ValueRef` preflight for worktree claim enumeration and
  legacy verification. Path enumeration now performs bounded row/aggregate
  checks before decoding retained vectors/strings, inside one read
  transaction; promotion uses bounded preflight and indexed `EXISTS` checks
  for both exact path and `(repo_id, admin_id)` conflicts.
- Added path and repository/admin lookup indexes, including the ordering
  needed by bounded `LIMIT` enumeration.
- Centralized the v69 ledger table DDL and made schema verification compare the
  exact canonical shape, in addition to column and index metadata. This
  rejects wrong types, non-unique indexes, wrong predicates, and CHECK text
  hidden in comments. Added fixtures for each case.

## Unverified work and concrete limitations

- No Cargo command, build, nextest, Clippy, or full test suite was run because
  Rust validation is centrally scheduled by the primary.
- Linux source/test fixtures do not establish macOS or Windows compilation,
  native path/ref behavior, or Windows process-tree cleanup. The Windows
  direct-child limitation above requires platform validation and/or a
  platform-owned job-object seam before stronger guarantees can be claimed.
- The full THE-516 acceptance criteria remain open beyond chunks 1–2:
  collision-resistant allocation/creation doors, opaque tab and downstream
  routing, journaled rename/recovery, feature IDs/membership migration,
  legacy admission/quarantine integration, and sandbox/provider/cache
  consumer migration. These are explicit primary-deferred chunks, not omitted
  acceptance criteria in this dispatch.
