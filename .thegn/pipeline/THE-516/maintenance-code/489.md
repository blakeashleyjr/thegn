# THE-516 foundation implementation — native dispatch row 489

Verdict: implementation-ready

Implemented the primary-approved chunks 1–2 only. This is a partial
foundation handoff and does not claim THE-516 is complete.

## Implemented

- Added versioned, domain-separated, length-delimited identity encoding with
  full SHA-256 digests and bounded inputs.
- Added immutable `ExactPath`, bounded `BranchRef`, `RepositoryId`,
  `WorktreeId`, and `WorktreeGeneration` types. Exact native path bytes are
  captured in the existing utility boundary; display labels are bounded and
  never parsed back into authority.
- Added `repo::canonical_common_dir` and `repo::repository_id`. Repository IDs
  use the canonical Git common directory, not origin or basename. Moving that
  directory intentionally changes the ID and requires explicit trusted-overlay
  migration.
- Added bounded, byte-oriented Git worktree inspection through
  `worktree::inspect_registered`, including exact registered path, common dir,
  admin dir, and branch ref. Missing, ambiguous, failed, and unsupported
  representations have distinct typed errors.
- Added schema v69. It creates an exact BLOB-backed `worktree_instances`
  ledger with uniqueness on admitted instance/path and `(repo_id, admin_id)`,
  plus nullable compatibility identity/state/quarantine columns on legacy
  `worktrees` and `tab_groups` rows.
- Added DB ledger APIs for exact insert/read/path enumeration, explicit
  quarantine/split transitions, and legacy-to-verified promotion. These APIs
  do not probe Git; admission ownership remains with the existing background
  reconciliation lanes. No legacy rows are silently backfilled or selected by
  first-row lookup.
- Added regression tests for encoding vectors, alias separation, display
  bounds, unsupported/relative inputs, raw branch parsing, repository identity
  separation, Git inspection, additive schema shape, malformed identity
  lengths, uniqueness, and quarantine behavior.

## Scope deliberately not implemented

The approved boundary keeps old callers and behavior APIs intact. Therefore
lossy allocation paths, slug-based tab routing, repository-slug fallbacks,
creation-door migration, opaque consumer routing, journaled rename/recovery,
feature IDs/membership migration, and downstream sandbox/provider/cache
consumer migration remain for later approved chunks. These are explicit
design dependencies, not silently omitted acceptance criteria.

Schema migration performs no Git/filesystem inspection. Existing legacy rows
remain legacy until a later background admission lane proves one exact Git
claim; ambiguous claimants must be quarantined before routing, mutation,
cleanup, or deletion.
