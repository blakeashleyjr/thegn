## Decisions that make the chunks implementable

### Authority and exact encoding

Git remains the source of truth. The exact repository identity is derived from
the canonical absolute Git common directory returned by Git, not from origin,
basename, or a DB slug. A repository opened through a symlink is resolved to
the same Git common directory before identity bytes are formed. A failed or
ambiguous common-directory probe is a typed refusal for authority operations.

Add a core `identity` module with versioned types (names are proposed API, not
existing API):

```text
RepositoryId([u8; 32])
BranchRef { raw: Vec<u8>, display: String }
WorktreeId([u8; 32])
WorktreeGeneration([u8; 16])
WorktreeInstance { id, generation, repo, admin_id, branch, path, owner }
```

The byte encoding is domain-tagged, versioned, and length-delimited (u64
big-endian length followed by exact bytes). SHA-256 is already available to
`thegn-core`; retain the full 32-byte digest and render all 64 hex digits when
the ID is used in a path or wire value. Readable prefixes are optional labels
after the digest, never substitutes for it. Do not use six/eight-character
hashes, `to_string_lossy`, normalized branch text, or a remote URL in an
authority key.

`BranchRef` and Git path/admin identifiers must travel through `OsStr`/raw
bytes on platforms that support them. The platform adapter returns a typed
`UnsupportedIdentityEncoding` before any branch, worktree, DB, or filesystem
mutation when exact preservation is unavailable. Display conversion is
separate and may escape bytes; it is never parsed back into authority.

`WorktreeGeneration` is minted once per create attempt from OS randomness and
is never regenerated during retries or rename. `WorktreeId` is the full digest
of the versioned repository ID, generation, and exact allocation inputs. The
candidate path is selected from the full digest of `(repo_id, raw branch ref,
generation, path mode)` and has a fixed bounded component shape:

```text
in-repo:  <root>/.worktrees/<repo-id>/<worktree-id>-<display-label>
external: <worktrees_dir>/<repo-id>/<worktree-id>-<display-label>
```

The label is bounded, escaped display text only. A pre-existing path, symlink,
or digest collision is a refusal, not permission to reuse. After `git worktree
add`, the allocator reads Git's exact common directory, worktree administrative
directory/id, raw branch ref, and registered path and verifies every field
against the requested `WorktreeInstance`. The path is therefore collision
resistant without making a path-side manifest authoritative.

There is no new user-facing manifest source of truth. The DB stores an exact
identity ledger/cache for fast lookup and migration state; Git metadata is
revalidated before attach, reuse, move, mutation, and cleanup. A small private
rename/migration journal is allowed only for incomplete transactions and is
replayed against Git; it cannot authorize a worktree that Git does not prove.

### Legacy, degraded, and generation policy

Existing worktrees stay at their current paths. Startup/admission enumerates
Git worktree metadata and maps a legacy DB row only when common directory,
registered path, admin id, and raw branch ref have one exact claimant. No
mass-move is performed. A duplicate path/tab, missing claimant, lossy-only
match, or DB row with competing candidates becomes `quarantined`; it is shown
read-only with an explicit diagnostic and cannot be opened, routed, assigned,
moved, or deleted by identity inference. `LIMIT 1` is removed from authority
lookups.

If the DB cannot open or an identity lookup fails, mutation/registration,
cleanup, and routing fail closed. Read-only hydration may use a last-known
exact mapping already in memory or a verified Git result; it may not fabricate
an unsuffixed basename slug. A new Git admin identity or new allocation nonce
is a new generation. A branch label rename keeps the same generation; a
delete-and-create receives a different generation even if the branch text is
reused. Events and async completions carry the opaque generation and are
discarded when it no longer matches the live instance.

### Rename and feature policy

Retain the current user-visible behavior that a branch rename may move the
checkout to the newly labelled path, but make it transactional. The opaque
instance ID/generation and provider identity do not change. The transaction
preflights both paths and all exact claimants under the repository mutation
lock, journals the expected Git admin id/common dir/old and new raw refs,
renames the branch, moves the registered Git worktree, revalidates Git, then
updates the cache/tab/provider bindings. It attempts a branch rollback when
the move fails; if rollback or the cache update fails, it persists a typed
recoverable split state and reports failure, never success. Startup recovery
chooses the exact old/new Git state or leaves the journal for explicit repair.

Features get an explicit `FeatureId` and persisted member rows. A display name
or proposed branch label remains user-facing input only. Legacy feature links
are migrated only when every member has one exact branch/ref claimant; aliases
that normalize alike are quarantined and never silently federated.

## Ordered implementation chunks

The chunks are intentionally serial. A later chunk must not be started until
the preceding chunk's focused tests and review are complete. Each chunk names
the production scope it is allowed to touch and the regression tests that make
its boundary observable.

### Chunk 1 — typed canonical identities and lossless Git inspection

Depends on: none. First chunk recommendation.

Scope:

- Add `crates/thegn-core/src/identity.rs` and export it from `lib.rs`.
- Add only the Git metadata/byte transport helpers needed by the identity
  types in `crates/thegn-core/src/repo.rs`, `worktree.rs`, and `util.rs`.
- Keep existing callers on their old APIs for this chunk; do not change path,
  tab, or DB behavior yet.

Exact APIs to provide:

```text
repo::canonical_common_dir(root) -> Result<ExactPath, IdentityError>
repo::repository_id(root) -> Result<RepositoryId, IdentityError>
worktree::inspect_registered(root, path) -> Result<GitWorktreeIdentity, IdentityError>
identity::encode_parts(domain, &[BytePart]) -> Vec<u8>
identity::display_label(raw) -> DisplayLabel
```

`inspect_registered` must identify the exact Git common directory, admin
directory/id, registered path, and branch ref without lossy porcelain parsing.
It must distinguish “not registered,” “ambiguous,” “Git probe failed,” and
“unsupported byte representation.”

Regression tests to add in `thegn-core`:

- Known-vector tests prove length-prefix/domain separation and full digest
  stability; changing a delimiter, repo common-dir byte, admin id, or raw ref
  changes the result.
- `feat/a`, `feat-a`, `feat_a`, case variants, Unicode labels, empty labels,
  and overlong labels have distinct authority inputs while bounded display
  labels remain non-authoritative.
- Unix raw-byte branch/path tests preserve bytes through Git inspection where
  the platform permits them; an unsupported platform/representation returns
  the typed refusal before mutation.
- Relative path, symlink alias, same-basename roots, missing common dir, and
  ambiguous Git metadata cases are explicit tests.

### Chunk 2 — identity ledger schema, compatibility, and quarantine

Depends on: Chunk 1.

Scope:

- Extend `crates/thegn-core/src/models.rs`, `store/workspace.rs`,
  `db_workspace.rs`, `db.rs`, and `db_migrate.rs`; add a focused
  `store/worktree_identity.rs`/`db_worktree_identity.rs` seam if that keeps
  the existing workspace god-file smaller.
- Do not change creation doors or silently backfill ambiguous rows.

Add an additive schema version and an identity ledger with exact BLOB fields,
not lossy TEXT authority fields:

```text
worktree_instances(
  instance_id BLOB PRIMARY KEY,
  generation BLOB NOT NULL,
  repo_id BLOB NOT NULL,
  common_dir BLOB NOT NULL,
  admin_id BLOB NOT NULL,
  branch_ref BLOB NOT NULL,
  path BLOB NOT NULL,
  owner BLOB NOT NULL,
  state TEXT NOT NULL,             -- verified|legacy|quarantined|split
  created_at INTEGER NOT NULL,
  UNIQUE(repo_id, admin_id), UNIQUE(path)
)
```

Add a nullable `instance_id` to `worktrees` and `tab_groups` first, preserving
old path/tab columns for compatibility reads. Add explicit identity state and
quarantine reason. Do not turn every cache into an authority FK in one blanket
rewrite: classify each existing `worktree`/`worktree_path` column as routing,
durable binding, or disposable cache, then migrate only the first two classes
in the later routing chunk. The DB ledger is a cache/reconciliation record;
Git verification remains mandatory.

Migration behavior and tests:

- Fresh DBs create the ledger and enforce uniqueness on opaque instance ID,
  exact path, and `(repo_id, admin_id)`.
- A legacy row is promoted only after an exact Git match. Duplicate tabs,
  same path with different claimants, and same-basename repos are quarantined;
  migration never picks the first SQL row.
- Migration is idempotent and leaves legacy paths untouched. A DB open/read
  failure produces a typed “authority unavailable” result and never returns a
  basename fallback. Read-only APIs expose last-known exact labels only.
- Fault tests cover interrupted migration before each row/state transition,
  newer schema refusal, malformed BLOB lengths, duplicate uniqueness claims,
  and reopening after quarantine.

Depends on: Chunks 1–2.

  or a new `worktree_identity.rs` module; update `repo.rs` only for identity
  resolution.
- Update `store/workspace.rs`, `db_workspace.rs`, and lifecycle helpers needed
  to register/delete by `WorktreeInstance`.
- Keep old entrypoints as thin compatibility wrappers only until Chunk 4.

Replace authority use of `worktree_path(root, branch, cfg)` with a fallible
allocator API:

```text
WorktreeAllocator::create(root, branch_ref, base, owner, cfg, db)
  -> Result<WorktreeInstance, WorktreeCreateError>
verify_instance(root, instance) -> Result<VerifiedInstance, IdentityError>
resolve_instance(root, path_or_id) -> Result<VerifiedInstance, IdentityError>
remove_instance(root, instance, delete_branch) -> Result<RemoveReceipt, IdentityError>
```

The allocator holds `util::lock_git_mutations(root)` from candidate selection
through Git add and verification, rejects a pre-created path or symlink, uses
the exact `OsStr` branch/ref, and records the verified ledger/cache row only
after Git proves the result. Cleanup revalidates common dir, admin id, path,
branch ref, owner, and generation immediately before removal; an unregistered
or ambiguous path is retained and quarantined.

Tests must prove two exact branches and two same-basename repositories produce
distinct bounded paths and instance IDs; a pre-created directory, symlink,
path swap, duplicate claim, failed Git add, and concurrent create cannot reuse
or delete another claimant. A remove/recreate test proves the generation
changes. These are core tests, not only host smoke coverage.

Every door receives and propagates `WorktreeInstance`/opaque generation rather
than recomputing `repo_slug`, `branch_tab`, or `worktree_path`. Creation events,
optimistic placeholders, issue/autopilot rows, lifecycle hooks, and DB writes
carry the instance ID; branch/repo text is display-only. The optimistic TUI
path may show a provisional label, but it cannot open or reconcile by a
slugged tab string. If DB registration fails, the verified Git worktree remains
reachable and is surfaced as an exact unregistered/quarantined instance rather
than being routed under a fallback tab.

Add host regressions for each door (wizard, CLI, daemon/control, tracker,
autopilot, merge/external registration): two colliding labels create two
independent instances; a restart or retry attaches the same generation; a DB
failure refuses authority; and an async completion for an old generation is
ignored after a replacement.

### Chunk 6 — journaled rename and recovery

Depends on: Chunks 3–5.

Scope:

- `crates/thegn-core/src/worktree.rs` and the new private journal seam
- `crates/thegn-host/src/handlers/worktree_rename.rs`
- rename handling in `crates/thegn-host/src/wizard.rs`
- identity-aware provider/sandbox calls in `provider_factory.rs`, `agent.rs`,
  `hibernator.rs`, `share.rs`, and `sandbox_events.rs`

Expose a transaction API such as:

```text
rename_instance(root, instance_id, expected_generation, new_branch, cfg, db)
  -> Result<RenameReceipt, RenameError>
recover_pending_renames(root, db) -> Result<RecoveryReport, RenameError>
```

Under the Git mutation lock, preflight the exact old instance, destination
path, branch/ref namespace, and all dependent claimants. Journal old/new raw
refs, paths, admin id, common dir, instance/generation, and the next step.
Perform branch rename, Git worktree move, post-move Git verification, then one
cache/tab/provider publication step with generation CAS. Attempt branch/path
rollback on each failure. If rollback is impossible, leave `split` journal
state with exact facts and a recoverable old/new choice; never swallow the
failure or update the UI as successful. A stale completion cannot publish over
a newer generation.

Fault-inject after branch rename, after worktree move, after ledger/journal
publication, after DB update, and after provider update. Also test destination
pre-creation, concurrent rename, path swap, DB lock/failure, Git move failure,
restart recovery, and stable provider identity across the move. Existing
physical path movement remains supported here because the opaque instance ID,
not the path or tab label, is the stable identity.
