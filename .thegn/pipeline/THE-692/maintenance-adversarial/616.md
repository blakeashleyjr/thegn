## Finding 1 — acceptance-critical manual-land dispatcher is not exercised (P2)

The required `UpToDate` create-if-absent path is implemented at
`crates/thegn-host/src/cmd/land.rs:156-164`, but no test invokes `run` with an
already-contained branch and no existing queue row. The smoke scenario at
`test/smoke.sh:906-920` first lands a new branch (creating the row through the
`Landed` arm), then exercises `UpToDate` only against that already-landed row.
The existing helper test at `crates/thegn-host/src/cmd/land.rs:353-370` proves
the writer can insert a final row, but it does not prove the `UpToDate` arm
passes its verified commit identity, target, and non-root context through to
that writer.

This leaves the primary issue repair unguarded for the measured population of
already-contained worktrees: the most important invocation could regress while
all current tests remain green. Add a hermetic CLI/dispatcher regression that
starts with the branch already an ancestor of the target, calls `thegn land`
once, and asserts `status=landed`, the configured target, and the exact
verified OID. Keep a second invocation assertion that the full existing row,
including `updated_at`, is unchanged. The test-only addition in this review at
`land.rs:396-430` covers the helper’s idempotence but does not close this
dispatcher gap.

## Finding 2 — root, non-landed, and post-CAS degradation branches remain dark (P2)

The implementation’s safety boundaries are in the dispatcher at
`crates/thegn-host/src/cmd/land.rs:74-97` and `:141-204`: root lands must not
observe/write a row; `Ready`, conflict, gate, and unreachable outcomes must not
create one; and a write/lifecycle failure after CAS must warn while preserving
exit zero. The added tests only call `persist_landed_row` and cover a changed
queue plus landed-row persistence. They do not exercise those command-level
branches or verify that an injected post-CAS SQLite failure skips sidebar
filing without turning a successful Git land into a retryable failure.

Add focused command-level coverage for the root no-row path, at least one
non-landed outcome per writer boundary (with the remaining variants covered by
the same table-driven harness), and an injected final-row write failure. These
tests should assert both queue state and command/lifecycle behavior, not merely
the helper return value.

## Source review result

No exploitable production-code bypass was found in the row writer: observation
occurs before fold/CAS, the immediate transaction rechecks registry and queue
identity, repeated landed writes preserve the row and grace clock, and the
manual path writes before lifecycle filing. The schema operation is read/write
for every non-root manual land, including `on_landed = "off"`. The findings
above are mandatory regression coverage gaps against the primary acceptance
matrix, so this review is revisions-needed rather than source-review-clear.
