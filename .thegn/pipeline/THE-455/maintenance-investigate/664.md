### Defects that remain

- `crates/thegn-svc/src/calendar/ics.rs:21-22` has only `MAX_FILES = 20_000`. At `:123-145`, `entries.flatten().take(MAX_FILES)` caps arbitrary directory entries before extension filtering (`:127-128`); errors from both `read_dir` iteration and entries are silently discarded (`flatten`). Readdir order is unspecified, so eligible calendars can be hidden and selected files vary.
- If all 20,000 entries are eligible, each may consume up to 32 MiB of sequential source I/O and parsing. `read_one` releases the transient per-document reservation (`:95`), so retained event accounting does not establish a cumulative bytes-read or total elapsed-work cap. A directory of empty or out-of-window ICS files can still consume substantial read/parse work without exhausting the retained-event budget.
- `read_all` (`:100-145`) uses `exists` / `is_file`, both following symlinks. `read_one` calls `File::open(path)` before checking descriptor metadata (`:65-68`); a `.ics` symlink to a FIFO can therefore block at open before any size/type check. The path can also be swapped between any pathname metadata test and `File::open`. Descriptor metadata currently checks only `len`, not regular-file type.
- Vdir `ReadFailure::Io` is deliberately skipped (`:132-138`), so invalid UTF-8, permission/read errors, and replacement-related errors may silently produce an apparently complete page. This conflicts with the issue's authoritative-snapshot requirement; one such failure should fail the account fetch, preserving the cache through the existing caller path.
- `list_events` (`:188-201`) embeds synchronous `read_all` in `Box::pin(async move { ... })`. The host calls the router inside a new current-thread runtime (`crates/thegn-host/src/hydrate_calendar.rs:324-334`), itself running from the background lane. Thus the work is off the UI loop, but async cancellation/deadlines cannot interrupt synchronous filesystem/parser work; one account also delays later accounts in the sequential router.
- Existing local ICS tests at `crates/thegn-svc/src/calendar/tests.rs:1742-1787` cover a normal file, a small vdir with unrelated content, and a missing path. They do not pin ordering, source budgets, special file policy, read/metadata error behavior, or refusal reasons. Existing core ICS tests cover parser admission, but do not prove local traversal limits.

## Smallest complete proposed fix

Keep this issue focused on local source traversal and use current admission/error APIs where possible:

1. Replace `MAX_FILES` with named limits for eligible calendar files, total source bytes per fetch, and (if approved as necessary to bound arbitrarily many irrelevant entries) directory entries inspected. Align the total source-byte ceiling with existing account/global reservation policy or document why a separate cap is needed. Enforce aggregate bytes before reading each next document; refuse the whole account fetch with a typed reason on any exceeded cap. The coordination note specifically requires file-count overflow refusal with a reason, not silent truncation.
2. Extract deterministic entry selection into a helper that can be given explicit candidate ordering in tests. Filter candidates by `.ics` and eligible file type, sort by a stable path/name key, then enforce the eligible-file bound. To avoid unbounded memory/CPU from arbitrary unrelated directory entries, use a separately named scan-entry budget and typed refusal; it must be larger than the eligible-file cap so more non-ICS entries than the ICS cap still works. Do not cap the raw iterator at the eligible-file cap.
3. Establish an explicit symlink policy. Recommended safe default for this task: require a regular file and reject `.ics` symlinks rather than following them; apply it to the configured single-file source and vdir children, and document/test that behavior. Open and validate the same file handle with no-follow/nonblocking flags or an existing cross-platform helper where supported, then verify descriptor metadata is a regular file before reading. Keep any OS-specific open helper in the platform-approved location; do not add scattered per-OS cfg attributes.
4. Treat directory iteration, metadata, UTF-8, and read failures as account-level errors, not debug-only skips. Also fail the whole fetch if a candidate is replaced or ceases to be a regular file between enumeration and opening. This reuses current failure handling and prevents partial snapshots from replacing the cache.
5. Add a cooperative total deadline/cancellation check between enumeration, file reads, and parser work. File-type-safe no-follow/nonblocking open prevents FIFO hangs before checks can run. If a hard wall-clock guarantee requires an owned worker seam beyond the existing bounded background lane, make that explicit in review; Tokio timeout alone cannot cancel the synchronous operation. Avoid broad router/hydration changes unless the chosen cancellation seam requires them.
6. Do not introduce new partial-page semantics. A bounded/incomplete local scan returns a typed `CalendarError` and preserves the previous authoritative cache via existing `record_failure` behavior. If primary confirms THE-452 has changed the page contract, integrate with that contract rather than building a competing status model.
