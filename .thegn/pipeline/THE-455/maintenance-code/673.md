# THE-455 maintenance-code — native dispatch 673

verdict: implementation-ready

## Scope

Implemented primary revision 1's approved source-boundary design. The shared
no-follow regular-file opener is in `thegn-core::fsperm`, reachable by svc
without reversing the host → svc → core dependency direction. Local ingestion
returns an account error on any incomplete scan/read, preserving the existing
complete-or-error `EventPage` cache contract.

## Changes

- Added descriptor-verified no-follow regular-file opening in core. Unix opens
  are also nonblocking; FIFO/device types are identified from descriptor
  metadata. Windows opens the reparse point and validates the resulting
  descriptor metadata.
- Reworked local ICS/vdir selection to inspect a bounded number of directory
  entries, retain only regular `.ics` candidates, sort paths deterministically,
  and refuse the account if eligible files exceed `MAX_FILES`.
- Added hard per-document, aggregate-source-byte, eligible-file,
  directory-entry, and 30-second cooperative deadline limits. Reads use capped
  buffer growth; parser checks the same deadline between logical lines and
  admission rejects excess events during parsing.
- Metadata, read, UTF-8, special-file, and deadline failures now fail the
  account instead of skipping a source and publishing a partial page.
- Added regressions for deterministic candidate order and over-cap refusal,
  checked parser deadline behavior, no-follow regular/symlink/FIFO handling,
  local symlink refusal, and invalid UTF-8 refusal. Existing sparse oversized
  document and event-cap regressions remain applicable.
