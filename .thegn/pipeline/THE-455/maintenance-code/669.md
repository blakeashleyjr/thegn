## Design blocker

The plan requires the local ICS reader in `thegn-svc` to reuse `crate::platform::open_directory_nofollow`, `open_cleanup_file_at`, and `cleanup_file_identity`. Those functions are implemented in `crates/thegn-host/src/platform/` (`platform/mod.rs:89-103`, Unix implementation at `platform/unix.rs:612-657`, Windows implementation at `platform/windows.rs:563-603`). They are `pub(crate)` and therefore inaccessible outside `thegn-host`. More fundamentally, `crates/thegn-svc/Cargo.toml` has no dependency on the host, while `crates/thegn-host/Cargo.toml:52` depends on svc; `docs/ARCHITECTURE.md:12-20,30-36` codifies that dependency direction. The service cannot call the host seam without reversing the crate boundary.

No existing service-owned generic filesystem opener provides the required pinned-directory, no-follow, nonblocking open plus descriptor identity check. Calling `symlink_metadata` and then `File::open` in svc would preserve the TOCTOU/FIFO defects the approved plan explicitly requires removing. Adding a second per-OS helper or direct platform cfgs would violate the primary instruction and architecture ratchet. Resolving this requires a primary decision on a changed seam design, such as injecting a host-owned opener into svc or relocating the existing platform seam to an owner accessible to svc. Neither change is specified by the approved plan, so I did not choose one unilaterally.

## Confirmed branch contract and existing protections

- The current `EventPage` contract in `crates/thegn-svc/src/calendar/mod.rs:181-204` is complete-or-error. `crates/thegn-host/src/hydrate_calendar.rs` records account failure without applying a page. Thus refusing a failed local scan can preserve the previous authoritative cache; no competing partial-page status model is needed on this branch.
- Existing `thegn-core::calendar::admission` already defines a 32 MiB per-document limit, content-line/parser limits, event admission, account limits, and a shared reservation pool. `crates/thegn-svc/src/calendar/ics.rs` already reads through a capped buffer and parses incrementally under that meter.
- The remaining production defects are present in `crates/thegn-svc/src/calendar/ics.rs`: `MAX_FILES = 20_000` is applied to raw `read_dir` results before filtering; iterator errors are flattened; vdir read/UTF-8 failures are skipped; source bytes across documents and inspected entries have no aggregate caps; path opens follow symlinks and can block on special files; work is synchronous inside the boxed async future.
