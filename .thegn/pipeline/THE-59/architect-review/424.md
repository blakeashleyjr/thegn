## Blocking findings

- Transcription cancellation is only logical: the reducer returns to `Idle`
  and stale request ids prevent injection, but the external transcriber child
  is not signalled or killed. This remains active after `voice-cancel`, config
  disable/reload, and controller drop.
- The service writes the complete WAV synchronously before starting its
  deadline loop. A child that does not consume stdin can therefore block
  indefinitely, defeating `max_seconds`; several post-spawn error paths also
  return without killing/reaping the child.

These violate the design's explicit requirement for bounded, cancellable
external commands and termination on every cancel/error path. They are one
process-lifecycle gap and should be fixed in a single fresh coder round.
